# 予定の重なりを先に警告する

「授業と別の予定が重なっていたのに、 直前まで誰も気づかなかった」 型の事故を機械で先に拾う仕組みの一般則。
engine = [`scripts/calendar_conflicts.py`](../scripts/calendar_conflicts.py) (判定・「間に合うか」・台帳の読み方・通知の段と記録・表示・合成の selftest)。 枠表と学期の暦の読み方・予定の読み込み・台帳の置き場所は engine に入れず、 adapter が「日付 → 占有の list」 を返す provider と引数で渡す ([`script-layer-placement.md#engine-instance-seam`](script-layer-placement.md#engine-instance-seam))。 adapter の例 (個人層) = `odakin-prefs/scripts/calendar_conflicts.py` (時間割と学年暦の provider)。

## <a id="occupancy-outside-calendar"></a>1. カレンダーに入っていない占有を作る

- **カレンダーだけを見る検出器では、 カレンダーに入っていない予定との重なりは原理的に拾えない**。 典型 = 授業 (時間割表にしか無い)、 当番表、 定例の枠表。 検出器を作る前に「重なりうる占有の正本はどこか」 を列挙し、 カレンダーの外にあるものは枠表 + 暦から占有を**生成**する。
- 学期の暦から「その日にその枠があるか」 を決める: 学期の始まり・終わり (学部 / 大学院のように対象で違うなら枠ごとに選ぶ)、 休暇・休業日・終日休講・試験期間・出構不要の週、 時限の一部だけが補講・休講になる日 (「1・2 時限は授業、 3-5 時限は補講」 型の注記を読む)、 時限の時刻がずれる週。 暦の entry に「未確認」 の印があれば使わない (時刻をずらす規則なら、 使わない = 通常の時刻 = 占有の広い側)。
- **暦に書かれていない日は枠どおりとみなす** (= 誤検出の側に倒す)。 祝日の一覧を持たない実装は、 「祝日だが授業日」 として暦に載らない祝日も授業ありとみなすことになる = 限界として書いておく。
- 枠表や暦が無い年度・期間では**黙って「授業なし」 にしない**。 「未チェック」 の 1 行を出す (新年度の切り替わりが典型)。

## <a id="template-vs-instances"></a>2. 実日程が個別に入る枠は占有に数えない

- 枠表には、 自分の授業のように**毎回その枠で起きるもの**と、 会議・セミナー・個別指導のように**枠は確保してあるが実日程が個別にカレンダーに入るもの**が混ざる。 後者を毎週の占有にすると、 (a) 開かれない週の他の予定と毎週重なる、 (b) カレンダーに入った実日程そのもの (セミナー自身・指導の打ち合わせ自身) と重なる。 実測で、 これが誤検出の大半を占めた。
- 数えるのは前者だけ。 後者は、 開かれる日の実日程がカレンダーにあれば予定どうしの重なりで拾える。 実日程がカレンダーに無い class なら、 それは枠表でなくカレンダー側を直す (登録の規律)。
- 判定を枠表の構造に持たせる (例: 科目の実体を持つ枠だけ数える)。 枠の名前の語で当てない。

## <a id="what-counts"></a>3. 何を占有に数えるか

- 数えない: 終日の予定 / 1 日の予定で開始 = 終了のもの (目印) / 確認用のリマインダー (時刻に置いただけで時間を取らない)。 リマインダーの見分けは**台帳の題名の正規表現**で持ち、 コードに焼かない (足すのは「時間を取らない」 と確かめたものだけ = 足した予定は計算から黙って消える)。
- <a id="multi-day-events"></a>**日をまたぐ時刻つきの予定は、 期間に入る日すべての占有に数える** (日への割り方と、 予定の写しに最後の日を持たせる理由 = [`google-api-direct-access.md#calendar-read-timezone-and-span`](google-api-direct-access.md#calendar-read-timezone-and-span))。 目印 (開始 = 終了) の判定は 1 日の予定だけに当てる = 開始と終了の時刻が同じでも、 日が違えば占有。 写しが最後の日を持たないと、 2 日目以降の重なりは黙って落ちる (実測: 会期の時刻つきの予定と、 その間の授業・会議の重なりが出ていなかった)。
- 同じ日時・同じ題名の予定が複数のカレンダーにあるときは 1 つに数える (購読・共有で重複する)。
- **移動の予定 (乗換案内から入る「〜へ移動」) も占有に数える**。 移動が行き先の予定と重なるなら、 それは「着くのが遅れる」 という本物の警告。
- 授業の枠と、 その授業自身のカレンダーの予定 (題名に科目名が入る) は重ねない (将来そのカレンダーを購読しても自己一致しない)。
- 共有カレンダー (家族共用など) の予定は、 誰の予定かを題名から判別できない。 本人が行かない予定は台帳の除外に入れてもらう (推測で外さない)。

## <a id="tight-connection"></a>4. 「間に合うか」 は別の段

- 場所が外の予定と直前・直後の授業の間が短い (目安 30 分未満) のに、 その間に移動の予定が無いものは、 重なりとは別の段 (通知しない) で出す。
- 「学内か」 は場所の文字列で判定するが、 **他大学の「〜キャンパス」「〜号館」 は学外**。 学内の建物名の形 (先頭が番号の「N 号館」 など) に限って学内とする。 場所の無い予定は判定しない。
- 場所の書かれた予定が少ないと、 この段はほとんど発火しない (実測)。 誤検出も出ないので切らずに置いてよい。

## <a id="ack-ledger"></a>5. 承知済みの台帳

- 1 件 = 日付 (+ 期間の終わり) + 組の両側の題名の一部 + 「日付 + 理由」 (理由の無い行は効かせない = 見て決めた記録だけ)。
- 承知済みの組は通知しないし一覧からも外す。 ただし**当日の一覧には「承知済み」 付きで出す** (当日の段取りの確認のため)。
- 毎週重なる組を意図して重ねている場合 (定例と会議の日) は期間で承知する。 期間の終わり (年度末など) を必ず書く。
- 送った連絡 (早退・欠席の連絡) のように記録がある事実だけを agent が入れてよい。 本人の判断が要るもの (動かすのか、 意図的か) は本人に聞く。

## <a id="notification-timing"></a>6. 通知の段と出し方

- 段 = 「3 日前」 (残り 2-3 日) と「前日」 (残り 0-1 日)。 記録の鍵 = 段 + 日付 + 組。 **同じ段は 1 回だけ**、 段が変われば 1 回ずつ出る。 気づいたのが遅く残り 1 日なら「前日」 の段だけ。 今日の組で両方とも終わったものは出さない。
- **固定時刻の日次 job (例 毎朝 9 時) に載せない**。 夜に足された「翌朝 9 時の重なり」 が当日の 9 時まで鳴らない。 受け手の端末ごとの**間隔 daemon** (例 30 分ごと) から出し、 夜の時間帯は通知も記録もしない (= 夜明けの run で出る)。 受け手ごとの成果物なので、 無人 routine の単一ホスト gate に入れない ([`scheduled-tasks.md#per-recipient-notification-locus`](scheduled-tasks.md#per-recipient-notification-locus))。
- 投稿は通知の唯一の入口を通す ([`macos-clickable-notifications.md`](macos-clickable-notifications.md))。 題名のタブ・改行を潰すのは入口の engine が持つ (呼び側で重ねない)。
- 通知に頼り切らない: session 開始時の一覧と dashboard にも同じ段を出す (通知は数秒で消える)。

## <a id="folded-injection"></a>7. 注入を畳んでいる環境

- SessionStart の注入を 1 ブロックに畳んでいる環境では、 **既存の surface (予定の一覧など) に段を足しても注入されない** (畳まれた hook の出力は件数行の 1 つになる)。 近い重なりは digest の行にも出す (2 日以内は緊急の印) = [`hook-authoring.md#injection-digest-and-relay`](hook-authoring.md#injection-digest-and-relay)。
- digest の hook test は実カレンダーを読まないよう env で重なりの行を止める (隔離)。

## <a id="measure-before-wiring"></a>8. 配線の前に実データで数える

- 作ったら配線の前に、 今のカレンダーで 7 日先・30 日先を回して件数を数え、 1 組ずつ「本物 / 本人にしか分からない / 困らない」 に分ける。 数えずに配線すると、 毎週の誤検出が session 開始の一覧を壁紙にする。
- 数える / 数えないの設計の分かれ目 (枠表の文字列の枠を数えるか等) は、 両方で回して増えた組を読んで決める。
