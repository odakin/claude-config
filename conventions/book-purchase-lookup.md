# Book purchase lookup — 図書館に本の購入を頼む前の下調べ

## <a id="scope"></a>場面

大学図書館などに本の購入を依頼する前に、 **書誌を揃え、 その館が持っていないことを確かめ、 新刊で買えるか・いくらかを調べる**とき。
候補は 1 冊ずつの思いつきのことも、 共有された本の束 (→ [scanned-book-survey.md](scanned-book-survey.md)) や
著者の著作一覧から一括で作ることもある。 道具 = [`scripts/book-lookup.py`](../scripts/book-lookup.py)。

## <a id="workflow"></a>手順

1. **書誌を揃える**: `book-lookup.py bib <ISBN|書名>` で CiNii Books の書誌 (NCID・版・ページ・巻ごとの ISBN・叢書・所蔵館数) を取る。
   書名だけでは版・訳書・著者が決まらない本 (同名の本が複数ある、 ファイル名しか手がかりが無い) は、 現物かスキャンの**奥付**で決める
   ([scanned-book-survey.md#colophon](scanned-book-survey.md#colophon))。 共有 Drive folder の中の、 取り込まないと決めた本の奥付だけを見たいときは、
   写しを変えずに別 dir へ落とす (`shared-drive-folder-watch.py --fetch-to DIR --only 語`、
   [google-api-direct-access.md#shared-folder-watch](google-api-direct-access.md#shared-folder-watch))。
2. **所蔵を確かめる**: `book-lookup.py held --fano <参加組織コード>` は下調べ。 **結論は `book-lookup.py opac` でその館の OPAC を引いて出す** ([#cinii-is-a-hint](#cinii-is-a-hint))。
   候補が数冊を超えるなら、 結果は証拠つきの台帳に置く ([#holdings-ledger](#holdings-ledger))。
3. **価格と入手を見る**: `book-lookup.py price <ISBN>` ([#price-and-availability](#price-and-availability))。
4. **紙か電子か・置き場所**: 図書館の購入方針 (電子書籍優先、 洋書の扱い、 冊子体を希望するときの理由、 学科への分置) は館ごと・年ごとに変わる。
   **その年の館の通知を全文読んでから**依頼文を書く。 公開されている収書方針と、 毎年の運用ルールは別物のことがある。
5. **品切れ本の扱いを決める** ([#out-of-print](#out-of-print))。
6. **申込メールは候補リストから生成する** ([#request-from-list](#request-from-list))。

## <a id="cinii-is-a-hint"></a>CiNii の所蔵は「無い」 の証明にならない

CiNii Books OpenSearch に参加組織コード `fano=` を付けると、 その館の所蔵に絞れる (`held` は書誌詳細 JSON の所蔵館リストで判定する)。
ただし**所蔵なしと出た本のかなりの部分が、 その館の OPAC にはあった** (実測)。 すり抜けは 3 通り:

- CiNii に登録されていない**紙の本** (館が総合目録に全点を登録しているとは限らない)
- **電子書籍** (CiNii に出ないことが多い。 館によっては電子書籍の所蔵も「重複」 に数える)
- **ISBN の無い古い登録** (ISBN で引くと 0 件。 書名の表記も違うことがある = 「詳解 X」 が「X : 詳解」 で登録されている等)

∴ OPAC は **ISBN と書名の両方で**引く。 書名の検索は部分一致なので、 当たった行が本当にその本か (著者・出版社・年) を目で見る。
書名で引くと**旧版だけ持っている**ことも分かる。 新しい版を頼むかは館の規則しだいで、 依頼文に「旧版を所蔵しているが新しい版を」 と書いておくと重複調査で止まりにくい。

OPAC の検索 URL は館ごとに違う。 キーワード検索の URL (`...?kywd={q}` 型) が GET で叩ける OPAC なら `book-lookup.py opac --url '<URL の検索語を {q} にしたもの>'` で件数と行が取れる。
件数の出し方と行の区切りは OPAC の製品ごとに違うので `--hit` / `--item` の正規表現で合わせる。 館ごとの URL と正規表現は、 その館を使う側の非公開の記録に置く。
表示する行は 1 ページ目の先頭 5 件だけで、 それより多いと「ほか N 件は表示していない」 と出る。 著者名だけ・書名だけで引くと当たりが数十〜数百件になり、 その本が 6 件目以降に埋もれる (実測)。 **書名と著者名を空白でつないで引く** (多くの OPAC はキーワードの AND 検索になる)。 それでも多いなら、 ページ送りの設定を持たせた `library-holdings-ledger.py` で全行を見る ([#holdings-ledger](#holdings-ledger))。

## <a id="same-name-authors"></a>同姓同名の著者は著者 ID で分ける

「この著者の本を全部」 と頼まれて CiNii Books を著者名で引くと、 **同姓同名の別の人の本が混ざる**ことがある (実測: 分野の違う 2 人の本が 1 つの著者名の検索に混ざった)。
書名の分野だけで仕分けると、 分野の近い本で間違える。

- CiNii の書誌の RDF (`https://ci.nii.ac.jp/ncid/<NCID>.rdf`) に著者の ID (`ci.nii.ac.jp/author/DA...`) が出る。 確実に本人の本を 1 冊選び、 その ID の著者ページ (`https://ci.nii.ac.jp/author/<ID>`) から本の一覧を取る。
- 著者ページに無い新刊・共著は、 書名と版元で CiNii を引き直すか、 本人・版元のページで補う。
- 所蔵確認も同じ著者の本だけを対象にし、 リストに「同名の別人がいた、 ID で分けた」 と書いておく (次の人が同じ罠を踏まない)。

## <a id="holdings-ledger"></a>所蔵確認の結果は証拠つきの台帳を正本にする

候補リストの 1 欄に「所蔵なし」 と書くだけだと、 **外した本の根拠・引いた語・日付が残らない** (実測: CiNii だけを見た時点の「どの版も無い」 が、 OPAC で旧版が見つかった後もリストの欄に残っていた)。
候補が数冊を超えるなら、 所蔵確認の結果は 1 冊 1 件の台帳 (YAML) を正本にし、 候補リストの欄はその写しにする。

- **1 件 = 1 冊 (版)**。 候補に入れた本も、 所蔵ありで外した本も置く (同じ本が別の機会にまた候補に上がる)。
- **結論は人が決める** = `所蔵なし` / `図書` / `電子ブック` / `旧版のみ` / `訳書のみ`。 機械は証拠 (引いた語・件数・当たった行・日付) と読み (`書名で当たりあり (要目視)` まで) を書くだけにする。 書名の当たりは同名の別の本のことが多い。
- **引く語は ISBN (版ごと) と「書名 著者」 の両方**。 当たりが別の本だったら、 語を絞って (版元名を足す等) 引き直し、 0 件になることを確かめる。
- **申込文の生成は台帳の点検を先に通す** (候補の全冊が台帳にあり、 申し込める結論か)。 本文に「所蔵を確かめた」 と書くなら、 その主張を機械で裏付ける。
- **申し込む直前に全冊を引き直す**。 候補を作ってから申し込むまでに、 館が同じ本を買うことがある。

道具 = [`scripts/library-holdings-ledger.py`](../scripts/library-holdings-ledger.py) (`refresh` / `check` / `show`)。
館ごとの値 (検索 URL・件数と行の正規表現・ページ送り・電子ブックの表示語) は設定 file に置き、 その館を使う側の非公開の記録に置く。
候補リストの形式は使う側で読み、 `check --require` に `[{"no", "title", "isbn"}]` の JSON で渡す。

## <a id="price-and-availability"></a>価格と、 新刊で買えるか

| 情報源 | 分かること | 限界 |
|---|---|---|
| openBD (ISBN でまとめて引ける API) | 版元が登録した価格 | **登録時の値**。 値上げが反映されていないことがある。 古い本は旧価格の文字列のまま |
| 大手書店の商品ページ (紀伊國屋ウェブストア) | 今の定価 (税込・本体) と在庫 | 価格が出ないページがある = **注文できない見込み** (品切れ・絶版が多い) |
| 別の書店の検索結果 (楽天ブックス) | 表示価格と注文可否 | 「注文できない」 はその店で扱えないだけのことがある = 弱い信号。 別の書店では取り寄せできることもあった (実測) |
| 版元のサイトの書籍検索 | 在庫ありに絞れる版元なら、 紙の品切れを直接確かめられる | 版元ごとに作りが違う。 紙が品切れで電子版だけ売っている本が見分けられる |

- 定価は税込と本体を分けて記録する。 図書館の発注で割引があるかは別に確かめる。 洋書の円価格は為替で変わる。
- **雑誌扱いの叢書は ISBN を持たない**ことがある (雑誌コードで流通する別冊・ライブラリ)。 書名と叢書の番号で引く。
- 1980 年代より前の本も ISBN が無いことがある。 書名で引き、 価格が見つからなければ「不明」 と書く (推測で埋めない)。
- 洋書はペーパーバックとハードカバーで ISBN が違い、 在庫と価格も違う。 依頼文に両方書いておくと、 片方が手に入らないときに止まらない。
- <a id="self-published"></a>**自費出版 (注文ごとの印刷) の本は大手書店に商品ページが無い** (紀伊國屋は 404、 楽天も無い)。 価格は通販の商品ページの表示で見るしかない。
  図書館が通常の取引先から買えないことがあるので、 候補に入れるかは依頼者に聞き、 入れるなら依頼文に「自費出版で書店では扱いがないようです」 と書く。 評判を見て入れるかを決めることもある ([#author-or-canon-sets](#author-or-canon-sets))。

## <a id="out-of-print"></a>品切れの本

- 図書館の規則 (執行の通知・収書方針・購入申込の案内) に**品切れ・絶版の本の扱いが書いていないことがある** (実測)。
  「規則に無い」 と言う前に、 見た文書を列挙する (見ていない規程集などがあればそれも書く)。
- 近い条項として、 **価格調査・在庫調査を図書館に頼める**、 **書店に直接頼むときの手順** (事前に館へ連絡して重複調査) が書いてあることがある (実測)。
  依頼文で品切れ見込みの本をまとめ、 在庫調査と古書での購入ができるかを聞く。
- 紙が品切れで電子版だけある本は、 電子書籍を優先する館では電子版で買う方向になりうる。 紙を希望するなら理由を書く。

## <a id="ebook-held-paper-request"></a>電子ブックだけ館にある本を紙で頼む

館によっては**電子ブックを持っている本の紙は重複扱い**で、 原則として買わない (通知に書いてある)。 それでも紙が要るなら:

- **その本に固有の理由**を書く。 全冊に書く一般の理由 (一覧性が低い・教育に使いにくい) に足して、 「数式が多く、 式を行き来しながら読むので電子書籍では使いにくい」 のような、 その本の性質から来る理由にする。 一般の理由だけでは例外にならない。
- **置き場所を学科側 (分置) にする**と、 館が電子を優先する理由 (書架の狭さ) にも応えられる。
- 台帳では結論を `電子ブック` のまま残し、 紙で頼む理由を別の欄 (`paper_request`) に書く。 結論を「所蔵なし」 に書き換えない (事実が変わるので)。
- 規則は「原則」 なので通るかは館しだい。 返事は手順メモに記録し、 次の年の前例にする。

## <a id="author-or-canon-sets"></a>「この著者の本を全部」「この分野の定番を全部」 と頼まれたとき

- **範囲を決めて書き、 外したものを理由つきで並べて返す**。 「定番」 は人によって違うので、 どこまでを入れたか (例: 大学院の教科書として広く使われるもの) と、 入れなかった類 (隣の分野の教科書・公理論的な専門書・講義ノート・勉強法の本など) を書く。 依頼者はそれを見て足し引きできる。
- 著者の本は**著者 ID** で集める ([#same-name-authors](#same-name-authors))。 著者のページがあれば、 旧版・分担執筆の章・刊行予定を見分けるのに使う。
- 外す理由の典型 = 館に所蔵あり / 電子ブックだけ所蔵 / 旧版・訳書だけ所蔵 (これは残すことも多い) / 旧版 (新しい版に置き換わった) / 分担執筆の章 / 刊行予定 / 自費出版 / 教科書でない。 どれに当たるかを台帳の `decision` に書く。
- **評判を聞かれたら**、 通販の評価 (星と件数)・読書記録サイトの評価・専門の掲示板の書評を並べ、 批判 (演習問題が無い・計算の誤りの指摘・扱いが薄い章) も書く。 件数の少ない評価は重く見ない。 「標準の教科書の代わりか、 副読本か」 まで書くと判断しやすい。

## <a id="request-from-list"></a>申込メールは候補リストから生成する

- 候補リスト (書誌・所蔵確認・価格と入手の表) を 1 か所に置き、 **申込メールの本文はそこから script で作る**。
  冊数・通し番号・「番号 N は旧版を所蔵」 のような参照を手で書くと、 候補を足したときにずれる。
- 所蔵確認で外した本は、 リストに「外した理由と確認日」 を残す (同じ本を別の session がまた候補に入れる)。 正本は台帳 ([#holdings-ledger](#holdings-ledger))。
- 生成 script は最初に台帳の点検 (`library-holdings-ledger.py check`) を呼び、 通らなければ本文を作らない。 旧版・訳書・電子ブックだけ所蔵の本は、 本文の補足に「旧版を所蔵しているが新しい版を」 のように本ごとに書く。
- 洋書の冊数・自費出版の本の番号のように、 リストから数えられるものは script で数える (手で書くと候補を足したときにずれる)。
- 研究室などから希望を募っているなら、 締切の翌日に 1 通にまとめて送る日を決め、 その日を期限にした TODO に手順 (希望を足す → 所蔵確認 → 本文生成 → 提示 → 承認 → 送信) を書く。
