# 紙の解答用紙の採点と返却 — 写真から採点し、 赤入れして一人ずつ返し、 全体に知らせる

紙で実施した小テスト・試験の解答用紙を写真で取り込み、 採点し、 解答用紙の写真に赤で直しを書き込んで一人ずつメールで返し、 クラス全体に結果を知らせるまでの一般則。
写真の前処理・帰属・転記 (verbatim) は [`photographed-document-transcription.md`](photographed-document-transcription.md)、 写真の取り込み (Picker) は [`chalkboard-photo-archive.md#pick`](chalkboard-photo-archive.md#pick)。 すべて実測 (導入先 1 件)。

## <a id="pipeline"></a>順番 — どの段も本人の確認を通してから次へ

1. 取り込み → 帰属 (写真 → 学生) → 転記と小問ごとの点を 1 つの正本に → 合計は正本から導出する (手で足さない)
2. 読み切れない字は写真を見せて本人が決める ([#ambiguous-readings](#ambiguous-readings))
3. **全員の一覧 (名前・小問ごと・合計) を本人に見せて、 本人が点を確定する** ([#rubric](#rubric))
4. 赤入れ → 全員分を目で確かめる ([#red-annotation](#red-annotation))
5. 返却の文面と宛先の一覧を見せて OK → まとめて 1 回の承認で送る ([#return-by-mail](#return-by-mail))
6. 返し終えてから全体に知らせる ([#class-summary](#class-summary))

置き場所 (正本と導出) = [#records](#records)。 採点そのものは agent に任せられても、 点の確定・判読の判定・送信・投稿は本人の番。

## <a id="rubric"></a>部分点の決まり

- 問ごとの配点は本人が決める。 小問の中の割り振り (どの段に何点) は採点する側が決めて全員に同じに当て、 **表にして採点の spec に残す** (後で「途中まで合っていた人はどう扱ったの」 と問われたときに表で答える)。
- <a id="partial-work-ordering"></a>**途中までちゃんとやった人が、 答えだけ書いた人より下にならないようにする** — 「答えが合っていて途中が無い = 何点」 と「答えが違って途中が正しい = 段ごとの部分点」 を別々に決めると、 途中が正しく最後だけ違う人が、 答えだけ覚えていた人より低くなる (実測)。 確定の前に、 その順が全員の一覧で崩れていないかを見る。 例 (5 点の小問): 答えだけ 2.5 < 答えが違うが途中が正しい (最大 3) < 途中に誤りがあるが答えが合う 4 < 正しく導いた 5。
- <a id="error-carried-forward"></a>**誤りを引き継いだ先の段は、 そこでの計算が正しければその段の満点** (同じ誤りを 2 度数えない)。 決まりを書いただけでは当たらない — 書いた後に、 前の段の誤りを引き継いだ解答用紙を 1 件ずつ開き、 段ごとの点を付け直す (実測: 説明では「引き継いだ先は減点しない」 と言いながら、 その段に点を付けていなかった)。
- 選ぶ問題 (選択肢から選ぶ) は選択肢ごとに点 (正しく選ぶ / 正しく選ばない)。 上の「答えだけ」 の決まりは当てない。
- 決まりを変えたら全員分を付け直し、 変わった箇所と人を本人に見せる。 合計は正本から導出し直し、 導出の検査 (`--check`) で一致を確かめる。

## <a id="ambiguous-readings"></a>読み切れない字

- 判読しきれない箇所は推測で埋めない。 読みの候補と、 候補ごとの点の違いを書き、 **写真のその箇所を切り出して本人に見せる**。 決まったら転記に本人の判定として残す (判読不能の印の扱い = [`photographed-document-transcription.md`](photographed-document-transcription.md))。
- 本人に確かめてほしい項目の一覧で、 項目の番号と写真の連番を同じ形の数字で並べない — 「3 を見せて」 がどちらの 3 か分からなくなる (実測: 確認の 3 番目を写真の 3 枚目と取り違えた)。 項目は写真の file と学生の id で指す。

## <a id="red-annotation"></a>赤入れ — 解答用紙の写真に点と直し方を書き込む

- 返すのは点だけでなく、 **どこが間違っているかと正しい式**。 解答用紙の右に余白を足して点・注記を書き、 間違えた行に下線・丸、 注記からその行へ矢印。 道具 = [`scripts/annotate-scan.py`](../scripts/annotate-scan.py) (spec の形は冒頭)。 座標は同じ道具の `--grid` の格子の画像で読む (割合で書く = 画像の大きさに依らない)。
- <a id="typeset-formulas"></a>**式は組版で書く** — `x^(1/3)` のような文字の冪は読みにくい (実測)。 `$…$` (matplotlib の mathtext) で上付き・分数・根号を組む。 小問ごとの正しい式は 1 つの file に定数で置き、 全員の注記から使う (書き写しの誤りを 1 か所にまとめる)。
- <a id="reread-the-line"></a>**注記は 1 人ずつ、 解答のその行を読み直して書く。 採点の理由 (転記に書いた comment) から写さない** — 採点の理由は印象で書いた短い文で、 解答用紙に書くと解答の中身と食い違う (実測: 解答用紙の左辺には入っている記号を「左辺に入っていない」 と書き、 本人に「意味不明」 と言われた。 誤りは右辺の代入だった)。
- 点は注記の spec に書かず、 採点の正本から引く (spec と記録の点がずれない)。 小問を全部書いたか (抜け) を道具で確かめる。
- できたら **全員分を縮小して並べ、 目で見る** — 下線・矢印が別の行を指していないか、 注記が余白からはみ出していないか (実測: 下線が隣の行にずれていた 1 件をこれで見つけた)。 長い注記は句点の後ろで折り返す (道具が持つ)。
- 赤入れの下地 (前処理した解答用紙の画像) は、 紙の切り出しが解答用紙の端を切り落としていないかを見る。 切れていれば元の写真から手で切り、 その手順も下地を作る script に入れる (実測)。
- 送る画像はメールで開ける大きさに縮める (例: 長辺 2600 px 前後の JPEG)。 file 名は学生の id で作る (氏名を file 名に入れない)。

## <a id="return-by-mail"></a>一人ずつ返す (メール)

- 本文は雛形 1 つ (姓と点だけが違う) から作り、 雛形を正本にする。 添付・本文・宛先の一覧は道具で作る (手で 1 通ずつ組まない)。 一覧は名前と宛先を含むので一時 dir に置き、 送り終えたら消す。
- 送る前に一覧 (宛先・姓・点・添付の名前) を本人に見せて OK をもらい、 dry-run の出力を名簿と点の記録に突き合わせる。
- <a id="one-approval"></a>**一人ずつ違うメールも、 送信 CLI のまとめて送る口で 1 回の承認で送る** — 1 通ずつ送信の command を打つと、 承認のダイアログが通数だけ出る (実測)。 使い捨ての送信 loop を書くのも違う (送信の gate が止める)。 送信 CLI に要る条件 = [`gmail-sending.md#batch-personalized-send`](gmail-sending.md#batch-personalized-send)。
- 途中で止まったら、 送信済みフォルダを件名で引いて送った宛先を並べ、 一覧から外してから残りを送る (二重送信を防ぐ。 記憶や自分の log で数えない)。
- 受けていない人 (名簿にあって解答用紙の無い人) には送らない。

## <a id="class-summary"></a>全体に知らせる — 人数・平均・中央値・標準偏差

- 返し終えてから、 クラス全体に: 受けた人数・満点・平均・中央値・標準偏差・問ごとの平均。 分布が片側に偏る小テストでは、 平均だけでなく中央値を並べる。
- <a id="sd-divide-by-n"></a>**標準偏差は n で割る** — 知らせるのは受けた全員という集団そのものの散らばりで、 より大きな集団を推定するのではない (n−1 で割るのは、 受けた人を標本と見て母集団を推定するとき)。 どちらで割ったかを記録に書く。
- **数値は道具の出力から写す** = [`scripts/score-stats.py`](../scripts/score-stats.py) (両方の標準偏差・問ごとの平均・分布を出す)。 頭や使い捨ての code で計算した値を載せない (記録の根拠にならない)。
- 分布の刻みや最高点・最低点は、 少人数のクラスでは個人を特定しうる = 載せるかを本人に選んでもらう (既定は載せない)。 個人特定の考え方 = [`../CLAUDE.md#third-party-facts`](../CLAUDE.md#third-party-facts) と同じ向き。
- 採点の決まり (答えだけ・途中あり) を 1 段で添えると、 点の理由が伝わる (載せるかは本人が決める)。
- 投稿は plain text、 API で投稿して読み戻し、 下書きと照合する ([`paste-destined-plain-text.md`](paste-destined-plain-text.md) / [`google-classroom-api.md`](google-classroom-api.md))。

## <a id="explained-solutions"></a>解説つきの解答を配る — 間違いの型と人数を採点の正本から

返却の後に解答を求められたとき、 とくに出来が悪かったときは、 答えだけの解答でなく、 途中を飛ばさず解説を入れた解答を配る (答えだけでは、 間違えた人が何を直せばよいか分からない)。

- **問ごとの並び** = 問題文 → 解答 (計算を 1 行も飛ばさない) → 解説 (その計算で何をしているか) → 答えの確かめ方 (符号・示量か示強か・次元・具体的な数値を入れた検算) → 多かった間違い (型ごとに、 解答用紙に書かれた誤った式をそのまま ✗ つきで示し、 なぜ成り立たないかを書く)。 問題文を載せると、 問題用紙が手元に無くても読める
- **解答を主にし、 基礎の説明はそれを初めて使う小問の中に置く** — 間違いの多くが問題の内容より手前 (関数の記号・偏微分・指数・対数の扱い) にあっても、 それを冒頭の 1 節にまとめると、 解答より先に解説を読む文書になる (実測)
- **間違いの型と人数は採点の正本から数える** (転記・採点の理由 = [#records](#records))。 機械で数えられるもの (選択肢ごとの人数・満点・答えだけ・白紙) は script で、 理由を読んで分けたもの (「理由を言葉で書いただけ」 など) は分けた結果を一覧で持ち、 同じ script で本文の人数と照合する。 1 人だけの誤りは人数を添えず型として書く
- **名前・学籍番号を入れない** — 配る前に、 tex と組んだ PDF の文字を名簿と照らす検査を同じ script に入れる
- **式と数値は検算の script で確かめる** (解説の枠に足した例・数値の表も。 頭で計算した値を載せない = [#class-summary](#class-summary) と同じ)
- 配り方 = PDF を配る場所 (Classroom なら Drive) に上げてお知らせに添付する。 文面は file にして本人の OK → 投稿 → 読み戻して照合 ([`google-classroom-api.md#readback-after-post`](google-classroom-api.md#readback-after-post))

## <a id="records"></a>記録の置き場所 — 正本と導出

| 何 | 置き場所 |
|---|---|
| 写真 → 学生の帰属 | 帰属台帳 (確定後は変えない) |
| 転記・小問ごとの点・採点の理由 | 転記の正本 (1 file) |
| 合計 | 正本からの導出 (導出の検査で一致を確かめる。 手で直さない) |
| 配点・部分点の表・確定の経緯 | 採点の spec (本人の言葉のまま) |
| 赤入れの注記 (座標・文) | 1 人 1 つの spec (点は持たない)。 正しい式の定数は 1 file |
| 返却の一覧 (宛先・本文・添付) | 一時 dir (送り終えたら消す)。 送ったことは案件の TODO と送信済みフォルダ |
| 全体への知らせ | 下書きを file にして、 投稿の後に読み戻しで照合 |

- 学生の氏名・学籍番号を file 名・dir 名・commit message に書かない (中身は暗号化しても名前は見える = [`confidential-repo-boundary.md#role-words-in-names`](confidential-repo-boundary.md#role-words-in-names))。
