# jps-talk-submission.md — 日本物理学会 (JPS) 大会 一般講演申込の form 機構と落とし穴

**Load this when**: JPS 年次大会 / 秋季大会の一般講演申込・概要集原稿提出の作業に入るとき (毎年 6-7 月頃に年次大会申込)。

制度個別値 (締切日・参加費額・領域キーワード番号表) は毎年変わり得るので**当年の募集要項・公式キーワード一覧が正本** (https://www.jps.or.jp/activities/meetings/ 配下)、 本 file は**制度横断で効く form 挙動・書式・落とし穴のみ**を持つ (= [erad-submission.md](erad-submission.md) と同じ思想)。 個人固有値 (会員番号・所属略称の定型・過去の選定) は各自の個人層に置く。

## 申込の全体像

- 申込は**会員マイページのみ** (https://member.jps.or.jp/a/login.do?act=init)。 ⚠️ **ログイン ID は会員番号とは限らない** (= 入会時に別途決めた username のことがある)。 個人層の記録に ID が無いなら、 会員番号で代用せず本人に聞く — 会員番号は form の「会員番号」 欄に書く値であって 認証子ではない。 さらに**大会システム (原稿送信・参加票発行) は登録番号 + 別パスワード**の第 3 の体系。 締切は 14:00 JST 型 (= 深夜 23:59 でない) が通例 — 締切日当日の午後に始めると間に合わない。
- 講演申込と参加登録 (参加費支払) が**同一 form で一体**。 申込完了と同時に参加費の支払義務が発生する (講演取消でも返金なし)。
- **受付システムは学会本体と別ドメインの外部運営** (2026 実測: 自動返信の送信元 domain = `gakkai-web.net` 〔local part は大会別、 例 `jps_gakkai<西暦下2桁>@`〕、 各種手続ページ = `https://www.toyoag.co.jp/jps/index.html`)。 **`from:jps.or.jp` で mail 検索しても受理票は hit しない** — 大会名 or `from:gakkai-web.net` で検索する。 受理票は form の「登壇者メールアドレス」 欄に入れたアドレスに届く (= 会員登録メアドではない)。
- **登録完了で「登録番号」+「パスワード」 が発行される** (受理票画面 + 自動返信メール)。 修正・取消・**概要集原稿投稿**に必須 → durable に記録 (受理票メールを消さない + タスク管理側に pointer)。 講演申込期間後は登壇者変更・講演取消以外の修正を受け付けない。
- **概要集原稿は別締切** (申込締切の約 5 週後)。 各種手続ページから登録番号+パスワードで投稿。 申込完了時に概要集 follow-up タスクを必ず起票する。
- 申込時の「講演要旨」 欄 (200 字程度) は**プログラム編成専用・非公開** (概要集・プログラムに掲載されない)。 公開されるのは**題目・著者・所属** (講演概要集 Web 版 / PDF・Web プログラム / J-STAGE) → **集客は題目が勝負** ([giving-talks.md](giving-talks.md) の「タイトルは出席を決める唯一最重要の選択」)。

## 登壇件数の規則

- 一般講演の登壇 = **1 人 1 件** (シンポジウム・招待講演等の依頼講演を除く)。
- **例外 = 領域 13 (物理教育・物理学史・環境物理)**: 他領域で 1 件申込済でも、 領域 13 の 1 分野に限り**さらに 1 件**申込できる (= 専門 1 件 + 物理教育 1 件の 2 登壇が可能)。
- 領域 13 の 2 件目を申し込むときは**参加登録 (参加費) を「免除 (0 円)」 で選択** (form に明記あり) — 参加費は 1 件目で 1 回だけ払う。 二重払い注意。
- <a id="emergency-substitute-presenter"></a>**登壇予定者が登壇できなくなったら「臨時登壇」** (= 当日の急病・事故。 講演を取り消す前にこちらを検討する):
  > やむを得ない事由により登壇予定者が登壇できなくなった場合、 共著者が当該領域代表の許可を得て、 臨時登壇することができます。 臨時登壇も1人1件まで（自らの講演登壇を含めて2件）とします。 (募集要項 逐語)

  - **許可者は座長でなく「当該領域代表」** — 座長に伝えるのは実務上必要だが、 それだけでは規定を満たさない。 領域代表の氏名・メールは各領域の Web ページ (`div.jps.or.jp` → 各領域サイト → 「領域代表・領域役員」) にある。 ⚠️ 領域サイトは自己署名証明書のことがあり、 WebFetch が `self signed certificate` で落ちる → `curl -sk` で取る。
  - ⚠️ **上限の「2 件」 は領域 13 例外と重なると条文の射程外になる** — 「1 人 1 件 + 臨時登壇 1 件 = 2 件」 を前提にした書き方なので、 **領域 13 例外で既に 2 件登壇している人が臨時登壇できるか**は明文が無い。 文字通り読むと枠が無い。 打診の時点で領域代表 or 大会事務局 (連絡先は当年の募集要項) に扱いを確認する。
  - 取消が**既に提出済**かどうかで手続きが変わる (未提出なら取消せずに臨時登壇へ切り替える方が軽い)。
  - <a id="presenter-change-form"></a>**取消・登壇者変更・講演移動の申請 = 「講演取消等変更受付」 フォーム** (講演番号通知メールの「講演の取消・変更について」 から辿る。 実測):
    - **認証は無い**。 講演は「講演番号 **または** 登録番号」 で特定する (= 講演番号が分かれば登録番号は要らない)
    - 「申込識別情報」 (会員番号・氏名・所属・メール) は**元の申込者のもの**。 新しい登壇者は別欄 (会員番号・氏名・所属略称) に書く。 フォームに誰の番号かの明記は無いが、 新登壇者の番号が別欄にあることから元の申込者と読むのが自然。 共著者が代わりに出すとき手元に要るのは**元の登壇者の会員番号** (登録番号やパスワードではない)
    - メール欄は申込識別情報の一部 = 元の申込者のアドレスを書く (登録確認メールはそこに届く)。 代わりに出す人のアドレスを混ぜない
    - 申請締切はフォーム冒頭に書かれ、 会期中の日付のことがある。 入力 → 確認画面 → 送信の 2 段で、 完了画面に「正常に終了しました」 と出る
  - **取消を出した後で臨時登壇に切り替えたいとき**は、 領域代表に相談すれば、 領域運営委員を通じて学会事務局に「取消の取り下げ + 登壇者変更」 で扱えるかを確認してもらえる。 取消は WEB 版プログラムにすぐには反映されない (実測) ので、 相談の文面に取消済みであることを書いておく
  - Claude から外部サイトのフォームを送ろうとすると auto mode の分類器が止める → [`tool-call-robustness.md#classifier-real-world-transaction`](tool-call-robustness.md#classifier-real-world-transaction)
- 口頭発表 = 講演 10 分 + 質疑 5 分 (2026 年次大会実測)。 ポスター = 120 分。

## form 各欄の落とし穴

- **キーワード欄は code (番号 or 英字半角大文字) を入力する** — 名称文字列 (例: 素粒子論領域の「Th」 と直接入力) は「コード登録に存在しません」 エラー。 欄は 6 個並ぶが**必要数は領域依存** (1〜3 個 + 任意追加)、 残りは空欄で可。 番号表は当年の公式キーワード一覧を見る。
- **著者・所属の記法** (概要集・プログラムにそのまま出る):
  - 上付き = `^...^`、 下付き = `_..._`。 表現できない場合のみ LaTeX (`!LaTeX$…$`)。
  - **登壇者印 = `^@^` を名前の直前** (= °印。 form 注記「登壇者を示す印は、登壇者が筆頭著者以外の場合のみつけてください」 — アルファベット順等で登壇者が筆頭でないときは必須)。
  - **所属区分記号 `^A^` `^B^` …** を各著者名の直後に付け、 所属欄の同記号と対応させる。 記号は「2 番目の所属以降」 が原則だが「1 番目につけても構いません」 (form 原文) → **全所属に付けて uniform にする**のが対応間違いを防ぐ (著者を分野慣習順 〔素粒子論系はアルファベット順〕 に並べ、 所属もその登場順に並べる)。
  - **連結は全角カンマ「，」** (半角カンマは form 例示に反して実運用では全角指定)。
  - 所属は**略称表記** (form 例: `東大理, 阪大工^A^, 広大総合科^B^, 高エ研^C^, 筑波大低温セ^D^`)。 外国機関は英字略称 (UCLA 等) がそのまま通る。 外国人著者名は Latin 表記が概要集通例。
- **半角カタカナ禁止** + **1 時間無操作で session 失効** (「次へ」 でエラー → 最初からログインし直し)。 入力データは手元に組み立ててから form を開く。
- **英語講演「希望する」 は別扱い**: 英語セッションにまとめられ、 日本語の同分野と**別会場・別日時**になる可能性 (form 注記)。 日本語で話すなら「希望しない」。
- **共著者の同意 checkbox** = 「共著者の同意を得ているものとみなす」 宣言。 チェック前に共著者の了解を取っておく (対面・chat での確認で可、 form は手段を指定しない)。
- 共著者の会員番号入力欄は**無い** (2026 年次大会実測) — 会員番号が要るのは申込者 (= 登壇者本人) のみ。 非会員の共著者もそのまま氏名を書ける。
- 概要 (要旨) は非公開・題目は公開という**非対称**があるので、 磨くべきは題目 > 要旨。 abstract に数式を書かない流儀は個人層の paper-style 側 (該当者のみ)。

## <a id="program-slot-lookup"></a>講演番号通知 → 講演時刻の導出 (申込の約 3.5 週後)

申込締切の約 3.5 週後に「講演番号通知 <登録番号>」 mail が届く (2026: 7/6 締切 → 7/30 通知)。 番号 = `<日><a|p><会場>-<順番>` (例 `16pE532-11` = 16 日 午後 E532 会場 11 番目)。 **時刻は番号だけでは決まらない** (= 休憩・取消・長い講演が混ざる) ので Web program で確定する:

1. program = `https://onsite.gakkai-web.net/jps/jps_search/<yyyy>a{u|s}/program/date/program<領域>.html#j<番号の会場部>` (au = 秋/年次、 領域 file 名は日程表 `timetable.html` の link から。 素粒子論 = `programsr`、 領域 13 = `program13`)。 会期の 7/31 前後に公開。
2. **session の `<ol>` 内 `<li>` を先頭から数える** (各 `（15分）` を積算、 `<div class="roundframe spaces">休憩 (hh:mm〜hh:mm)</div>` で時刻を jump)。 順番 -N = N 番目の `<li>`。 ⚠️ WebFetch の要約は **講演を 1 件落として番号をずらす**ことがある (2026 実測: 1 件欠落で 16:00 と誤報、 実 16:15) — 要約の時刻を採らず `curl` + 自分で数える。 持ち時間の規則 (講演 10 分 + 討論 5 分) と会場→建物の対応は前付け PDF (`jps.or.jp/activities/meetings/files/<yyyy>a_mae.pdf`、 p.9 前後 / 会場配置図)。
3. 確定したら **talks.yaml の date を会期初日から講演日に更新** + calendar に講演 slot の event (15 分) + events.yaml の talks 行に番号・時刻・event id — の 3 点を同 turn で。 同日の学内会議との重なりは calendar を並べた瞬間に見えるので、 その場で出欠を user に問う。 ⚠️ 番号通知の turn で「program 確定後に絞る」 と書いて止めない (program 公開は通知の翌日)。

**道具**: 上記 1-2 (日程表 → session → `<li>` 数え) は [`scripts/jps-program-talks.py`](../scripts/jps-program-talks.py) に固めてある — `slot 16pE532-11` (番号 → 日時・会場・題目)、 `sessions --day 15 --slot p` (当日午後の全 session)、 `talks j15aG721` (session の講演 + 計算した開始時刻)、 `grep '<regex>'` (全領域の題目を横断検索)。 program の構造 fact (anchor / `<li>` / 休憩 div / 領域 file code / 概要集は login 越し) は script docstring が正本。

## <a id="talk-announcement-links"></a>講演の告知 (SNS・メール) に貼るリンクと、本文に書くこと

- **貼るのは大会サイトの「領域別プログラム」** (`https://jps<yyyy>a.gakkai-web.net/data/html/program<領域>.html#j<session>`、 login 不要)。 上の `onsite.gakkai-web.net/jps/jps_search/...` は同じ内容の検索サイト側で、 開きはするが告知には公式側を使う。 host 名は大会ごとに変わりうるので、 大会トップの「領域別プログラム」 link から辿って確かめる (実測)。
- **英語の読み手には** `https://onsite.gakkai-web.net/jps/jps_search/<meeting>/program/date_e/program<領域>.html#j<session>`。 題目も英語で載っているので、 **英題は自分で訳さずここから取る** (実測)。
- **anchor は session 単位しか無い**。 講演ごとの link は概要集 PDF (`data/pdf/<講演番号>.pdf`) だけで、 login なしでは 401 = 告知には使えない (実測)。 link を開いた人は session の先頭に着くので、 **本文に「session の N 番目」・開始〜終了時刻・建物と部屋を書く** (会場記号 → 建物は会場案内の配置図)。 link があっても時刻は本文から落とさない (時刻の抜けた案内メールの draft を実測)。 海外の読み手には時刻に (JST) を付ける。
- 字数の上限がある SNS は [`scripts/post-length.py`](../scripts/post-length.py) で数える。 X は日本語と絵文字が 2、 URL が 23 なので、 Bluesky や Mastodon に入る文面が X では超える。 ハッシュタグは末尾に足すより本文の語をタグにする (`#arXiv に`) 方が短い。
- Vivaldi Social は Mastodon 系でも上限が別で、公式英語 help の現行値は **1337 文字、URL は 23 文字**。
  `post-length.py` は Mastodon 500 と Vivaldi 1337 を別行で検査する。公式の言語版が食い違う場合は、
  投稿画面または英語の一次情報で現行値を確かめ `--vivaldi-limit` で上書きする。
- Facebook の hashtag は clickable で同じ tag の投稿を辿れるが、見える範囲は投稿の audience 設定に従う
  ([Meta の説明](https://about.fb.com/news/2013/06/public-conversations-on-facebook/))。個人の学術告知では、
  継続企画・会期中の索引として同じ tag を使う目的が無ければ、末尾の hashtag 列は既定で付けない。
  検索可能であることを reach 増加の保証として書かない。
- 同日に複数講演があるとき、一本目の投稿に二本目をぶら下げる文面は、親投稿の書誌を繰り返さず
  「午前は物理教育の話も」のように関係を一文で示す。時刻・建物・部屋・講演番号・実物への link は
  子投稿側にも自立して残し、時間が離れた読者が親を開かなくても来場できるようにする。

## <a id="program-triage-by-interest-profile"></a>聴講計画: 関心プロファイルで program を triage する

会期の全日程に出る場合、 3,000-4,000 件の題目から自分向けを拾う作業は「keyword を思いつく」 だけでは漏れる。 手順 (2026 秋で確立):

1. **関心プロファイルを外部化して持つ** — arXiv digest を運用しているなら、 その profile (最優先テーマ / コアトピック / arXiv category) と直近の高スコア論文の題目がそのまま照合基準になる (= 「何を面白いと思っているか」 の機械可読な記録。 頭で思い出すより網羅的)。 無ければ INSPIRE の自分の publication list から主要 keyword を起こす。
2. **program を全領域で dump して keyword 横断検索** (`jps-program-talks.py grep`)。 keyword は profile の語 + 日本語表記ゆれ (波束/wave packet、 捩率/torsion/テレパラレル) を OR で束ねる。 自分の領域だけ見ない — 波束・測定論は領域 1 (量子情報) / 領域 11 (統計力学) に、 重力は宇宙線・宇宙物理領域 (相対論 session) に散らばっている。
3. **hit を「直撃 / 隣接 / 関心圏」 の 3 段で並べ、 user に番号で選ばせる**。 各候補に日時・会場 (建物)・競合を添える。 「全部入れて」 と言われたら bulk 登録 (calendar は API 直接、 会議 ledger に id を残す)。
4. **calendar は 3 層**: 会期 all-day (参加確定・参加票等の実務) / 自講演 (別 event) / 聴講 (🎧 prefix、 候補は「（候補）」 prefix、 description に session の前後・移動経路・競合を書く)。 競合は description に「当日選択」 と明記して残す (= 消さない、 現地で選ぶ材料)。
5. **推薦の出所を残す** (= 「X さんの DM で推薦」 「digest profile 照合」) — 後で「なぜ入れたか」 が分かる。 Discord DM 等の機械射程外で来た推薦は user に転記してもらい、 その旨を書く。

## 発表内容の選定 (制度が形を決める部分)

- 「1 人 1 件 + 領域 13 例外」 により、 専門の演題を 2 本持っていても**同一領域では 1 本しか話せない**。 2 本目は (a) 領域 13 (教材・教育ネタがあれば) / (b) 別の研究会 (基研研究会等) に振り分ける、 が定石。
- タイトルは [giving-talks.md](giving-talks.md) 基準 (問い形 or 平叙断定、 聴衆の言葉、 「〜の解析」 型の dull を避ける) で書く。

## <a id="candidate-calendar-discipline"></a>聴講候補を calendar に置くときの規律

上の triage で拾った候補を calendar に落とす段の規律。 **calendar 自体を「当日その場で選ぶための一覧 (candidate view)」 として使う** のが前提で、
そのとき壊れやすい点が 4 つある (= いずれも実測で踏んだ)。

1. **粒度は 1 トーク 1 event**。 複数講演を 1 つの block event にまとめると「全部行くか全部行かないか」 の読みを強いてしまい、
   1 本ずつ選ぶという目的を壊す。 **最初からばらして作る** — 後から split すると、 元の block と split 後の event が
   同じ時刻に二重に並ぶ後始末が要る。 ⚠️ split する際は**元が単一トークの event を二重に作らない** (= 完全重複は候補でなく noise)。
   例外 = **session / シンポジウム丸ごとに通しで座る**という選択。 これは「その session に居る」 こと自体が 1 単位なので、
   トークに割ると逆に意図が消える。
2. **候補は差し替えでなく追加**。 方針を決めた後でも、 選ばれなかった側の event を消したり時間を縮めたりしない。
   予定は覆る (= 会場移動が想定より早く済んで、 放棄するはずだった枠が復活する、 は実測で起きる)。
   消えるのは **user が明示的に「もう行かない」 と決めた範囲だけ**。
3. **重複は制約にしない — 内容だけで採否を決める**。 既に何か入っている時間帯を「埋まっている」 とみなして候補を出さない、
   他の予定 (会議・懇親の集まり・**自分の講演**) との衝突を理由に候補を落とす、 のどちらもしない。
   衝突は「消す理由」 ではなく **description に書く情報** (= 同時刻に何があるか / 移動が要るか / 間に合わないか)。
4. **空き時間を埋めるのではなく、 プログラム全体を profile で走査する**。 3 の裏返しで、 これが順序の問題として効く —
   session 丸ごとの block event が置いてある窓は「空き」 計算上 busy になり、 **窓の中の個別トークが候補検討の射程から
   丸ごと落ちる**。 一般形は [convention-design-principles.md#coarse-entry-hides-its-contents](../docs/convention-design-principles.md#coarse-entry-hides-its-contents)。

**会場の建物名は推測で書かない**。 会場コードから建物番号を導ける大会が多いが (例: `A1xx` → 1号館 / `E5xx` → 5号館 /
`G7xx` → 7号館 / `M13xx` → 13号館)、 これは**複数の確定例から起こした規則であって公称ではない**。 プログラムの HTML に
建物名が載っていないことがあるので、 導出した建物名は description に「推定」 と書いて現地表示に委ねる。

**会期中の常設ミーティング**を昼休みに入れてくる分野がある (= 素粒子論の中小規模研究室懇談会)。 これは学会の program には
載らず ML で告知されるので、 **午前最終コマ・午後初コマを選ぶ前にその存在を思い出す**。 会場が本会議の教室なので
直前の講演と別建物になりうる。 検出の穴と carrier は下記。

**道具**: `scripts/calendar-events.py` (list / gaps / dups / add / delete)。 **削除は既定 dry-run で、
終日 event と protect 正規表現に当たるものを常に保護する** (= 「今日の X より後を消して」 で会期 event や
夜の別予定を巻き込む事故を設計で塞いである)。 `gaps` の出力は上の 4 の理由で**入口にしない**。

## <a id="participation-ticket"></a>参加票 (名札) と領収書 — 会期前に刷って持って行く

講演申込の手順は番号通知・聴講計画で終わりがちだが、 **会期に入る前に参加票を刷る段がある**。 期限は mail に書かれず
会期初日の前日にしかないので、 参加票メールを受けた turn でタスク管理に「会期初日の前日」 期限で起票する
(一般形 = [convention-design-principles.md#deadline-in-the-referent](../docs/convention-design-principles.md#deadline-in-the-referent))。

- **受付が無い大会がある** (実測): 参加票を提げて直接講演会場へ入る方式。 当日に受付で名札をもらう前提でいると、
  会場で刷る手段が無い。 参加票を入れるホルダーは現地配布 (次回以降は持参して再利用、 と案内される)。
- **参加票メール** = 会期の 1〜2 週間前に大会システム (受理票と同じ外部運営ドメイン) から、 **登録番号ごとに 1 通**。
  件名は「参加票及び講演概要集」 型。 同じ登録番号 + パスワードで講演概要集 Web 版にも入れる。
- **認証**: ID = 登録番号 / パスワード = **参加票メール本文のもの** (⚠️ 申込時の受理票のパスワードとは別物)。
  login は本人が行う (agent は代行しない)。
- **参加票は PDF ではなく「印刷用 HTML」** (`namecard.php` = `window.print()` 前提)。 「PDF を DL」 と探しても見つからない。
  領収書 (`receipt.php`) も同じ個人ページから同じ形で出る。 A4 で刷って**四つ折り (A6)** にし、 氏名・所属を見える側に。
  版面の半分が上下逆さなのは折る前提の正常な状態。
- **機械で PDF にする** = 本人がブラウザでページを保存 (or 本人が curl で login → POST で取得) → [`scripts/html-print-pdf.py`](../scripts/html-print-pdf.py):
  ```
  python3 scripts/html-print-pdf.py namecard.html --base-href <参加票ページのディレクトリ URL> -o sankahyou.pdf --expect-pages 1 --png
  ```
  `<base href>` 差し込み (保存 HTML の CSS・画像は相対 path) と、 用紙指定の無い領収書型ページへの `@page{size:A4}` を script が行う。
  出力の `*-print.pdf` (raster 版) を刷る — ブラウザの print-to-PDF は文字を Type3 font で書き、 そのままだと印刷前検査が落ちる。
- **刷る前**: [office-automation.md#print-preflight](office-automation.md#print-preflight) の 5 点 (特に 5. = プリンタ本体の用紙サイズとトレイの紙)。
