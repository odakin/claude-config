# ポッドキャストの配信（配信先への登録・載せる文・公開予約・判断を任されたとき）

仕上げた音声をホスト (RSS を出すサービス) に上げ、各配信先に番組を登録し、回ごとに公開していく場面。
音声の仕上げそのもの (音量・ジングル) は [`podcast-audio-finishing.md`](podcast-audio-finishing.md)、
収録の分割は [`audio-transcription.md#splitting-long-recordings`](audio-transcription.md#splitting-long-recordings)。

## <a id="rss-directories"></a>配信先への登録

どの配信先も「ホストの RSS の URL を渡す → RSS に書かれたメールアドレス宛に届く確認で持ち主を示す」の形をとる。
**先に RSS を完成させる**: 回が 1 つも無い・長さ (`itunes:duration`) が空の RSS は登録の段で失敗する (実測、Spotify)。
アカウントの作成・パスワード・電話番号・支払い方法・規約への同意・本人確認は番組の持ち主が自分でやる。
確認のメールは RSS のアドレス宛なので、そのメールボックスが読めれば確認コードの受け取りは代われる。

| 配信先 | 入口 | 持ち主の確認 | 注意 (実測) |
|---|---|---|---|
| Spotify | Spotify for Creators の「既存の番組を追加」 | RSS のメール宛に数字の確認コード | カテゴリは RSS でなく登録画面で選ぶ (3 つまで)。ホスト一覧に無ければ「その他」。一度「数分待って」で失敗し、画像を JPEG に替えた後に通った (どれが効いたかは切り分けていない)。番組ページが開くまで数時間 |
| Apple Podcasts | Podcasts Connect の「RSS フィードがある番組を追加」 | Apple Account でのログイン | Apple Account は支払い方法の登録と Apple Podcasts の規約同意で有効になる。追加すると下書き → 「コンテンツ配信権」の選択 → 処理が終わってから「公開」→ 審査 (数日)。「公開」を押すと状態は「利用可能」 になるが、公開ページ (`podcasts.apple.com/…/id<番号>`) と検索 API (`itunes.apple.com/lookup?id=`) に出るまでは時間がかかる (直後は 404 と 0 件)。更新頻度の欄は空のままでも公開の操作に進めた。⚠️ 番組を持たない Apple Account でサインインすると「Podcasts Connect に参加する」の画面になる = 押すとそのアカウントに別の Connect アカウントができる。番組が見えなければ、まずサインインしたアカウントを疑う (右上のメニューに出る)。カテゴリは主と副の 2 つだけ使う ([Apple Podcasts categories](https://podcasters.apple.com/support/1691-apple-podcasts-categories)) |
| Amazon Music | Amazon Music for Podcasters | RSS のメール宛に確認のリンク | 配信が始まると番組ページの URL がメールで届く (実測では 1 時間以内)。Audible にも出る |
| YouTube | YouTube Studio「作成 → 新しいポッドキャスト → RSS フィードを送信」 | 上級機能の解放 (自撮りの短い動画 / 身分証 / 一定期間の利用履歴のどれか) | 電話番号の確認だけでは開かない。審査は通常 24 時間と表示される。解放されたら: 取り込みの規約に同意 → RSS の URL (検証される) → RSS のメール宛の確認コード (有効 1 時間) → 取り込む回の範囲 (すべて / 日付以降 / 過去の回は入れない) → 公開設定で保存。ポッドキャストは**非公開で作られ**、取り込みが終わると「コンテンツ → ポッドキャスト」に「公開」が出る (チャンネルのアカウント宛に「公開できるようになりました」のメールも来る。押すまで外からは回が 0 本に見える)。「公開」の確認画面で、番組と取り込み済みの全回が公開になり、以後 RSS から入る回も既定で公開になる (回ごとに確かめたいなら番組の詳細ページで変える)。⚠️ この最後の確認ボタンは、agent が押すと auto mode の判定で止められた (実測) = 確認画面を開いたまま持ち主に押してもらう。「RSS フィードを取得できませんでした」のメールが毎日届いていた間にも新しい回は取り込まれていた (実測) = メールで判断せず [外から回を数える](#verify-from-outside)。番組の URL = `youtube.com/playlist?list=<ID>` (Studio の番組の行のリンクに出る)。途中で閉じると一覧に「設定を続行」が残り、取り込む範囲が保存されていないことがある (実測) = 開いて範囲から選び直す。⚠️ 一度取り込んだ回は GUID で固定され、後で音声を差し替えても取り直さない (取り込みの規約) = 音声の直しは登録の前に済ませる。狭い画面ではダイアログの右下のボタンが画面の外に出る |

登録できたら、各配信先の番組ページの URL を公式サイトとホストの「配信先」欄に入れる。
URL は開くことを確かめてから入れる (登録直後は開かない)。
<a id="link-check-title"></a>**「開く」は HTTP 200 ではなく、ページの題 (`<title>`) が期待のページであること**で確かめる。失効して他人の手に渡ったドメインは、別のサイト (賭博・広告) が 200 で返す (実測: ある番組の旧ドメインがそうなっていた)。回ごとの「出てきたもの」のリンクも同じ。bot を弾くサイトは curl に 403 を返す = ブラウザで題を見る

## <a id="artwork-jpeg"></a>番組の画像は RGB の JPEG で

3000 × 3000 の PNG をホストに上げると、透明度つき (RGBA) の PNG に保存し直されて容量も膨らむことがある (実測)。
Apple Podcasts は RGB を求めるので、**配信先に渡すのは RGB の JPEG** にする (JPEG は透明度を持てないので同じことが起きない)。
PNG は元の絵として手元に残す。

## <a id="show-website-link"></a>公式サイトへのリンクは説明文に書く

ホストが出す RSS の番組リンク (`<link>`) はホスト自身の番組ページに固定され、変える欄が無いことがある (実測)。
その場合、公式サイトへのリンクは**番組の説明文の末尾**と**各回の紹介文の末尾**に書く。アプリは各回の紹介文を
番組の説明文より目立つ所に出すので、回の方にも要る。回の紹介文に足す 1 行は予約の道具で自動で付けると漏れない。

- **サイトは各回にページを持たせ (`…/ep/3/`)、紹介文からはそのページへ飛ばす**。ページごとにその回の題と紹介文を
  `og:title` / `og:description` に入れると、SNS にその回のリンクを貼ったときにその回のカードが出る。
  1 ページに全部の回を並べて目印 (`…/#ep3`) で飛ばす形では、カードはどの回でも番組全体のものになる
  (`#` 以降はサーバーに送られず、カードを作る側はページの JavaScript も走らせない)
- **目印の形のリンクを公開済みの紹介文に書いてしまったら**、紹介文は書き換えず、トップの `<head>` の小さな script で
  `#ep<番号>` をその回のページへ移す (サイトにある番号だけ = 公開直後でまだページが無い回はトップに留まる)
- **回の一覧は、トップには新しい数回だけを置き、それを超えたら「すべての回」のページへのリンクを回数で自動で出す**。
  トップに全部を並べる (たたむ形も開けば同じ) と回が増えるたびにトップが伸び、お便りの欄などが下へ沈む。
  「増えたら移す」 を人が覚えておく形にしない (回数で切り替える)

## <a id="host-normalization"></a>ホストの音量調整は外す

手元で -16 LUFS に仕上げたなら、ホストのアップロード時の「ラウドネスをノーマライズする」は外す。
作り直させると符号化が 1 回増え、雑音除去が入ることもある。外して上げると、配信ファイルが手元の MP3 と
バイト単位で同じになることを確かめられる (sha256 を比べる)。

## <a id="scheduled-publish-api"></a>API で公開予約を入れるとき

- **時差の指定が無視されることがある**: `+09:00` 付きで渡しても、その数字が UTC として保存された (実測、LISTEN)。
  現地時間の枠は UTC に直し、時差を書かない形で渡す。作ったら**予約時刻を読み戻して**期待と比べる
- 予約時刻を渡すと状態は「予約済み」になる (下書きを指定しても)。公開はホストが時刻に行い、配信先には RSS で届く
- 紹介文を後から書き換えるときは、書き換えない欄 (題・公開範囲・回の番号) も読んだ値を渡し直す。
  省いた欄が消えるかはサービス次第なので、書き換えの前後で全欄を読み比べる
- **本番の番組で API を試すなら、試しのエピソードには捨ててよい URL (slug) を明示する**。省くと番号つきの URL が振られ、
  消してもその URL が解放されず、あとで本番の回がその番号を使えなくなった (実測、LISTEN。振られ方は推定)。
  消す前に slug を別の名前に付け替えておけば、元の URL は空く (実測 = [`#listen-style-api`](#listen-style-api))。
  当たったら本番の回の URL を別のもの (`ep03` など) にする。サイトや紹介文のリンクは API が返す URL を使えば壊れない
- 予約中・非公開の回は、一覧の API にも公開ページにも出ないことがある (実測) = 読み戻しは作ったときの ID で
- 上げた直後は長さ・大きさの欄が空で、数分で埋まる (実測)。公開前日になっても空なら処理の失敗を疑って知らせる
  (長さが空の RSS は配信先の登録で失敗する、[上](#rss-directories))

## <a id="unattended-release-split"></a>配信を無人のマシンに任せるとき

音声は多くの場合クラウドストレージか作業用のマシンにある。無人のマシンの launchd からは
`~/Library/CloudStorage/` が読めないことが多い ([`launchd-cloudstorage-tcc.md`](launchd-cloudstorage-tcc.md))。
そこで仕事を 2 つに分ける:

1. **手元 (回を用意する場)**: 仕上げ・題・紹介文を用意して持ち主の OK をもらい、**OK を記録したその場で**
   音声を上げて公開予約まで済ませる。予約表 (回ごとの題・紹介文・音声の sha256・枠・OK・状態) を git に置いて push する
2. **無人のマシン**: 1 日数回、予約表を pull して、予約した回が公開されたかをホストに問い合わせ、公開されたら
   公式サイトに載せて push する。次の枠が空・OK 待ちの回が近い・OK 済みなのに予約されていない・公開時刻を過ぎても
   公開されない、を知らせる。**音声は読まない**

こうすると、無人のマシンに要るのは 2 つの repo と API のトークンと git の push だけで、マシンを替えても担当を移すだけで済む。
同じことを知らせ続けないよう、知らせの本文が前回と違うときだけ送る (起きたこと = 予約した・公開した、は毎回送る)。

## <a id="delegated-release"></a>配信の判断を任されたとき

持ち主から「題も切れ目も予約も任せる」 と言われたら、回ごとの OK を取らずに進めてよいが、次を決めておく:

- **出す前に聞く例外**を書いておく: 番組として触れないと決めた話題に触れている / 共演者や第三者の実名・連絡先・本人が公開して
  いない事情が音声に入っている / すでに出すと決めた範囲を越える私的な話 / 配信の決まりを外れる (枠の変更・差し替え・取り下げ)。
  音声は後から一部だけ消しにくいので、書き起こしを通して読み、語の検索もかけてから予約する
- **題は収録の中で言い切られていることにする**。話の中で「説」「らしい」 と留保された主張を題で断定しない (紹介文なら留保ごと書ける)
- <a id="title-without-production-metadata"></a>**題には中身だけを置く**。収録日や分割の番号 (k/n) のような作り手側の情報は題に入れず、紹介文の最後の 1 行へ移す。
  配信日はどのアプリでも別の欄に出るので収録日は聴く人に要らない / 「3/3」 は続きものの断片に見えて途中から聴く人を遠ざける /
  アプリは長い題の後ろを切る。予約表には別の欄 (収録日・分割) で持ち、最後の行は道具が作る (題に手で書く運用は元に戻る)。
  その行は短い記号の形 (「YYYY.M.D 収録 k/n」) にする。「n つに分けた k つめ」 と言葉で開くと冗長 (実測: 持ち主に冗長と言われて戻した)
- **予約は公開の数日前までに入れる** (取り消せる余裕を残す)。予約したら、題・紹介文・枠・判断した点 (切れ目・頭の削り・題の差し替え)
  をまとめて持ち主に報告する
- 予約表の OK の欄には、持ち主の OK なのか委任での判断なのかを書く (後から誰が決めたか分かるように)
- 出す前に聞くと決めた話を見つけたら、**該当する回だけ予約を止めて**、ほかの回は進める。聞くときは話の中身を 3〜4 行に要約し、「そのまま出す / その一言だけ切る / その話ごと切る」 のように選べる形にする。返事は予約表と記録に持ち主の発言のまま書く
- 宣伝 (SNS への投稿) は別にする: 文案は作ってよいが、持ち主のアカウントから出すものは持ち主が投稿する
- **題・紹介文に使う語は、機械の文字起こしの聞き違いを疑う**。同音の漢字の取り違え (合成例: 「〜権」 を 「〜券」) は、
  どの転写を回しても同じに出るので気づきにくい。題にする語は前後の言い直し (「〜の権利」 等) と誤転写の対照表で確かめ、
  確かめられなければ持ち主に聞く (実測: 公開してから持ち主の指摘で直した)。転写側の規律 = [`audio-transcription.md#transcript-words-in-titles`](audio-transcription.md#transcript-words-in-titles)

## <a id="regroup-scheduled-episodes"></a>予約済みの回を組み替えるとき

配信尺の決まりを変えた・短すぎる回があった、などで**まだ出していない回を切り直す・番号を繰り上げる**とき:

1. **出した回は切り直さない**。切り直すのは未公開の部分だけ。本数は「残りの長さ ÷ 下限」で上限が決まる (付ける冒頭・締めの音の長さも足す)。
   切れ目の選び方 = [`audio-transcription.md#splitting-long-recordings`](audio-transcription.md#splitting-long-recordings)
2. **予約表 (正本) を先に直す**: 番号・題 (「k/n」 のような分割数が入っていれば、出した回の分も)・紹介文・枠・URL
3. ホストを 1 回ずつ予約表に合わせ、**そのつど読み戻す** (状態・公開時刻・URL・紹介文が空でないこと)。順番:
   外す回の slug を替えて下書き・非公開に戻す (消さない = [`#listen-style-api`](#listen-style-api)) → 空いた slug から順に、後ろの回の URL を
   回の番号に付け替える (付ける前に空いていないと失敗する) → 枠を前へ詰める
4. 最後に**全回を読み戻して予約表と突き合わせる** (状態・時刻・題・紹介文のリンク・音声の大きさと長さ)
5. 出した回の題を直したなら、RSS に新しい題が出たことを確かめる (配信先は RSS に合わせて同じ回の題を書き換える)
6. 共同作業者と共有している配信用の写しも差し替える。**旧版は消さずに別のフォルダへ**移し、どの版が旧いかを名前で分かるようにする

## <a id="verify-from-outside"></a>配信先で聴けるかを外から確かめる

各配信先が番組を公開しているか・新しい回が入ったかは、管理画面へのログイン無しに外から読める。
「全部の配信先に出ている?」には、管理画面の表示やメールでなく、これで答える。

| 配信先 | 見る URL | 分かること |
|---|---|---|
| ホスト | 番組の RSS (curl で読む。python の既定の User-Agent は弾かれることがある) | 回の数と最新の回 = 突き合わせの基準 |
| Apple Podcasts | `https://itunes.apple.com/lookup?id=<番組の番号>&entity=podcastEpisode&limit=1&country=<国>` | 番組が出ているか (公開の直後は 0 件) と最新の回 |
| YouTube | `https://www.youtube.com/feeds/videos.xml?playlist_id=<番組の再生リスト ID>` | 公開されている回 (非公開の間は 0、新しい 15 回まで)。⚠️ 公開中でも一時的に 404 を返すことがある (実測: 404 の数分後に 200 で全回) = 1 回の 404 を「非公開」と読まず、間をおいて読み直す。読み直しても 200 でなければ「読めない」と報告する (非公開かどうかはこれでは分からない) |
| Spotify / Amazon Music | 番組ページ | 開くか (HTTP 200) だけ。回までは見えない |
| ホストの番組ページ・公式サイト | 各ページの HTML | 各配信先へのリンクが全部あるか |

- **最新の回をホストの RSS と突き合わせる**: 配信先の最新の回が RSS より古ければ、取り込みが遅れているか止まっている。
  公開の直後の食い違いは、少し待ってから見直す (配信先が RSS を読みに来る間隔は配信先ごとに違う)
- 番組ごとの URL の一覧は 1 か所 (公式サイトのデータなど) に置き、確かめる道具はそこから読む (URL を道具に写さない)

## <a id="follower-counts"></a>フォロワー数を読む

フォロワー数は外からは読めない (番組ページ・検索 API・公開フィードのどれにも出ない) = 配信先ごとの管理画面か、持ち主の認証で読む口 (ホストの API・YouTube Data API = [下](#follower-counts-without-login-screen)) で読む。
管理画面では再生数・聴いた人の数が同じ画面に並ぶので、欄の名前 (と欄の説明) を見て取り違えない。ログインは持ち主がする。

| 配信先 | 読む場所 | 注意 (実測) |
|---|---|---|
| ホスト (LISTEN) | GraphQL `podcast(id) { followers { id name username } }` | フォローしている利用者の**一覧**が返る = 誰かまで分かる。持ち主が個人のアカウントでフォローしていればそれも入る = 「自分を除く」 はこの一覧から引く |
| Spotify | Spotify for Creators の番組のホーム (題の下の「N 人のフォロワー」) | 全期間の総数。誰かは出ない。再生回数・オーディエンス (過去 30 日) が同じ画面に並ぶ |
| Apple Podcasts | Podcasts Connect の「アナリティクス」の番組の表の「フォロワー」の列 | 分析値が「-」や API の null で非表示になることがある。表示条件は選んだ期間内に少なくとも 5 人のユニークユーザーが再生すること ([Data requirements](https://podcasters.apple.com/support/841-data-requirements)) であり、フォロワー数が 5 未満という意味ではない。非表示なら人数不明として扱い、0〜4 人という上限を置かない。番組を持たない Apple Account で入ると番組が出ない ([上の表](#rss-directories))。サインインは同じ日のうちに切れた (実測)。保存済み認証も有効期限を保証せず、失効時は持ち主が入り直す。画面の幅が狭いと表でなく 1 列 (既定はリスナー) の一覧になり、フォロワーの列が出ない = 幅を広げて読む (実測)。Podcasts Connect の画面に案内のある公式の CLI「Reporter」 は、サブスクリプションと支払い・財務のレポートを落とす道具で、フォロワーなどのアナリティクスは落とせない ([About Reporter](https://help.apple.com/itc/podcastsreporterguide/en.lproj/static.html)) |
| Amazon Music | Amazon Music for Podcasters の Overview の FOLLOWERS | **右上で選んだ期間の数** = 既定の 7 日では 0 と出ることがある。始めて 90 日以内の番組は「Last 90 days」 で全部になる。**画面で選べる期間は最長 90 日** = それより古い番組の全期間は、ページの裏の `POST /api/metrics/podcast` (`followsAggregate` を `PODCAST_ID` ごと、ヘッダ `csrf-token` = `localStorage` の `csrfToken`) に番組の開始より前からの期間を渡して、ページの中から読む (実測: 7 日で 0、90 日と開始前からで同じ数)。⚠️ 終わりの時刻を未来にすると HTTP 200 のまま `error` に `DependencyException` が入って数が空になる (実測) = 終わりは今日の 0 時 (UTC)。定義 = 番組の Follow を押した Amazon Music の利用者 (同 FAQ) |
| YouTube | YouTube Studio のアナリティクス →「リアルタイム」 の「チャンネル登録者 (現在の数)」 | 番組 (再生リスト) でなく**チャンネル**の登録者。チャンネルの公開ページの見出しに登録者数の行が出ないことがある (Studio で 0 のときに出なかった。非表示の設定でも出ないので、行が無いことから 0 とは言えない) = Studio で読む。Studio に別のアカウントで入っていると「権限がありません」 = URL に `?authuser=<番組のアカウントのアドレス>` を付けると切り替わる |

- 配信先を足した数は「のべ」: 同じ人が複数の配信先でフォローしていても除けない。持ち主本人を除けるのも一覧が出るホストだけ
- 管理画面でしか読めない配信先は、**ページの中で数だけを返す JS** (画面の文から抜く / 裏の口をページの中から叩く) にしておくと、ログイン済みのブラウザで毎回同じ手順で読める。返すのは数だけにする (トークン・利用者名を返さない)。ログインが切れていれば「要ログイン」、頁や画面が違えば「読めない欄」 を返して途中で止めない ([`web-form-automation.md#step-driver-harness`](web-form-automation.md#step-driver-harness) の契約 1)
- Google でログインする管理画面は、ブラウザに Google のログインが残っていてもパスワードかパスキーを聞かれることがある (持ち主が入れる)
- <a id="follower-counts-without-login-screen"></a>**ログインの画面を開かずに読む口**: YouTube は公式の YouTube Data API (`channels.list` の `part=statistics`・`mine=true`) で登録者数が返る
  = 持ち主の OAuth 同意後は refresh token で access token を更新して読める。更新トークンの失効・取り消し時は持ち主の再同意が必要。
  Spotify・Apple・Amazon の管理画面が使う API は、持ち主が提供した認証で CLI から読む経路もある。
  実装 = [`scripts/podcast-followers.py`](../scripts/podcast-followers.py)。Spotify は番組 metadata の followers、Amazon は followsAggregate、Apple は全期間の FOLLOWERS を読む。
  数値非表示 (Apple の null) と取得失敗を分け、認証エラーを 0 人にしない。端末の長い非表示入力・保存権限・送信先制限・応答検査は共通 engine、番組 ID と非表示を集計へどう入れるかは呼び元が持つ。
  分けられているかの確かめ方 = 保存した認証と同じ形で値だけを無効にした写しを一時 dir に作り、記録しない形で 1 回読む (engine なら配信先ごとに `--check <配信先> --show <番組 ID> --auth-dir <写し>`)。
  3 つとも status が認証エラー (`login_required` / `login_required_or_access_denied`) で数が空なら、失効した日に 0 人や非表示として記録されない (実測)。写しは読んだらすぐ消す。
  同じ engine の `render_history_chart` は保存済み履歴から SVG / PNG を描き、欠測と集計上の仮定を区別する。
  - ⚠️ 管理画面のログインの Cookie を保存して読ませる形は、 そのアカウントにログインしているのと同じ力を手元に置く = 漏れたら乗っ取られる
  - ⚠️ Claude Code の auto mode では、 ログイン中のページから値を抜き出す操作も、 Cookie で読む道具を書く操作も、 classifier が「認証情報の探索」 として止めた (実測)。
    作るかどうかは持ち主が決め、 権限の設定 (毎回確認する mode か、 その作業に絞った規則) も持ち主が先に決める。 止められた操作を別の道具で続けない

## <a id="promo-per-platform"></a>番組の告知文を媒体ごとに書く

同じ回の告知を、 ニュースレター (Substack など) と SNS (Mastodon 系・Bluesky・X) に書き分けるとき。

- **その媒体でしか通じない事実は、 他の媒体では売りにならない**: その媒体で受けた感想・反応に応える回だ、 という話は、 そこの読者にしか響かない。
  媒体ごとに、 その読者が初めて聞いて引かれる中身 (その回の話・この先の回の話) を選び直す (実測 = 持ち主の指摘)
- **番組の内側の言葉は読者に見えない**: 1 回の収録を何回にも分けて出す番組で「後半は」「収録の後半は」 と書くと、 何の後半か分からない。
  起きることそのもの (「飲みながら録るので、 だんだん…」) を書く (実測)
- **字数は媒体ごとの数え方で数える** = [`../scripts/post-length.py`](../scripts/post-length.py) (X は日本語 1 字を 2、 URL は 23)。
  X は無料のアカウントで 280。 有料のプランは長い投稿ができるが、 上限は情報源で割れている (25,000 / 4,000)。 長い投稿もタイムラインには頭の 280 ぶんだけが出る = 引きは頭に置く
- URL を貼るとカードが出る媒体 (Bluesky・X) では、 回の題はカードに出る = 本文は引きに使う

## <a id="listen-style-api"></a>LISTEN (listen.style) の API

公式の説明書は無く、GraphQL を introspection で読んだ (実測)。

- 窓口 = `https://listen.style/graphql`、認証 = Bearer の API トークン (設定の「API トークン」で作る)
- 音声 = `createPresignedUploadUrl(fileName, type: AUDIO, contentType)` → 返った `uploadUrl` に PUT → `path` を
  `createEpisode(..., media: {audioPath})` に渡す。`createEpisode` は `status: SCHEDULED` + `scheduledAt` で予約、
  `normalizeLoudness: false` でホストの音量調整を外す。`scheduledAt` の時差は無視される (上の節)
- 読む = `episodes(ids)` / `podcast(id)`。紹介文は **HTML で保存される** (`<p>…</p>`)
- 紹介文の書き換え = `updateEpisode` (題と公開範囲は必須。回の番号も渡す。状態・音声・出演者は省けば変わらなかった)
- 音声の差し替え (仕上げを作り直したとき) = 同じ `updateEpisode` に `media: {audioPath}` (+ `normalizeLoudness: false`)。状態・公開時刻・出演者・画像は残る。⚠️ **紹介文 (`description`) を渡さないと空で上書きされる** (実測: 音声だけ渡したら全回の紹介文が消え、公開中の回も数分空になった) = 音声だけ替えるときも紹介文を毎回渡し、読み戻して空でないことを確かめる
- **今すぐ公開** = `updateEpisode` に `status: PUBLISHED` だけを渡す (`scheduledAt` は渡さない)。予約中の回がその場で公開になり、
  `pubDate` はその時刻になった。RSS には数分以内に載った (実測)。紹介文は上の注意どおり毎回渡す
- **URL (slug) の付け替え** = `updateEpisode(slug: …)`。付け替えて空いた slug は、別のエピソードに付けられた (実測)。
  = 要らなくなった予約は**消さずに** slug を替えて `status: DRAFT` + `visibility: PRIVATE` に戻すと、元の URL を次の回に使える
  (消すと URL が解放されない = [上の節](#scheduled-publish-api))。戻した後は状態が `DRAFT` になったことを読み戻す (予約のままだと公開される)
- 公開済みの回の題を直すと、RSS は数分で作り直された (実測)。RSS の回の識別子 (`guid`) は題と無関係の値 = 題を直しても配信先で
  別の回として増えない (配信先はそれぞれ次に RSS を読んだときに書き換える)
- **番組の設定 (説明文・配信先の URL・カテゴリ) を変える mutation は無い** = 画面から。作成画面ではカテゴリを 1 つしか選べない。
  配信先の URL = ダッシュボード → 番組 → 選択欄「設定」→「配信先編集メニュー」のボタン →「配信先サービスを設定する」
  (Spotify / Apple / YouTube Music / Amazon と、連携サービスの YouTube・X など) →「送信」。
  ⚠️ 番組のカードの「⋮」は配信先の入口ではなく、「ポッドキャストを削除する」が並んでいる
- アカウントの写真 (ダッシュボードの管理者の欄に出る) は `/user/profile` で替える。ログインに使った Google アカウントの写真とは別で、
  既定は表示名の文字を丸に入れたもの。ファイルを選ぶ画面になるので、選ぶのは持ち主
- **埋め込みプレーヤー** = oEmbed (`https://listen.style/oembed?url=<回の URL>`) が `<回の URL>/player` の iframe (高さ 178px) を返す。
  選べるのは色 (`?theme=auto|light|dark`) だけ。プレーヤーにはその回について LISTEN が出す文も出て、隠せない
  (紹介文の回もあれば、文字起こしの抜粋の回もあった、実測。どちらを出すかを決める欄は、GraphQL の Episode 型と mutation、
  回の管理画面には見当たらなかった) = 自動の文字起こしの誤変換がサイトに出うる。埋め込む前に持ち主に見せ、
  サイトの作りはプレーヤーの有無を回ごとに切り替える形にしておく
  - 文字起こしの誤変換は、持ち主がログインした回のページで段ごとに直す (段に hover → 鉛筆 → 編集欄 → Enter で保存)。
    直した文は回のページにはすぐ出たが、プレーヤーの抜粋は 60 分たっても古い文のままだった (実測) = プレーヤーの文を直す手段として当てにしない
  - 編集欄を機械で直すとき、キーで全選択して打ち直すと文字が欄の途中に入った (実測)。欄の値を丸ごと入れ直してから Enter で保存する
- 公式の MCP (`@ondinc/listen-mcp-server`) は読むだけ
- 消したエピソードの URL は解放されない / 予約中・非公開の回は一覧に出ない / 上げた直後は長さが空 (いずれも [上の節](#scheduled-publish-api))
- RSS は python の `urllib` の既定の User-Agent だと 403 を返す (curl では読める)
