# 研究者向けプログラム申請の所属確認 (機関メール・研究室ページ・審査)

AI ベンダー等が PI 向けに出す割引・無償プランは、 申請フォームで **機関メール** と **研究室ページ** から所属を確かめる。 本 doc はその通し方と落ちどころ。

観測元 = 実測 (非英語圏の大学に所属する PI の申請、 n=1)。 n=1 の観測は「観測」、 解釈は「推測」 と書き分ける。

> 画面操作一般は [`web-form-automation.md`](web-form-automation.md)、 経路の選び方は [`machine-route-first.md`](machine-route-first.md)、 人間にしかできない最終操作の手渡しは [`convention-design-principles.md#user-execution-handoff`](../docs/convention-design-principles.md#user-execution-handoff)。

## <a id="flow-shape"></a>1. フォームの形と、 どこで落ちるか

- 典型の 4 段: ① 資格の宣誓 (PI であること) → ② 機関メールの確認 → ③ 研究室ページの URL → ④ 審査。
- ④ で **数秒以内に不合格** = 自動 gate。 画面と同時に「資格を確認できませんでした」 のメールが届く。 **「手動審査のために送信されました」 = gate 通過** (人の審査。 観測では「通常 7 営業日」)。
- 不合格からの再申請はその場でできた。 **1 回ごとに変えるのは 1 項目** にする (どれが効いたか後で分かるように)。
- 分野ごとの枠が埋まった告知が冒頭に出ることがある。 申請分野は実態どおりに選ぶ (埋まった分野に寄せない)。

## <a id="lab-page-requirements"></a>2. 研究室ページは「機関ドメイン上」 かつ「申請名と同じ文字体系」

観測 (同一申請者・同一機関メール・同一アカウントで 3 回):

| 出したページ | 結果 |
|---|---|
| 研究室の独自サイト (外部ホスティングのドメイン。 メンバー欄には氏名・職位・機関メールがあるが、 出したのがどのページかは未確認) | 即時不合格 |
| 機関ドメイン上の公式の個人ページ (漢字・カナのみ。 ローマ字名もメールも無い) | 即時不合格 |
| 機関ドメイン上の英語版の教員一覧 (ローマ字名・職位・分野の 1 行) ※ 推定 (出したページの記録が残っておらず、 後から確かめられなかった) | 手動審査へ |

- 推測: 自動 gate は ① URL のドメインが機関のものか ② ページ上の名前が申請者 (アカウント名・機関メール) と結びつくか、 を見ている。 ① は 1 行目と 3 行目の対比から、 ② は 2 行目と 3 行目の対比から。
- **How to apply**: 非英語圏の申請者は、 まず **機関ドメイン上の英語ページ** (英語版の教員一覧・英語プロフィール) を探す。 母語だけの公式個人ページは ③ に入れず、 ④ の自由記述欄に回す。
- 大学の研究者データベースが外部業者のドメインで動いていることがある。 英語の個人ページがあっても ① で落ちうるので、 ドメインを確かめてから使う。
- 研究室の独自サイト (GitHub Pages / Cloudflare Pages 等) は通らなかった。 機関ドメインでない時点で落ちると考えておくのが安全。

## <a id="evidence-field-bridge"></a>3. 手動審査の自由記述欄 = gate が結べなかったものを人に渡す

- 審査中の画面に「審査に追加したい証拠」 欄 (観測: 200 字) が出ることがある。 入れるもの:
  1. 役割 (PI / Professor)
  2. 母語表記 ↔ ローマ字の対応 (例 `山田太郎 = Taro Yamada`)。 ③ に出したページが一覧や別表記 (ハイフンの有無等) のときに特に要る
  3. 個人の公式ページの URL (母語のみでもよい。 人は機械翻訳で読める)
  4. 分野の共同体 DB (INSPIRE / ORCID / Google Scholar 等) — 所属と業績を第三者の場で示す
- URL が字数の大半を使う。 **字数は目視でなく機械で数える** (`python3 -c "print(len('...'))"`)。 候補を 2〜3 本、 字数つきで並べて user に選んでもらう。
- 審査中画面の「取り下げて別のリンクで再申請」 は審査中の申請を捨てる操作。 証拠の追加で足りるなら使わない。

## <a id="magic-link-handoff"></a>4. 機関メールの確認が「サインイン用リンク」 のとき

- 確認メールがコードでなく **ログイン用のリンク** (観測: 10 分で失効、 件名は「安全なリンクが届きました」 型) のことがある。 リンクを開く = 申請者名義でログインする操作 = 認証の代行なので、 **agent は開かない**。
- agent がやること: 受信箱を読み、 **到着時刻と失効時刻** を伝え、 そのメールへの直リンクを渡す。 再送のたびに新しいリンクが届くので、 最新のものを指す。
- user に添える注意: **フォームを開いているのと同じブラウザ profile で開く** (別 profile だと別のセッションに入る) / ログアウトや新規アカウント作成の画面が出たら進めずに止める。
- 画面がコードの入力を促した場合だけ、 user から受け取ったコードを agent が入れてよい。

## <a id="after-submission"></a>5. 提出後

- 「◯営業日で回答」 は予告された inbound。 **回答予定日 + 14 日の待ち TODO** を同じ turn で立てる (一般則 = [`convention-design-principles.md#expected-inbound-tripwire`](../docs/convention-design-principles.md#expected-inbound-tripwire))。 回答は機関メール宛に届く。
- 既存の個人サブスクリプションとの関係 (移せるか・別課金が続くか) はフォームに書かれていないことが多い。 承認後の加入時に確かめ、 申請の時点では決めない。
- 支払い情報の入力と最終の加入操作は user 本人。
- **結果の通知は毎回 新しいスレッドの no-reply で来て、 送り手 domain が雑音 list に入っていることが多い** →
  待ち項目に送り手の検索条件を書く ([`email-surface-pattern.md#new-thread-expected-inbound`](email-surface-pattern.md#new-thread-expected-inbound))。
  手動審査の結果は、 見込み (7 営業日) より早く来ることがある (実測)

## <a id="after-decline"></a>6. 手動審査で不承認になった後

観測 (実測):

- **手動審査の不承認メールは、 自動 gate の即時不合格と同じ文面** (理由は書かれない)。 本文だけでは「どの申請の結果か」
  が分からないので、 手動審査に回った申請が残っていたかで判断する
- 不承認の後に再申請すると、 **機関メールの確認の直後に即時不合格** になり、 研究室ページを入れる画面が出なかった
  → 研究室ページや証拠を変える再申請は効かない。 **問い合わせに切り替える**
- 機関メールの確認リンク (サインイン用) を開くと、 **機関メールで別のアカウントにサインインする**
  (個人の有料アカウントとは別)。 問い合わせ前に、 どのアカウントで申請したかを画面左下などで確かめる
- 申請アカウントの画面に「同じ組織の別チームに参加しましょう」 型の案内が出ることがある (同じドメインで既に
  チームがある場合)。 即時不合格との関係は分からない (推測の域)

問い合わせの経路:

- **無料プランのアカウントのサポートチャットは AI だけ** (人に引き継がれない)。 有料プランのアカウントに
  入り直すと、 人の窓口がありうる経路になる。 本文には「申請は別アカウント (機関メール) で行った」 と書く
- チャットの AI は、 資格確認が繰り返し落ちる件を **本人確認ヘルプフォーム** に回した。 フォームの項目
  (観測): 申請アカウントのメール / 組織 ID (設定 → アカウント) / 個人か組織か / 問題の種類 (身分証・セルフィー系の
  選択肢の中に「その他」) / 自由記述。 **自由記述は 500 字で切れる** — 貼る前に機械で数え (`python3 -c "print(len(...))"`)、
  入る版を先に作る。 Enter は送信なので、 改行は貼り付けで入れる
- 選び方の推測: 資格 (大学の PI か) の確認なので「組織」、 身分証の不具合ではないので「その他」
- 自由記述に入れるもの: 役職と所属 / 不承認と即時不合格の日時 (UTC) / 英語で名前・職位・所属が載るページ /
  サポートチャットの会話 ID。 **研究室ページ欄に入れた URL は重ねない** (字数の無駄)。 研究室の独自サイトは
  自動 gate では落ちるが、 **機関メールが名前と並んで載るページなら人が読む証拠としては強い**
