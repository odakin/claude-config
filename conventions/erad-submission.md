# e-Rad / 競争的研究費 応募の落とし穴・書式ルール

府省共通研究開発管理システム（e-Rad）経由で研究費（JST・科研費・各種財団等）に応募する際の、**フォーム固有の制限・書式ルール・つまずきどころ**。e-Rad の応募フォームを Claude が代行入力・支援する前に読む。

制度ごとの個別値（費目・分野分類・字数上限・締切・予算枠）は各制度の**公募要領**＋応募管理リポの制度別ディレクトリを正とし、本書は**制度横断で効く e-Rad フォームの挙動**を扱う。出典 = JST 公募要領・e-Rad 操作マニュアル（例: JST 各事業の e-Rad マニュアル）＋ 実応募での観察。

> ⚠️ **本書の一般則は限られた制度での実応募観察に基づく**（全制度を網羅検証したものではない）。e-Rad は制度ごとに項目・制限・必須欄が異なるため、各記述は「観察された挙動」として扱い、実際の応募では必ず当該制度の公募要領・e-Rad マニュアルで裏取りすること。

## 応募フォームのタブ構成
- e-Rad の応募入力は **4 タブ構成**: **基本情報** / **研究経費・研究組織** / **個別項目** / **応募・受入状況**。各タブを順に埋めて保存する。
- 自由記述（研究目的・研究概要等）や課題名・分野は「基本情報」「個別項目」、金額・組織は「研究経費・研究組織」、他制度との重複・エフォートは「応募・受入状況」に分かれる（各タブの詳細は本書の該当節を参照）。

## 応募情報ファイル（提案書の添付）
- e-Rad の「**応募情報ファイル**」欄 = 応募者が作成した提案様式（提案書）の **PDF をアップロードする欄**（「参照」→ ファイル選択 →「アップロード」）。e-Rad の Web 入力情報と結合され、1 つの応募内容提案書 PDF になる。
- 1 ファイル・最大容量は制度規定（30MB / 10MB 等、要項確認）。
- **提出形式は制度依存**: 応募情報ファイルとして **PDF をアップロードする制度**（JST 等）と、**様式の xlsx/docx 本体をそのまま提出する制度**（科研費系）がある。要項で指定形式を確認する（様式の fill → PDF 化の手順は [office-automation.md](office-automation.md)）。
- 提出するのは **完成・承認済みの正式版 PDF**。生成途中の下書き・中間レンダリング・編集用 docx と取り違えない。

## 文字種の制限
e-Rad の入力欄は厳格な charset 制限があり、**欄の種類で置換戦略が違う**:
- **研究課題名（英語）など半角欄**: 半角（ASCII）限定。ギリシャ文字（μ, τ, α …）・全角マイナス（−, U+2212）・全角記号はエラー（「半角文字で入力してください」）。→ **英語綴り / ASCII に置換**（μ→mu, τ→tau, −→半角ハイフン）。カタカナ置換は英語欄では不適。
- **研究目的・研究概要・役割分担等の日本語 long-textarea**: ギリシャ文字・上付下付・数学記号・`§`・エム・ダッシュ・丸付き数字・ローマ数字・機種依存文字を弾く。→ **カナ / 日本語に置換**（σ→シグマ、①→(1)、—→、）。日本語欄でも全角は可だがこれら弾かれ文字は除く。
- **禁止文字の詳細リスト（置換表）は [office-automation.md #erad-forbidden-chars](office-automation.md#erad-forbidden-chars) が正本**。応募様式（xlsx/docx）の draft 段階で排除しておくと、様式と e-Rad textarea の二重 maintenance が不要。

## 字数制限（フォーム依存）
- 研究目的・研究概要・役割分担・相違点 等の自由記述欄には **字数上限**がある（**改行・スペースも 1 文字としてカウント**することが多い）。上限は制度・欄ごとに異なる。
- 超過すると **末尾が黙って切れる** か保存時エラーになる。→ **貼り付け前に文字数を実測**し、貼付後にフォームのカウンタも確認する。コピペで末尾に改行・空白が混入して超過することがあるので末尾を点検。
- 制度によっては自由記述欄に「提案書参照」と書かせる運用もあるが、実内容の記入を求める制度もある（要項に従う）。

## 研究分野は二系統（混同注意）
- **制度独自の大分類**（ラジオボタン等の固定リスト）= 提案様式の分野欄と一致させる。
- **e-Rad 共通の研究分野（「研究の内容検索」ポップアップ）** = 科研費系の細目分類。制度の大分類名で検索しても実体に合う細目は出ないことが多い。**研究の実体**を表すキーワード（例: 理論素粒子なら「素粒子」→「素粒子・原子核・宇宙線・宇宙物理」）で検索・選択する。両者は独立した別項目。

## 研究経費・研究組織
- 金額は **千円単位**で入力する欄が多い（"____,000 円"）。
- **間接経費 = 直接経費の一定率**（10% 等、制度規定）。固定で自動計算 or 手入力。様式が消費税欄空欄なら 0。
- **「研究組織」の各メンバー直接経費は初年度分のみ**（全期間総額ではない）。「申請額（初年度）」と「研究者ごとの金額合計」が一致して差額 0 になればよい。
- **直接経費と間接経費は別欄**。合計を 1 欄に入れない（合計は自動表示）。
- **年度配分**: 日本の年度 = 4月〜翌3月。研究期間・招へい/滞在期間が年度境界（3月→4月）を跨ぐ費目は年度分割（例: 1〜6月の活動 → 1〜3月＝前年度・4〜6月＝当年度に按分）。1 年度に収まれば全額その年度・他年度 0（必須欄なので 0 を明示入力）。

## 応募・受入状況（不合理な重複・過度の集中）
- **「研究内容の相違点及び他の研究費に加えて本応募研究課題に応募する理由」欄を、応募中・実施中の他の競争的資金すべてに記入**する。本応募自身の行は空欄。テーマ・対象・手法・経費使途の違い＋当該資金が固有に必要な理由を簡潔に書く。
- 同制度の別申請を先に提出済みだと、それも「応募中」として並ぶ。同制度同士は **招へい者・テーマ等の独立性**を明記。
- **エフォート欄は応募者自身の判断値**で、提案書様式側に規定値（推奨%）はない。応募者が実態に即して決める。
- **「その他の活動」のエフォートで全体 100%**。応募中課題のエフォートは応募時点では他活動に計上されない（= 採択までは加算されず、採択時に実態へ反映して再調整。実施中＋その他の活動で 100%）。教育 0% 等の不自然な配分は審査で目立つので実態に合わせる（teaching を 0% にすると査読印象が悪い）。
- 学位欄の「(Unregistered)」= e-Rad 研究者情報に学位の取得年月日・大学が未登録の表示。多くの場合チェックのみで申請は通る（直すなら研究者情報を別途編集）。

## 機関承認・提出フロー
- e-Rad 上の **所属研究機関承認の要否は制度による**（研究者提出だけで完結する制度もある）。ただし研究者招へい・国際協定等を伴う場合、**学内の機関決裁（メール経由）が先に必要**なことが多い。
- 一般的フロー: 申請書を **研究支援事務へメール提出** → **機関決裁（学長承認等）** → 承認連絡後に **研究者が e-Rad で提出**。
- **機関決裁は時間を要する**。配分機関の締切の **2 週間前まで**に事務へ相談・提出するのが安全（締切直前は e-Rad 混雑で提出処理が間に合わないリスクもある）。
- **課題 ID は応募作成時に e-Rad が自動採番**（手入力不可）。問い合わせ時に使うので控える。

## 提出完了の判定・提出後
- 締切時刻までに応募ステータスが **「配分機関処理中」または「申請中／応募中」**になっていれば正常完了（「受理」は必須ではない）。なっていなければ無効。
- 「提出済の課題 ＞ 課題一覧」でステータスを確認。控え（応募内容提案書 PDF）は「応募内容提案書のプレビュー」or 課題一覧から取得できる。
- 機関決裁した事務へ **提出完了の一報**を入れると事務が状態を把握できる。

## 様式の機械記入・署名合成・提出ファイル（2026 SPReAD 学生応募で確立）

Excel/docx の fill・docx→PDF・署名合成の **一般技法は `office-automation.md` が SoT**。本節は e-Rad / 学生応募 固有のみ。

### 提出ファイルの規定
- **ファイル名**: `第N回_様式M_様式名_e-Rad所属機関コード_ローマ字氏名.{xlsx,pdf}`。⚠️ **接頭辞の有無は回で変わる**（当回の様式0「提出書類リスト」+ 公式 self-check の例で必ず確認。SPReAD は R1 が接頭辞なし・第2回が「第2回_」付き）。ローマ字＝姓先頭大文字で続けて記載。
- **様式1 のみ Excel**、他様式は PDF 化（`docx-to-pdf.sh`）。
- **公式 self-check**: 別紙の `research_plan_self_check.py <様式1.xlsx>`（字数・形式・ファイル名を検証、**要確認ゼロ＝完全クリア**。字数は改行・スペースも1字）。ファイル名が要確認に残るのは接頭辞欠落のことがある。
- **様式1 の式キャッシュ**: openpyxl 記入で字数・経費の式キャッシュが空になる→提出ファイルに値を残すには **Excel で開いて保存**（公式案内）。手順・gate ヘルパー（`assert_formula_cache_intact`）・修復は [`openpyxl-clears-formula-cache`](office-automation.md#openpyxl-clears-formula-cache)。`load_workbook(data_only=True)` で結果確認。
- **応募内容提案書プレビュー**（e-Rad が吐く `E0204R01_*.pdf` 等）= **添付した様式PDF の連結**。様式1（xlsx）と e-Rad 入力欄（課題名・研究目的・経費）は含まれない＝それらはタブ側で別途確認。

### 様式 xlsx の入力セル特定
gov-form xlsx 共通の経験則（LEN 式の先 = 入力 / Y入力は data validation / 業績は 1 件 1 セル / 必要性はラベル 1 つ下の merged / サマリは触らない）は [`gov-form-input-cell-heuristics`](office-automation.md#gov-form-input-cell-heuristics)（観測元: 学振 DC2 + SPReAD 第2回）。 e-Rad 経由 SPReAD の例: 課題名 / 活用方法 = `N列=LEN(C列)` → C列入力。

### docx 同意確認書の記入
- ＿＿ blank → 値 / ☐→☒ / run 分割の対処は [`docx-fill-xml-edit`](office-automation.md#docx-fill-xml-edit)（zip+XML 直編集が runtime 軽量 + run 分割 dump 必須）+ [`docx-checkbox-content-control`](office-automation.md#docx-checkbox-content-control)（content control checkbox は toggle 困難 → PDF 化前提なら `☐→☒` 文字置換で視覚チェック）。
- ⚠️ **記入で行が増えるとページ数が空様式より増える**（判断記載欄等）。**空様式のページ数に合わせる**（文・所属を短縮、フォントは入力欄継承＝本文と同サイズ）。
- 補足に「**直筆署名 又は 氏名入力（電子的記名）も可**」とあることが多い（直筆署名の合成は step 4 = 様式一式の組み立て手順参照）。

### 学生が研究代表者として応募（代理応募）
- 様式 = 様式0/1/2 ＋ **様式3（学生署名）/様式4（指導教員署名）**。学生に研究者番号が無ければ**指導教員の番号で代理応募**（指導教員枠は消費しない）。
- ⚠️ **e-Rad 研究組織タブの「代表者」は指導教員（アカウント所有者）として表示される**（実際の研究代表者＝学生は様式側で明記）。直接/間接経費・エフォートは指導教員に割当。**扱いは機関事務の指示が最優先**。

### e-Rad 基本情報・経費タブ
- 基本情報: 課題名/研究期間（年度単位、最短=最長で固定のことあり）/研究分野(主)+キーワード/**研究目的・研究概要（各1000字、改行スペースも1字）**。様式1本文を流用しつつ1000字近くまで拡張可。[文字種の制限](#文字種の制限)を厳守。
- **経費**: 年度別・円単位。e-Rad は費目を細分（設備備品/消耗品/謝金/旅費/外注/印刷製本/会議/通信運搬/光熱水/その他諸経費/間接）。**API・クラウド計算資源・利用料は原則「その他（諸経費）」**。間接＝直接×30%固定。
- ⚠️ **補助上限が「直接経費基準」のことがある**（SPReAD＝**直接500万以下＋間接30%別途上乗せ**＝総計最大650万）。交付内定＝充足率×上限・申請額が上限なので**満額申請が有利**。下書きが「総計≤上限」で組まれていたら直接を満額に積み直す。

### 様式一式の組み立て手順（assembly order。各技法は office-automation.md スラッグが SoT、再掲しない）
draft + 公式空様式 + 署名画像 → 提出物 の順序。本節は「e-Rad 様式一式に組む順序」だけを持ち、各技法の実装はスラッグへ:
1. **計算式を含む xlsx 様式**を openpyxl で記入 → ⚠️ save で式キャッシュが飛ぶので Excel 再計算保存（[`openpyxl-clears-formula-cache`](office-automation.md#openpyxl-clears-formula-cache)、driver は `pdf_form_fill.assert_formula_cache_intact` で gate）。標題 drawing を持つ様式は [`excel-osascript-cell-write`](office-automation.md#excel-osascript-cell-write) 経由で値を書く。
2. 公式 self-check（あれば `research_plan_self_check.py`）で字数・形式・ファイル名を要確認ゼロまで。
3. **署名する docx 様式**を記入（記入要領削除・☒・run 分割注意）→ `docx-to-pdf.sh` で PDF 化（[`docx-to-pdf-pages`](office-automation.md#docx-to-pdf-pages)、空様式とページ数を一致させる）。
4. **署名を PDF に合成**: ① 手書き写真 → 透過 PNG（帯切出し + 輝度しきい値 + alpha 計算）= [`signature-photo-to-transparent-png`](office-automation.md#signature-photo-to-transparent-png)（raw photo を持っているとき）→ ② 濃度 boost = [`signature-image-overlay-density`](office-automation.md#signature-image-overlay-density)（alpha boost + 純黒、helper = `pdf_form_fill.boost_signature_alpha`）→ ③ anchor（「氏名：」等）右への配置 = [`pdf-prefill-direct`](office-automation.md#pdf-prefill-direct) + baseline 注意 [`pymupdf-insert-text-baseline`](office-automation.md#pymupdf-insert-text-baseline)。⚠️ `search_for("氏名：")` は CJK 互換字形で空振りリスクあり、 空振り時は [`pdf-text-match-nfkc`](office-automation.md#pdf-text-match-nfkc)（`get_text("words")` + NFKC 照合）に降りる。
5. ファイル名規定にリネーム → 提出。

案件固有のソース・具体値（記入スクリプト・記入済 docx・どの署名がどの様式か）は応募管理リポの `src/BUILD.md` 側に置き本節を参照する（＝組み立て順序の SoT は本節、技法の SoT は office-automation.md、案件値は各リポ）。
