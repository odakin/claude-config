# 音源からの採譜

音源の取得・デコードは [web-tools.md#youtube-audio-extraction](web-tools.md#youtube-audio-extraction)、
会話の文字起こしは [audio-transcription.md](audio-transcription.md) を参照。
ここは音楽を音符・リズム・運指へ起こす工程を扱う。

## <a id="evidence-stages"></a>工程と確度

音高検出、音響照合、聴覚照合を別の工程として記録する。
機械採譜のファイルが生成されたこと、内部データが一致すること、原演奏に合うことは別の検証結果である。
聴いて全音を照合していない版は、その範囲を初稿の説明に残す。

最初に音源の長さ・チャンネル・サンプルレート・無音区間・ハッシュを確認する。
チューニングやカポが音符とTABに影響する場合は確認し、不明なら推定として記録する。
原音と解析用のデコード音声は区別して保持する。

## <a id="pitch-and-attacks"></a>音高と発音

- **倍音と独立した音**: 上の音を検出しても、低い音の倍音かもしれない。基音付近の成分、発音時刻、前後のフレーズ、楽器で実現できる同時発音を照合する。
- **余韻と再発音**: 前の音の減衰が途中で分断され、新しいノートになる場合がある。発音前後の基音帯域の増減や立ち上がりを調べる。別の音の発音に伴うスペクトル変化だけで再発音としない。
- **反復との比較**: 同じ位置の別の演奏は弱音の候補を絞る手がかりになるが、演奏上の変化や弾き損じもあり得る。反復に合わせた補いは検出音と区別し、根拠を残す。
- **測定値の意味**: モデルの振幅・信頼度、スペクトルの比、音の正誤は同じ量ではない。閾値を正答率として説明しない。

使用したモデルとライブラリの版、周波数範囲、発音・持続時間の閾値、スペクトルの窓と帯域を案件側に残す。
初回の出力も控えとして残すと、後の修正と再推論による差を区別できる。

## <a id="meter-and-fingering"></a>拍節と運指

最小パルスと拍子を分ける。等間隔の発音を捉えても、それが八分音符か十六分音符か、
どこが小節頭かは別の判断である。自動テンポの値だけで決めず、旋律・伴奏・アクセント・反復の区切りを照合する。
拍節が未確定なら小節線とテンポの仮置きを明示し、原音上の時刻を付けて再検討しやすくする。

TABの運指案では、弦・フレットと実音の一致、同じ弦の重複、押弦の幅、前後の移動を検査する。
弾ける運指が得られても、それが演奏者の運指だとは確定しない。
同音を複数の弦で鳴らす場合や、移動で前の音が止まる場合は、単なる音高集合では復元できない。

## <a id="data-and-regeneration"></a>音符の正本と再生成

音符の正本は一つにし、本編・自由拍の冒頭・終止の付記もそこへ収める。
譜面用の整理した持続時間と原音に合わせた再生用の発音時刻を別々に持つ場合は、両者の役割をデータで示す。
生成スクリプト内に別の音符列を埋め込むと、編集用データを直しても一部の譜面や再生音だけ更新されなくなる。

初回計測の控え、再計測の候補、編集する音符の正本、生成物を区別する。
再抽出は候補へ書き、採用済みの手修正を自動で上書きしない。
MusicXMLを外部アプリで編集した場合は、変更を正本へ戻してからPDF・MIDIを作り直す。
再生成の手順と依存は案件のnoteかscriptの冒頭へ置き、READMEはその入口にする。

## <a id="lilypond-notes"></a>LilyPondで確認する点

- 単音の音価は弦指定より前に書く。例: `a'8\1`。順序を逆にして数字が連なると弦番号として読まれる。
- 版ごとのフォントAPIを確認する。2.26系の `\paper` では `fonts.serif`・`fonts.sans`・`fonts.typewriter` を使える。別の版の `set-global-fonts` の例をそのまま持ち込まない。日本語のフォントは実際に使えるものを選ぶ。
- TABの改段直後に出る括弧は、前段からタイで続く音を表す場合がある。推定音にも括弧を使う場合は、五線譜とTABで意味が重なることを凡例へ書く。

構文は使用中の版のマニュアル・同梱サンプル・定義で確かめる。

## <a id="validation"></a>照合と保存

1. **音響**: 基音・発音・音域・無音を原音から確かめる。弱音や多声部分は別に見る。
2. **データ**: 音符データとMusicXMLの音高・小節長、TABの実音、MIDIの音高・発音時刻を読み戻して照合する。
3. **表示**: PDFを画像化して全ページの日本語・五線譜・TAB・改段と改ページを確認する。
4. **聴覚**: 原音と譜面からの再生音を比較する。再生音の楽器音色は原録音と区別し、どこまで聴いて照合したかを報告する。

内部整備だけの変更では、生成された譜面ソース・編集データ・MIDI等が変更前と同じかも検査する。
音源の扱いとGit管理の範囲は保存先の約束に従い、初回計測・再生成に要るscriptは一時フォルダだけに残さない。
譜面の生成物の扱いは [repo-history-growth.md#generated-binaries](repo-history-growth.md#generated-binaries) を参照。
