# チャットでの数式の書き方

返事の数式がどう見えるかは、 **返事を読む画面** で決まる。 同じ書き方が、 ある画面では描かれ、 別の画面では生の TeX のまま出る。 書く前に、 読む画面を決める。

## <a id="by-surface"></a>画面ごとの書き方

**既定 = Codex app または Claude desktop の Code タブで読む返事では、文中・独立式とも LaTeX で組版表示する。** 読むための数式と、ソースの書き方を説明・転記するための code 表示を分ける。区切りと制約は画面別の節を適用し、別アプリの制限を流用しない。Unicode で書くのは、数式を描かない画面と、読む画面が分からないとき:

| 画面 | 数式の描画 | 書き方 |
|---|---|---|
| Codex app の会話本文 | 文中・複数行の独立式を描く | **LaTeX** を [#codex-app-katex](#codex-app-katex) の規則で (既定) |
| Claude desktop app の Code タブ | KaTeX で描く | **LaTeX** を [#code-tab-katex](#code-tab-katex) の規則で (既定) |
| Claude Code CLI (ターミナル) | 描かない | `_` / `^` + Unicode (σ ∂ ℏ ∫ など) |
| headless (`claude -p`・定期実行の出力) | 読む画面が別 (log・通知) | Unicode |
| Remote Control (スマホなどで読む) | 未測定 | Unicode (測ったら本表を直す) |
| 画面が決まらない (複数の画面で読まれる・どれか分からない) | — | Unicode (どの画面でも崩れない) |
| コピペして `.tex` に貼る LaTeX 片 | (読ませない) | code block = [latex.md#latex-in-chat-codeblock](latex.md#latex-in-chat-codeblock) |

Claude の Code タブかどうかは、system prompt の記述か、環境変数 `CLAUDE_CODE_ENTRYPOINT` (= `claude-desktop`) で分かる。Codex app はそのアプリの文脈か本人の確認で特定し、Claude の環境変数では判定しない。Remote Control のように同じ session でも読む画面が変わることがある。画面が分からなければ Unicode。

## <a id="codex-app-katex"></a>Codex app で LaTeX を書くときの規則

**読ませる数式は、文中も独立式も会話本文で組版する。** 画像化・PDF 化・Unicode への置き換えを既定にしない。

- 文中は `\( … \)`、独立式は別行の `\[` と `\]` で囲む。複数行はその内側に `\begin{aligned} … \\ … \end{aligned}` を置く。
- 読ませる数式を backtick や通常の code block に入れない。区切りやソースを説明するときは code 表示にし、**それを数式表示の試験と数えない**。転記用のソースを求められたら [latex.md#latex-in-chat-codeblock](latex.md#latex-in-chat-codeblock) に従う。
- リポジトリのプリアンブルに依存する独自マクロは、標準の数式コマンドへ展開して示す。
- 表示が崩れたら、同じ画面で短い式を、通常の本文として出し直す。文中と独立式、元テキストの改行、区切りを一つずつ変えて照合する。アプリ内に描画の code があることだけで実画面での成功を断定せず、一度の失敗だけで非対応と断定しない。
- Claude の Code タブの `\[…\]` 非対応・inline gate・Stop hook は次節の専用規則であり、Codex app の判定には使わない。

表示の確認範囲 (macOS、アプリ版 `26.1029.61003`): 文中の不等式・分数・根号・添字を含む式と、同じ二行のガウス積分を次の形で出したものが画面で組版された。確認はこの画面と例の範囲であり、全アプリ版・全 LaTeX コマンドへの保証ではない。

| 独立式の形 | 確認した表示 |
|---|---|
| 別行の `\[ … \]` 内に、改行した `aligned` | 二行の組版 |
| `\[\begin{aligned} … \end{aligned}\]` を元テキストでは一行に置く | 二行の組版 |
| 別行の `$$ … $$` 内に `aligned` | 二行の組版 |
| `math` 指定の fenced block 内に `aligned` | 二行の組版 (通常のソース表示用 code block と区別する) |

最初の表示失敗の原因は未特定で、同じ形での再試行は表示された。画像による回避を標準手順にせず、上の本文表示を使う。

表示の再試験用の入力 = [Codex app の数式見本](../docs/examples/codex-chat-math.md)。文中の式と上の四形式を、**会話の返事として**出して比べる。ファイルのプレビューや、ソースを説明する backtick の表示を会話本文の試験と取り違えない。

アプリ内の描画処理を補助的に読むなら、既存の [claude-app-bundle.py](../scripts/claude-app-bundle.py) の `--app` と `--where asar` を使う (読み取り専用)。Codex の renderer は確認した版では `app.asar` 内の `webview/assets/` に入っている。アプリの場所を確かめてから、例えば次の形で検索する:

```bash
python3 scripts/claude-app-bundle.py --app /Applications/ChatGPT.app grep 'renderMath' --where asar --context 80 --per-file 1 --max 3
```

同じ `--app` で `asar-ls` と `slice --where asar` も使える。`renderer`・`i18n`・`engine` の既定の探索や `version` の engine 欄は Claude 向けなので、Codex の情報と見なさない。読んだ処理が実際の返事で使われるかは、上の画面の試験で確かめる。asar を読む使い捨ての code を繰り返し作らず、この道具を再利用する。

## <a id="code-tab-katex"></a>Claude の Code タブで LaTeX を書くときの規則

<a id="code-tab-default-form"></a>**既定の書き方 (3 行)** — 書くときはこの形を使う。 下の関門のどれにも当たらない形で、 描かれ方は標準の LaTeX と同じ:

1. `\` を含む式は、 直前に半角空白を置いた ` \( … \)` で書く (`$…$` の 60 文字の制限が無い。 中身 200 文字まで、 1 行に収める)。
2. 添字と上付きは必ず `{}` で包む (`E_{I}`、 `m_{I}^{2}`)。 1 文字の添字 `E_I` は、 `$…$` でも `\(…\)` でも記号の無い式と見なされて落ちる。
3. `\` を含まない式は `$…$` で短く (英字 1 文字・`$E_{I}$`・`$x-y$`)。 数・金額・区間 (`30`・`0.35`・`[0,1]`) は数式にせず地の文で書く。 文字の並んだ積は `x\,y`・`\mathrm{d}x` と書いて 1. の形にする。

実測: 過去の返事で崩れた式をこの 3 行で機械的に書き換えると、 数式として書いた式はすべて描ける形になった。 添字に `{}` を付けるだけでは、 長くなった `$…$` が 60 文字を越えて、 落ちる式がかえって増えた = 1 と 2 は組で使う。 関門の細目 (下の箇条) は、 この 3 行から外れる式を書くときと、 生で出た式の原因を読むときに使う。

実測 (Code タブでの画面の試験と、 アプリ本体 2.26454.2・2.31226.0・2.31226.1 の描画器の code の照合):

- 区切りは `$…$` (インライン)・`$$…$$` (ディスプレイ)・`\(…\)` (インライン) だけ。 **`\[…\]` は描かれず生のまま出る**。 生で出た文字列はそのまま Markdown に渡るので、 `_{…}` の `_` が強調に取られて添字まで消える。
- 開きの `$` の直後と閉じの `$` の直前に空白を置かない (`$ x $` は生表示)。 インライン数式は 1 行に収める (行をまたぐと生表示)。
- **`\(` の直前には半角空白を 1 つ置く**。 本体の `\(` 用 guard は、 `\(` の直前の文字 (`*` `_` `~` は飛ばして見る) が **半角空白・タブ・改行・`(`・`[` か文頭** のときだけ数式の開始にする。 日本語の文字・読点・句点・「 ・〜 の直後に `\(` を置くと数式にならず、 `\(` と `\)` のバックスラッシュだけが Markdown のエスケープとして消え、 `_` は強調に取られて `(x{2},\dots,x{N})` のような生の文字列が出る。 「…なので、\(x\) は」 でなく 「…なので、 \(x\) は」 と書く。
- **`\(…\)` の中身にも guard がある** (`\(` 用 inline guard、 画面の実測と一致)。 外れると直前の規則と同じ形で生表示になる:
  - **中身に `\ ^ { } = < > | ! +` のどれか、 または `x_1` 形 (英字 `_` 数字) の添字が要る**。 **`\(K\)` `\(K(t)\)` `\(t\)` `\((N-1)\)` `\([0,1]\)` `\(K_E\)` `\(C_t\)` は生表示** → 1 文字は `$K$`、 `K(t)` `[0,1]` のような記号の無い式は地の文の文字で書く、 添字は `\(K_{E}\)` と `{}` を付ける。
  - **空白か文頭の直後の `-x` / `--x` (CLI の flag の形) を含む中身は、 `\英字` か `^` も含まないと落ちる** (実測: `\(-i\,d/dx\)` が生表示になった真因はこれで、 `\,` ではない。 空白の後の `\( a\,\mathrm d^{N}x \)` は描かれた)。 `\( {-}i\,\mathrm d/\mathrm dx \)` のように書く。
  - 中身に `$`・backtick・`\(`・`\|` `\.` `\+` `\*` `\?` `\数字` を入れない (ノルムは `\lVert v\rVert`)。 `\,` `\;` `\!` は通る。 中身は 200 文字以内、 `\)` は同じ行に置く。
  - `$…$` の gate にある 60 文字制限・英字 4 連続・括弧の釣り合いの判定は `\(…\)` には無い。
- **`$…$` には「数式らしさ」 の gate がある** ([#dollar-inline-gate](#dollar-inline-gate))。 60 文字を超える・数式記号を含まない (`$[0,1]$` `$xy$` `$P_D$`)・英字 4 文字以上が裸で続く、 などで生表示になる。 **落ちた `$` の閉じは次の式の開きになる** (本体は `$` を 1 文字進めるだけ) ので、 1 箇所の失敗が後続の `$…$` を道連れにする。 使い分け = [既定の書き方の 3 行](#code-tab-default-form) (`\` を含む式は直前に空白の `\(…\)`、 添字は `{}`、 `\` の無い短い式は `$…$`、 記号の無い式と数は地の文)。 `$$…$$` にはどちらの gate も無い。
- **数式を含む返事は Stop hook が機械で検査する** = [`hooks/chat-math-render-guard.py`](../hooks/chat-math-render-guard.py) (desktop の session の最終発話を本体と同じ判定式で走査し、 落ちる式を行番号・理由・直した形つきで block → 崩れた式だけを直した形で並べる短い追記を書く。 返事の全文は出し直さない = [hook-authoring.md#stop-hook-addendum-not-reemission](hook-authoring.md#stop-hook-addendum-not-reemission)。 金額・shell の変数・地の文の `$$` のような数式でない `$` は止めない。 他の hook の差し戻しの後に書いた返事も判定し、 自分が差し戻した後の返事では止めずに数だけ残す)。 規則を知っているだけでは防げない (実測: 規則を確定した後も、 読点の直後の `\(` と記号の無い `\(g\)` で 1 つの返事の大半の式が生表示になった)。 書くときは上の 3 行の形で書き、 細目の自己点検には頼らず hook に任せる。 Stop は返事が画面に出た後に走るので、 崩れた版は画面に残る = 表示の前に直す hook ([#code-tab-display-fix](#code-tab-display-fix)) と組で使う。 下書きを file にして `python3 hooks/chat-math-render-guard.py --check FILE` で先に見てもよい。 hook が写していないもの = `$$` block の判定 (見ない。 `\\0` を含む 1 行の pmatrix が描かれたので止めない)。 LaTeX を使わずに Unicode の地の文で書いた式も見ない (描けない形ではない) = Code タブで LaTeX に替えさせるのは、 CLAUDE.md・雛形に書く既定の語 ([#where-to-put-the-rule](#where-to-put-the-rule))。 共有 repo の project の hook として写して配る形 = [shared-repo.md#project-copy-of-user-hook](shared-repo.md#project-copy-of-user-hook)。
- 表のセルに `|` や `\|` を含む数式を書かない (`$\langle\psi|\phi\rangle$` はセルの区切りに取られる)。 `\mid` / `\vert` / `\lVert` で代えるか、 表の外に出す。
- コマンドは KaTeX にあるものだけ。 **physics パッケージは不可** (`\dd` `\dv` `\pdv` `\abs` `\norm` `\ev` `\mel` `\comm` `\tr` `\Tr`) → `\mathrm{d}x`, `\frac{\partial f}{\partial x}`, `|x|`, `\lVert v\rVert`, `\langle A\rangle`, `\operatorname{Tr}` で書く (`\|v\|` は `$…$` の gate が正規表現と見なして生表示にする)。 `\mathbb{1}` `\mathds{1}` `\id` も不可 (→ `\mathbb{I}` か `\mathbf{1}`)。 repo のプリアンブル固有のマクロも不可。
- 使えるもの (実測): `\ket` `\bra` `\braket` `\mathscr` `\mathfrak` `\bm` `\boldsymbol` `\operatorname` `\dfrac` `\tfrac` `\lVert` `\coloneqq` `\hbar` `\bmod`。
- 数式を code block や backtick の中に入れない (描かれない)。 `$$` の block の内側に空行を置かない。
- 長い導出はチャットに書かず、 `.md` ファイルや Artifact に出す。

**未知のコマンド 1 つで式全体が生になる理由**: 描画器は KaTeX をエラーを投げない設定で呼び、 エラーの色を地の文と同じにしている。 KaTeX は解釈できない式を丸ごと元の文字列として出すので、 式全体が普通の文字で出る (赤字にならないので、 壊れたと気づきにくい)。

### <a id="dollar-inline-gate"></a>`$…$` の中身の gate (描画器が KaTeX に渡す前の判定)

描画器は `$…$` の span を KaTeX に渡す前に「数式か、 通貨・散文・code か」 を判定し、 外れた span は普通の文字のまま出す (未知コマンドと同じく赤字にならない)。 以下は本体 2.31226.0 の描画 chunk (`$` span の inline guard) を読んで画面の試験と突き合わせ、 2.31226.1 の code でも同じと確かめたもの。 `$$…$$` はこの gate を通らない (実測: 84 文字で描画)。 `\(…\)` はこの gate を通らないが別の guard がある (上の節): 長さ・散文の判定は無く (実測: 71 文字で描画)、 数式記号は要る (2.31226.0 の画面では `\([0,1]\)` も描かれたが、 2.31226.1 の本体は記号の無い中身を落とす)。

- **中身は 60 文字以内**。 61 文字以上は生表示 (実測: 54 文字は描画、 67〜71 文字は生表示)。
- **中身の形が次のどれかであること**: (a) 英字 1 文字 (`$t$`) / (b) 数と四則演算だけの式で先頭が数字でないもの (`$-1$` `$x-y$` `$(0,1)$` `$f(0,1)$`) / (c) `\ ^ { } = < > | ! +` のどれかを含むもの、 または `x_1` `x_i` `x_D` `T_1` `T_d` `T_{…}` 形の添字を含むもの。 どれにも当たらないと生表示: `$[0,1]$` `$[a,b]$` `$a,b$` `$xy$` `$dx$` `$2x$` `$(a+b)c$` **`$P_D$` `$T_D$`** (大文字 `_` 大文字は添字と見なされない)。 → `[0,1]` は地の文のまま、 `$x\,y$`、 `$2\,x$`、 `$c(a+b)$`、 `$P_{D}$` のように書く。
- **散文に見えると生表示**: コマンド名と `{…}` の外に英字が 4 文字以上続く (`$\hat T+abcd$`)、 日本語が 2 文字以上、 `\%` でない `%`。 語は `\text{…}` / `\mathrm{…}` の中に入れる。
- **先頭・末尾**: 先頭が `{` は不可。 先頭が `(` なら (b) の形か `\コマンド` / `^` を含むこと。 末尾が演算子 (`+` `-` `*` `=` `<` `>` `/` `^` `_`)・開き括弧・`,` `:` `;` `\` は不可 (`$x+$`)。 先頭・末尾の空白は不可。
- **中身に入れられないもの**: `$`・backtick・`\(`。 `\|` `\.` `\+` `\*` `\?` `\数字` (正規表現に見える) → ノルムは `\lVert v\rVert` か `\Vert v\Vert`。 Markdown の強調の記号 (アスタリスク 2 連・下線 2 連・チルダ 2 連)・`](`・HTML タグ風 (`<b>` のように `<` 英字 `>`)。 `=~` `!~` `&&` `@` `#` (`\#` も) `"` `\\\\`、 行頭・空白・`(` `=` `,` の直後の `'`、 空白・引用符・`(` `/` `[` `=` `,` `;` の直後で `{` が続かない `^`、 空白や `(` の直後の `!` で終わるもの。
- **括弧の釣り合い**: `( ) [ ] { }` が釣り合わないと不可。 `|` が奇数個で末尾が `|` のときも不可 (`$\langle\psi|$`)。
- **開き `$` の直後が数字** なら通貨の形と見なし、 (c) の数式記号が無いと生表示 (`$2x$` は生、 `$2^n$` `$2+x$` は描画される)。 表計算の cell 参照の形 (`$A$1`) も数式と見なさない。
- **閉じ `$` の直後が数字** は不可 (通貨の形)。 `(` は code 上は通るはずだが、 同じ行に後続の `$…$` があると生表示になった (実測 3 回、 原因は未特定)。 空白を入れるか `\(…\)` にする。

**版で変わる**: 上は 2.26454.2 (macOS)・2.31226.0 (Windows)・2.31226.1 (macOS) での挙動 (`\(` の guard は 2.31226.1 の code から。 読んだ chunk 名と関数名は hook の header に記録)。 描画器はアプリの中でも画面ごとに設定が違う (ドル記号 1 個の数式を切っている描画器もある)。 規則が合わなくなったら、 [claude-app-bundle-reading.md](claude-app-bundle-reading.md) の手順で本体を読み直すか、 画面で 1 回試す。 gate の判定は `inlineGuard` を持つ chunk にあり、 `It=60` (文字数)・`\p{L}{4}` (散文)・`[\\^{}=<>|!+]` (数式記号) で引ける。 規則を変えたら hook の判定式も同じ版の code に合わせ直す (hook の test が規則の例を持つ)。

### <a id="code-tab-display-fix"></a>表示の前に直す hook (MessageDisplay)

Stop の検査は返事が画面に出た後に走るので、 崩れた版は画面に残り、 追記と並ぶ。 Claude Code の hook の種類 `MessageDisplay` は返事の文を画面に出す前に呼ばれ、 hook が返した `displayContent` を元の文の代わりに出す (公式の hooks の説明)。 [`hooks/chat-math-display-fix.py`](../hooks/chat-math-display-fix.py) はこれを使い、 上の判定式で落ちる式だけを意味を変えずに描ける形へ書き換える (区切りの付け替え・1 文字の添字の `{}`・`\(` の前の空白・表のセルの `|` → `\vert`・`\[…\]` → `$$…$$`・数だけの式 → 地の文)。 直した行が同じ判定式を通るときだけ差し替え、 直せない式と数式でない `$` は触らない。 書き換えの部品は Stop の hook の `fix_text` (Stop の「直した形」 の案内も同じ部品)。

- **表示だけ**: 会話記録と Claude が読む文は元のまま。 Claude 自身は崩れた形を書き続けるので、 書き方の既定 ([#code-tab-default-form](#code-tab-default-form)) は残す。 Stop の検査は、 この hook が同じ session で走った印 (`$TMPDIR/chat-math-display-fix/<session>`) があれば、 画面に出た直した文で判定する (表示で直った式では止めない)。
- **desktop では書き終えた後に 1 回**: desktop は engine を SDK の形 (`--output-format stream-json --include-partial-messages`) で動かすので、 hook は返事 1 つにつき書き終えた後に全文で 1 回呼ばれ、 差し替えた文が書き終えた返事として desktop に届く。 書いている途中の小分けの文は元のまま届く (実測 = 埋込 engine 2.1.317 を同じ flag で動かした出力)。 画面の試験 (desktop app 4.23118.0・埋込 engine 2.1.317、 project の設定だけに目印の語と式を差し替える hook を置いた folder): 書き終えた返事は差し替えた文で描かれ (目印の語・式 3 つとも)、 session を離れて戻っても差し替えた文のまま。 書いている途中に元の文が一瞬見えるかは画面では確かめていない (engine の出力では途中の小分けの文は元のまま)。 app を再起動した後は未確認。 session の turn の終わりに起こした側の session へ届く報告の文も差し替えた文だった = 表示の hook の書き換えは、 本人の画面だけでなく別の session へ渡る報告にも乗る (会話記録は元のまま)。
- この hook は desktop の entrypoint (`claude-desktop` / `claude-desktop-3p`) でしか動かない (CLI のターミナルは数式を描かない)。 対話の端末では行のまとまりごとに呼ばれるので、 code block の開閉を返事の id ごとの一時 file で引き継ぐ。
- 試験は、 project の `.claude/settings.json` だけに hook を置いた folder で session を開けば、 本人の全体の設定を触らずにできる。 SDK の形の出力は、 埋込 engine を同じ flag と `--setting-sources project` で `-p` 実行すれば、 本人の hook を読まずに確かめられる。
- 計器 = `~/.claude/state/chat-math-events.jsonl` (表示で直した式・差し戻し・差し戻しの後に残った式の数)。 効いたかは差し戻しの回数の前後で比べる。 校正 = `python3 hooks/chat-math-render-guard.py --calibrate <日数>` (全ての設定フォルダ `~/.claude*/projects` の、 画面に出た全ての版 = 差し戻された版も含めて数える)。

## <a id="where-to-put-the-rule"></a>規則をどこに置くか

規則の本文 (区切り・gate・使えるコマンド) は本 doc だけに置く (同じ本文を複数の file に写すと、片方だけ直る)。CLAUDE.md と template には、読む契機と、[画面ごとの既定](#by-surface) の要点 (どの画面で読む返事を LaTeX で組み、どの画面で Unicode にするか) と、Code タブの [既定の書き方の 3 行](#code-tab-default-form) と、本 doc への参照を書く (関門の細目は書かない)。要点が無いと、本 doc を開かない session は既定を知らないまま書く。入口だけを持つ file (repo の薄い AGENTS.md、Codex の kernel [`codex/HOME-AGENTS.md`](../codex/HOME-AGENTS.md)) には、読む契機と本 doc への参照を書く。個人層が [画面別の既定](#by-surface) と違う書き方を決めるときは、違える理由と範囲を個人層の規則に書き、どの画面が何を描くかの事実は本 doc に合わせる。
