# チャットでの数式の書き方

返事の数式がどう見えるかは、 **返事を読む画面** で決まる。 同じ書き方が、 ある画面では描かれ、 別の画面では生の TeX のまま出る。 書く前に、 読む画面を決める。

## <a id="by-surface"></a>画面ごとの書き方

| 画面 | 数式の描画 | 書き方 |
|---|---|---|
| Claude desktop app の Code タブ | KaTeX で描く | LaTeX を [#code-tab-katex](#code-tab-katex) の規則で |
| Claude Code CLI (ターミナル) | 描かない | `_` / `^` + Unicode (σ ∂ ℏ ∫ など) |
| 画面が決まらない (複数の画面で読まれる・どれか分からない) | — | Unicode (どの画面でも崩れない) |
| コピペして `.tex` に貼る LaTeX 片 | (読ませない) | code block = [latex.md#latex-in-chat-codeblock](latex.md#latex-in-chat-codeblock) |

Code タブかどうかは、 system prompt の記述 (Claude desktop app の Code tab で動いている旨) か、 環境変数 `CLAUDE_CODE_ENTRYPOINT` (= `claude-desktop`) で分かる。 Remote Control でスマホから読む session のように、 同じ session でも読む画面が変わることがある。 迷ったら Unicode。

## <a id="code-tab-katex"></a>Code タブで LaTeX を書くときの規則

実測 (Code タブでの画面の試験と、 アプリ本体 2.26454.2・2.31226.0・2.31226.1 の描画器の code の照合):

- 区切りは `$…$` (インライン)・`$$…$$` (ディスプレイ)・`\(…\)` (インライン) だけ。 **`\[…\]` は描かれず生のまま出る**。 生で出た文字列はそのまま Markdown に渡るので、 `_{…}` の `_` が強調に取られて添字まで消える。
- 開きの `$` の直後と閉じの `$` の直前に空白を置かない (`$ x $` は生表示)。 インライン数式は 1 行に収める (行をまたぐと生表示)。
- **`\(` の直前には半角空白を 1 つ置く**。 本体の `\(` 用 guard は、 `\(` の直前の文字 (`*` `_` `~` は飛ばして見る) が **半角空白・タブ・改行・`(`・`[` か文頭** のときだけ数式の開始にする。 日本語の文字・読点・句点・「 ・〜 の直後に `\(` を置くと数式にならず、 `\(` と `\)` のバックスラッシュだけが Markdown のエスケープとして消え、 `_` は強調に取られて `(x{2},\dots,x{N})` のような生の文字列が出る。 「…なので、\(x\) は」 でなく 「…なので、 \(x\) は」 と書く。
- **`\(…\)` の中身にも guard がある** (`\(` 用 inline guard、 画面の実測と一致)。 外れると直前の規則と同じ形で生表示になる:
  - **中身に `\ ^ { } = < > | ! +` のどれか、 または `x_1` 形 (英字 `_` 数字) の添字が要る**。 **`\(K\)` `\(K(t)\)` `\(t\)` `\((N-1)\)` `\([0,1]\)` `\(K_E\)` `\(C_t\)` は生表示** → 1 文字は `$K$`、 `K(t)` `[0,1]` のような記号の無い式は地の文の文字で書く、 添字は `\(K_{E}\)` と `{}` を付ける。
  - **空白か文頭の直後の `-x` / `--x` (CLI の flag の形) を含む中身は、 `\英字` か `^` も含まないと落ちる** (実測: `\(-i\,d/dx\)` が生表示になった真因はこれで、 `\,` ではない。 空白の後の `\( a\,\mathrm d^{N}x \)` は描かれた)。 `\( {-}i\,\mathrm d/\mathrm dx \)` のように書く。
  - 中身に `$`・backtick・`\(`・`\|` `\.` `\+` `\*` `\?` `\数字` を入れない (ノルムは `\lVert v\rVert`)。 `\,` `\;` `\!` は通る。 中身は 200 文字以内、 `\)` は同じ行に置く。
  - `$…$` の gate にある 60 文字制限・英字 4 連続・括弧の釣り合いの判定は `\(…\)` には無い。
- **`$…$` には「数式らしさ」 の gate がある** ([#dollar-inline-gate](#dollar-inline-gate))。 60 文字を超える・数式記号を含まない (`$[0,1]$` `$xy$` `$P_D$`)・英字 4 文字以上が裸で続く、 などで生表示になる。 **落ちた `$` の閉じは次の式の開きになる** (本体は `$` を 1 文字進めるだけ) ので、 1 箇所の失敗が後続の `$…$` を道連れにする。 使い分け = 1 文字と短く単純な式は `$…$`、 長い式・散文の混じる式で数式記号を含むものは `\(…\)` (直前に空白)、 記号の無い式は地の文、 `$$…$$` にはどちらの gate も無い。
- **数式を含む返事は Stop hook が機械で検査する** = [`hooks/chat-math-render-guard.py`](../hooks/chat-math-render-guard.py) (desktop の session の最終発話を本体と同じ判定式で走査し、 落ちる式を行番号・理由・直し方つきで block → 直して出し直す)。 規則を知っているだけでは防げない (実測: 規則を確定した後も、 読点の直後の `\(` と記号の無い `\(g\)` で 1 つの返事の大半の式が生表示になった)。 自己点検に頼らず hook に任せる。 下書きを file にして `python3 hooks/chat-math-render-guard.py --check FILE` で先に見てもよい。 hook が写していないもの = `$$` block の判定 (見ない。 `\\0` を含む 1 行の pmatrix が描かれたので止めない)。
- 表のセルに `|` や `\|` を含む数式を書かない (`$\langle\psi|\phi\rangle$` はセルの区切りに取られる)。 `\mid` / `\vert` / `\lVert` で代えるか、 表の外に出す。
- コマンドは KaTeX にあるものだけ。 **physics パッケージは不可** (`\dd` `\dv` `\pdv` `\abs` `\norm` `\ev` `\mel` `\comm` `\tr` `\Tr`) → `\mathrm{d}x`, `\frac{\partial f}{\partial x}`, `|x|`, `\lVert v\rVert`, `\langle A\rangle`, `\operatorname{Tr}` で書く (`\|v\|` は `$…$` の gate が正規表現と見なして生表示にする)。 `\mathbb{1}` `\mathds{1}` `\id` も不可 (→ `\mathbb{I}` か `\mathbf{1}`)。 repo のプリアンブル固有のマクロも不可。
- 使えるもの (実測): `\ket` `\bra` `\braket` `\mathscr` `\mathfrak` `\bm` `\boldsymbol` `\operatorname` `\dfrac` `\tfrac` `\lVert` `\coloneqq` `\hbar` `\bmod`。
- 数式を code block や backtick の中に入れない (描かれない)。 `$$` の block の内側に空行を置かない。
- 長い導出はチャットに書かず、 `.md` ファイルや Artifact に出す。

**未知のコマンド 1 つで式全体が生になる理由**: 描画器は KaTeX をエラーを投げない設定で呼び、 エラーの色を地の文と同じにしている。 KaTeX は解釈できない式を丸ごと元の文字列として出すので、 式全体が普通の文字で出る (赤字にならないので、 壊れたと気づきにくい)。

### <a id="dollar-inline-gate"></a>`$…$` の中身の gate (描画器が KaTeX に渡す前の判定)

描画器は `$…$` の span を KaTeX に渡す前に「数式か、 通貨・散文・code か」 を判定し、 外れた span は普通の文字のまま出す (未知コマンドと同じく赤字にならない)。 以下は本体 2.31226.0 の描画 chunk (`$` span の inline guard) を読んで画面の試験と突き合わせ、 2.31226.1 の code でも同じと確かめたもの。 `$$…$$` はこの gate を通らない (実測: 84 文字で描画)。 `\(…\)` はこの gate を通らないが別の guard がある (上の節): 長さ・散文の判定は無く (実測: 71 文字で描画)、 数式記号は要る (2.31226.0 の画面では `\([0,1]\)` も描かれたが、 2.31226.1 の本体は記号の無い中身を落とす)。

- **中身は 60 文字以内**。 61 文字以上は生表示 (実測: 54 文字は描画、 67〜71 文字は生表示)。
- **中身の形が次のどれかであること**: (a) 英字 1 文字 (`$t$`) / (b) 数と四則演算だけの式で先頭が数字でないもの (`$-1$` `$x-y$` `$(0,1)$` `$f(0,1)$`) / (c) `\ ^ { } = < > | ! +` のどれかを含むもの、 または `x_1` `x_i` `x_D` `T_1` `T_d` `T_{…}` 形の添字を含むもの。 どれにも当たらないと生表示: `$[0,1]$` `$[a,b]$` `$a,b$` `$xy$` `$dx$` `$2x$` `$(a+b)c$` **`$P_D$` `$T_D$`** (大文字 `_` 大文字は添字と見なされない)。 → `[0,1]` は地の文のまま、 `$x\,y$`、 `$2\,x$`、 `$c(a+b)$`、 `$P_{D}$` のように書く。
- **散文に見えると生表示**: コマンド名と `{…}` の外に英字が 4 文字以上続く (`$\hat T+abcd$`)、 日本語が 2 文字以上、 `\%` でない `%`。 語は `\text{…}` / `\mathrm{…}` の中に入れる。
- **先頭・末尾**: 先頭が `{` は不可。 先頭が `(` なら (b) の形か `\コマンド` / `^` を含むこと。 末尾が演算子 (`+` `-` `*` `=` `<` `>` `/` `^` `_`)・開き括弧・`,` `:` `;` `\` は不可 (`$x+$`)。 先頭・末尾の空白は不可。
- **中身に入れられないもの**: `$`・backtick・`\(`。 `\|` `\.` `\+` `\*` `\?` `\数字` (正規表現に見える) → ノルムは `\lVert v\rVert` か `\Vert v\Vert`。 Markdown の強調の記号 (アスタリスク 2 連・下線 2 連・チルダ 2 連)・`](`・HTML タグ風 (`<b>` のように `<` 英字 `>`)。 `=~` `!~` `&&` `@` `#` (`\#` も) `"` `\\\\`、 行頭・空白・`(` `=` `,` の直後の `'`、 空白・引用符・`(` `/` `[` `=` `,` `;` の直後で `{` が続かない `^`、 空白や `(` の直後の `!` で終わるもの。
- **括弧の釣り合い**: `( ) [ ] { }` が釣り合わないと不可。 `|` が奇数個で末尾が `|` のときも不可 (`$\langle\psi|$`)。
- **開き `$` の直後が数字** なら通貨の形と見なし、 (c) の数式記号が無いと生表示 (`$2x$` は生、 `$2^n$` `$2+x$` は描画される)。 表計算の cell 参照の形 (`$A$1`) も数式と見なさない。
- **閉じ `$` の直後が数字** は不可 (通貨の形)。 `(` は code 上は通るはずだが、 同じ行に後続の `$…$` があると生表示になった (実測 3 回、 原因は未特定)。 空白を入れるか `\(…\)` にする。

**版で変わる**: 上は 2.26454.2 (macOS)・2.31226.0 (Windows)・2.31226.1 (macOS) での挙動 (`\(` の guard は 2.31226.1 の code から。 読んだ chunk 名と関数名は hook の header に記録)。 描画器はアプリの中でも画面ごとに設定が違う (ドル記号 1 個の数式を切っている描画器もある)。 規則が合わなくなったら、 [claude-app-bundle-reading.md](claude-app-bundle-reading.md) の手順で本体を読み直すか、 画面で 1 回試す。 gate の判定は `inlineGuard` を持つ chunk にあり、 `It=60` (文字数)・`\p{L}{4}` (散文)・`[\\^{}=<>|!+]` (数式記号) で引ける。 規則を変えたら hook の判定式も同じ版の code に合わせ直す (hook の test が規則の例を持つ)。

## <a id="where-to-put-the-rule"></a>規則をどこに置くか

規則の本文は本 doc だけに置き、 CLAUDE.md や template には要点と本 doc への参照だけを書く (同じ本文を複数の file に写すと、 片方だけ直る)。 個人層で書き方を絞る (例: 画面によらず常に Unicode) のは自由。 その時も、 どの画面が何を描くかの事実は本 doc に合わせる。
