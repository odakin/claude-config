# チャットでの数式の書き方

返事の数式がどう見えるかは、 **返事を読む画面** で決まる。 同じ書き方が、 ある画面では描かれ、 別の画面では生の TeX のまま出る。 書く前に、 読む画面を決める。

## <a id="by-surface"></a>画面ごとの書き方

| 画面 | 数式の描画 | 書き方 |
|---|---|---|
| Claude desktop app の Code タブ | KaTeX で描く | LaTeX を [#code-tab-katex](#code-tab-katex) の規則で |
| Claude Code CLI (ターミナル) | 描かない | `_` / `^` + Unicode (σ ∂ ℏ ∫ など) |
| 画面が決まらない (複数の画面で読まれる・どれか分からない) | — | Unicode (どの画面でも崩れない) |
| コピペして `.tex` に貼る LaTeX 片 | (読ませない) | code block = [latex.md#latex-in-chat-codeblock](latex.md#latex-in-chat-codeblock) |

Code タブかどうかは、 system prompt の記述 (Claude desktop app の Code tab で動いている旨) か、 環境変数 `CLAUDE_CODE_ENTRYPOINT` (= `claude-desktop`) で分かる。 Remote Control でスマホから読む session のように、 同じ session でも読む画面が変わることがある。 迷ったら Unicode。

## <a id="code-tab-katex"></a>Code タブで LaTeX を書くときの規則

実測 (Code タブで 20 件の試験。 アプリ本体 2.26454.2 の描画設定とも照合):

- 区切りは `$…$` (インライン)・`$$…$$` (ディスプレイ)・`\(…\)` (インライン) だけ。 **`\[…\]` は描かれず生のまま出る**。 生で出た文字列はそのまま Markdown に渡るので、 `_{…}` の `_` が強調に取られて添字まで消える。
- 開きの `$` の直後と閉じの `$` の直前に空白を置かない (`$ x $` は生表示)。 インライン数式は 1 行に収める (行をまたぐと生表示)。
- **`\(` の直前には半角空白を 1 つ置く**。 本体の `\(` 用 guard は、 `\(` の直前の文字 (`*` `_` `~` は飛ばして見る) が **半角空白・タブ・改行・`(`・`[` か文頭** のときだけ数式の開始にする (本体 2.31226.1 の描画 chunk を読んで確定)。 日本語の文字・読点・句点・「 ・〜 の直後に `\(` を置くと数式にならず、 `\(` と `\)` のバックスラッシュだけが Markdown のエスケープとして消え、 `_` は強調に取られて `(x{2},\dots,x{N})` のような生の文字列が出る。 「…なので、\(x\) は」 でなく 「…なので、 \(x\) は」 と書く。 2026-10-11 に 1 通の返事で 63 箇所が生表示になった主因。
- **`\(…\)` の中身にも guard がある** (同じ chunk の `\(` 用 inline guard。 2026-10-10・2026-10-11 の画面の実測と全件一致)。 外れると `\(` の直前の規則と同じ形で生表示になる:
  - **中身に `\ ^ { } = < > | ! +` のどれか、 または `x_1` 形 (英字 `_` 数字) の添字が要る**。 **`\(K\)` `\(K(t)\)` `\(t\)` `\((N-1)\)` `\(K_E\)` `\(C_t\)` は生表示** → 1 文字は `$K$`、 `K(t)` のような記号の無い式は地の文の文字で書く、 添字は `\(K_{E}\)` と `{}` を付ける。
  - **空白か文頭の直後の `-x` / `--x` (CLI の flag の形) を含む中身は、 `\英字` か `^` も含まないと落ちる**: `\(-i\,d/dx\)` が生表示になった真因はこれ (`\,` ではない。 2026-10-11 実測: 空白の後の `\( a\,\mathrm d^{N}x \)` は描かれた)。 `\( {-}i\,\mathrm d/\mathrm dx \)` のように書く。
  - 中身に `$`・backtick・`\(`・`\|` `\.` `\+` `\*` `\?` `\数字` を入れない (ノルムは `\lVert v\rVert`)。 `\,` `\;` `\!` は通る。 中身は 200 文字以内、 `\)` は同じ行に置く。
  - `$…$` の gate にある 60 文字制限・英字 4 連続・括弧の釣り合いの判定は `\(…\)` には無い。
- **`$…$` の guard** (同じ chunk の `$` 用 inline guard): 中身 60 文字以内、 前後に空白なし、 末尾が演算子・`,`・`:`・開き括弧でない、 括弧と `{}` が釣り合う、 `\|` を含まない。 その上で「英字 1 文字」「数と四則の式 (先頭が数字でない)」「`\ ^ { } = < > | ! +` か `a_b` / `x_{` 形の添字を含み、 `{}` の外に英字 4 連続・CJK・`%` が無い」 のどれか。 `$P_D$` `$[0,1]$` `$xy$` `$1/q$` `$\|v\|$` は生表示。 **落ちた `$` の閉じは次の式の開きになる** (本体は `$` を 1 文字進めるだけ) ので、 1 箇所の失敗が後続の `$…$` を道連れにする。 条件の全文は [`hooks/chat-math-render-guard.py`](../hooks/chat-math-render-guard.py) の header。
- **数式を含む返事は Stop hook が機械で検査する** = [`hooks/chat-math-render-guard.py`](../hooks/chat-math-render-guard.py) (desktop の session の最終発話を本体と同じ判定式で走査し、 落ちる式を行番号・理由・直し方つきで block → 直して出し直す)。 規則を知っているだけでは防げない — 2026-10-10 に規則を確定した翌日に、 読点の直後の `\(` と記号の無い `\(g\)` で 1 つの返事の 63 箇所が生表示になった (同日に別 session でも)。 自己点検に頼らず hook に任せる。 下書きを file にして `python3 hooks/chat-math-render-guard.py --check FILE` で先に見てもよい。 hook が写していないもの = `$$` block の判定 (見ない。 `\\0` を含む 1 行の pmatrix が描かれたので止めない)。
- 表のセルに `|` や `\|` を含む数式を書かない (`$\langle\psi|\phi\rangle$` はセルの区切りに取られる)。 `\mid` / `\vert` / `\lVert` で代えるか、 表の外に出す。
- コマンドは KaTeX にあるものだけ。 **physics パッケージは不可** (`\dd` `\dv` `\pdv` `\abs` `\norm` `\ev` `\mel` `\comm` `\tr` `\Tr`) → `\mathrm{d}x`, `\frac{\partial f}{\partial x}`, `|x|`, `\|v\|`, `\langle A\rangle`, `\operatorname{Tr}` で書く。 `\mathbb{1}` `\mathds{1}` `\id` も不可 (→ `\mathbb{I}` か `\mathbf{1}`)。 repo のプリアンブル固有のマクロも不可。
- 使えるもの (実測): `\ket` `\bra` `\braket` `\mathscr` `\mathfrak` `\bm` `\boldsymbol` `\operatorname` `\dfrac` `\lVert` `\coloneqq` `\hbar`。
- 数式を code block や backtick の中に入れない (描かれない)。 `$$` の block の内側に空行を置かない。
- 長い導出はチャットに書かず、 `.md` ファイルや Artifact に出す。

**未知のコマンド 1 つで式全体が生になる理由**: 描画器は KaTeX をエラーを投げない設定で呼び、 エラーの色を地の文と同じにしている。 KaTeX は解釈できない式を丸ごと元の文字列として出すので、 式全体が普通の文字で出る (赤字にならないので、 壊れたと気づきにくい)。

**版で変わる**: 上は 2.26454.2 での挙動 (`\(` と `$…$` の guard の規則は 2.31226.1 の本体 code から。 読んだ chunk 名と関数名は hook の header に記録)。 描画器はアプリの中でも画面ごとに設定が違う (ドル記号 1 個の数式を切っている描画器もある)。 規則が合わなくなったら、 [claude-app-bundle-reading.md](claude-app-bundle-reading.md) の手順で本体を読み直すか、 画面で 1 回試す。

## <a id="where-to-put-the-rule"></a>規則をどこに置くか

規則の本文は本 doc だけに置き、 CLAUDE.md や template には要点と本 doc への参照だけを書く (同じ本文を複数の file に写すと、 片方だけ直る)。 個人層で書き方を絞る (例: 画面によらず常に Unicode) のは自由。 その時も、 どの画面が何を描くかの事実は本 doc に合わせる。
