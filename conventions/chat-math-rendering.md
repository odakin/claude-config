# チャットでの数式の書き方

返事の数式がどう見えるかは、 **返事を読む画面** で決まる。 同じ書き方が、 ある画面では描かれ、 別の画面では生の TeX のまま出る。 書く前に、 読む画面を決める。

## <a id="by-surface"></a>画面ごとの書き方

| 画面 | 数式の描画 | 書き方 |
|---|---|---|
| Claude desktop app の Code タブ | KaTeX で描く | LaTeX を [#code-tab-katex](#code-tab-katex) の規則で |
| Claude Code CLI (ターミナル) | 描かない | `_` / `^` + Unicode (σ ∂ ℏ ∫ など) |
| 画面が決まらない (複数の画面で読まれる・どれか分からない) | — | Unicode (どの画面でも崩れない) |
| コピペして `.tex` に貼る LaTeX 片 | (読ませない) | code block = [latex.md#latex-in-chat-codeblock](latex.md#latex-in-chat-codeblock) |

Code タブかどうかは、 system prompt の記述 (Claude desktop app の Code tab で動いている旨) か、 環境変数 `CLAUDE_CODE_ENTRYPOINT` (= `claude-desktop`) で分かる。 Remote Control でスマホから読む session のように、 同じ session でも読む画面が変わることがある。 迷ったら Unicode。

## <a id="code-tab-katex"></a>Code タブで LaTeX を書くときの規則

実測 (Code タブで 3 段階 52 件の試験。 アプリ本体 2.26454.2 と 2.31226.0 の描画器の code とも照合):

- 区切りは `$…$` (インライン)・`$$…$$` (ディスプレイ)・`\(…\)` (インライン) だけ。 **`\[…\]` は描かれず生のまま出る**。
- 開きの `$` の直後と閉じの `$` の直前に空白を置かない (`$ x $` は生表示)。 インライン数式は 1 行に収める (行をまたぐと生表示)。
- **`$…$` には「数式らしさ」 の gate がある** ([#dollar-inline-gate](#dollar-inline-gate))。 60 文字を超える・数式記号を含まない (`$[0,1]$` `$xy$` `$P_D$`)・英字 4 文字以上が裸で続く、 などで生表示になる。 `\(…\)` と `$$…$$` にはこの gate が無いので、 **短く単純な式以外のインラインは `\(…\)` を既定にする** (`\(` の直前には空白を置く)。
- 表のセルに `|` や `\|` を含む数式を書かない (`$\langle\psi|\phi\rangle$` はセルの区切りに取られる)。 `\mid` / `\vert` / `\lVert` で代えるか、 表の外に出す。
- コマンドは KaTeX にあるものだけ。 **physics パッケージは不可** (`\dd` `\dv` `\pdv` `\abs` `\norm` `\ev` `\mel` `\comm` `\tr` `\Tr`) → `\mathrm{d}x`, `\frac{\partial f}{\partial x}`, `|x|`, `\lVert v\rVert`, `\langle A\rangle`, `\operatorname{Tr}` で書く (`\|v\|` は `$…$` の gate が正規表現と見なして生表示にする)。 `\mathbb{1}` `\mathds{1}` `\id` も不可 (→ `\mathbb{I}` か `\mathbf{1}`)。 repo のプリアンブル固有のマクロも不可。
- 使えるもの (実測): `\ket` `\bra` `\braket` `\mathscr` `\mathfrak` `\bm` `\boldsymbol` `\operatorname` `\dfrac` `\tfrac` `\lVert` `\coloneqq` `\hbar` `\bmod`。
- 数式を code block や backtick の中に入れない (描かれない)。 `$$` の block の内側に空行を置かない。
- 長い導出はチャットに書かず、 `.md` ファイルや Artifact に出す。

**未知のコマンド 1 つで式全体が生になる理由**: 描画器は KaTeX をエラーを投げない設定で呼び、 エラーの色を地の文と同じにしている。 KaTeX は解釈できない式を丸ごと元の文字列として出すので、 式全体が普通の文字で出る (赤字にならないので、 壊れたと気づきにくい)。

### <a id="dollar-inline-gate"></a>`$…$` の中身の gate (描画器が KaTeX に渡す前の判定)

描画器は `$…$` の span を KaTeX に渡す前に「数式か、 通貨・散文・code か」 を判定し、 外れた span は普通の文字のまま出す (未知コマンドと同じく赤字にならない)。 以下は本体 2.31226.0 の描画 chunk (`$` span の inline guard) を読んで、 画面の 52 件の試験と突き合わせたもの。 `\(…\)` と `$$…$$` はこの gate を通らない (実測: `\(…\)` は 71 文字・`\([0,1]\)` とも描画、 `$$…$$` は 84 文字で描画)。

- **中身は 60 文字以内**。 61 文字以上は生表示 (実測: 54 文字は描画、 67〜71 文字は生表示)。
- **中身の形が次のどれかであること**: (a) 英字 1 文字 (`$t$`) / (b) 数と四則演算だけの式で先頭が数字でないもの (`$-1$` `$x-y$` `$(0,1)$` `$f(0,1)$`) / (c) `\ ^ { } = < > | ! +` のどれかを含むもの、 または `x_1` `x_i` `x_D` `T_1` `T_d` `T_{…}` 形の添字を含むもの。 どれにも当たらないと生表示: `$[0,1]$` `$[a,b]$` `$a,b$` `$xy$` `$dx$` `$2x$` `$(a+b)c$` **`$P_D$` `$T_D$`** (大文字 `_` 大文字は添字と見なされない)。 → `\([0,1]\)`、 `$x\,y$`、 `$2\,x$`、 `$c(a+b)$`、 `$P_{D}$` のように書く。
- **散文に見えると生表示**: コマンド名と `{…}` の外に英字が 4 文字以上続く (`$\hat T+abcd$`)、 日本語が 2 文字以上、 `\%` でない `%`。 語は `\text{…}` / `\mathrm{…}` の中に入れる。
- **先頭・末尾**: 先頭が `{` は不可。 先頭が `(` なら (b) の形か `\コマンド` / `^` を含むこと。 末尾が演算子 (`+` `-` `*` `=` `<` `>` `/` `^` `_`)・開き括弧・`,` `:` `;` `\` は不可 (`$x+$`)。 先頭・末尾の空白は不可。
- **中身に入れられないもの**: `$`・backtick・`\(`。 `\|` `\.` `\+` `\*` `\?` `\数字` (正規表現に見える) → ノルムは `\lVert v\rVert` か `\Vert v\Vert`。 Markdown の強調の記号 (アスタリスク 2 連・下線 2 連・チルダ 2 連)・`](`・HTML タグ風 (`<b>` のように `<` 英字 `>`)。 `=~` `!~` `&&` `@` `#` (`\#` も) `"` `\\\\`、 行頭・空白・`(` `=` `,` の直後の `'`、 空白・引用符・`(` `/` `[` `=` `,` `;` の直後で `{` が続かない `^`、 空白や `(` の直後の `!` で終わるもの。
- **括弧の釣り合い**: `( ) [ ] { }` が釣り合わないと不可。 `|` が奇数個で末尾が `|` のときも不可 (`$\langle\psi|$`)。
- **開き `$` の直後が数字** なら通貨の形と見なし、 (c) の数式記号が無いと生表示 (`$2x$` は生、 `$2^n$` `$2+x$` は描画される)。 表計算の cell 参照の形 (`$A$1`) も数式と見なさない。
- **閉じ `$` の直後が数字** は不可 (通貨の形)。 `(` は code 上は通るはずだが、 同じ行に後続の `$…$` があると生表示になった (実測 3 回、 原因は未特定)。 空白を入れるか `\(…\)` にする。

**版で変わる**: 上は 2.26454.2 (macOS) と 2.31226.0 (Windows) での挙動。 描画器はアプリの中でも画面ごとに設定が違う (ドル記号 1 個の数式を切っている描画器もある)。 規則が合わなくなったら、 [claude-app-bundle-reading.md](claude-app-bundle-reading.md) の手順で本体を読み直すか、 画面で 1 回試す。 gate の判定は `inlineGuard` を持つ chunk にあり、 `It=60` (文字数)・`\p{L}{4}` (散文)・`[\\^{}=<>|!+]` (数式記号) で引ける。

## <a id="where-to-put-the-rule"></a>規則をどこに置くか

規則の本文は本 doc だけに置き、 CLAUDE.md や template には要点と本 doc への参照だけを書く (同じ本文を複数の file に写すと、 片方だけ直る)。 個人層で書き方を絞る (例: 画面によらず常に Unicode) のは自由。 その時も、 どの画面が何を描くかの事実は本 doc に合わせる。
