# ポッドキャストの仕上げ（ジングル・音量・書き出し）

分割済みの本編 1 本に、ジングルを頭と尾に付け、音量を揃えて配信用ファイルに書き出す場面。
機械化 = [`scripts/audio-finish-episode.py`](../scripts/audio-finish-episode.py)。番組ごとの値
（ジングル、タグ、冒頭ジングルを切る位置、本編ごとの頭の削り）は、呼び出し側の薄い入口で渡す。

前段（文字起こし・分割）は [`audio-transcription.md`](audio-transcription.md)。

## <a id="loudness-target"></a>音量の目標: -16 LUFS ±1、true peak -1 dBTP 以下

- [Apple Podcasts の公式要件](https://podcasters.apple.com/support/893-audio-requirements) は
  **-16 LKFS ±1 dB、true peak ≤ -1 dBFS**（ITU-R BS.1770 で測る）。ほかの配信先は再生時に音量を揃えるので、
  ピーク側の条件が厳しいこの値に合わせておけば困らない。Spotify を -14 LUFS とする記事もあるが、公式ページでは未確認
- **ジングルも本編も同じ値に揃える**。LUFS は聴感の大きさを測る尺度なので、まず同じにしてから聞いて調整する
  （音楽のジングルは話し声より 5〜7 dB 大きいのが普通、実測）。調整するなら「ジングルを何 LU 下げるか」で持つ
- 本編ごとに大きさが違う（同じ番組でも 2 dB ほど、実測）ので、ジングルだけを本編に合わせるやり方だと回ごとに音量が揃わない

## <a id="limiter-oversampled"></a>ピークは 192 kHz で掛けたリミッターで抑える

本編を目標まで上げると、元の山が上限を越える。削る必要がある。

- 48 kHz のまま削ると、サンプルとサンプルの間に立つ山（true peak）が残る。**192 kHz に上げてから削り、戻す**
- 上限は -1.0 でなく **-1.5 dBFS** にする。MP3 にすると山が少し伸びる（実測で 0.4 dB 前後）
- **ffmpeg の `alimiter` の罠 2 つ**:
  - `level` は既定で有効で、出力を上限まで**自動で持ち上げる**（音量が勝手に変わる）→ `level=0`
  - 先読みの遅延を補正しない（頭がずれて尾が欠ける）→ `latency=1`
- **`loudnorm` だけで済ませない**: 目標の音量とピークを同時に満たせないとき、数秒単位で音量を自動で上げ下げする
  モードに**黙って切り替わる**。話の間や声の大小が平らになる
- 削った量（削る前のピーク − 上限）を記録する。6 dB を超えたら、大きな笑い声などの箇所を聞いて歪みを確かめる

## <a id="measure-rerender-loop"></a>書き出したら測り直す（1 回で合うと思わない）

リミッターで山を削ると本編の積分音量が少し下がり、MP3 にすると山が少し伸びる。どちらも書き出してみないと量が分からない。

1. 入力を測る → 利得を決める → 連結・リミッター・**符号化は最後に 1 回だけ**（圧縮音声は符号化のたびに劣化する）
2. 出力を測る: 全体・本編区間・冒頭ジングル区間の積分音量、true peak
3. 本編区間が目標から外れた分を利得に足し、true peak が上限を越えた分だけリミッターの上限を下げて作り直す（数回で収まる）
4. 検査: 全体 ±1 LU / true peak / 本編区間 ±0.5 LU / ジングル区間 / **長さ = 冒頭ジングル + 本編 + 締めジングル**
   （MP3 の前後の詰め物ぶん ±0.15 秒）/ **入力のメタデータが残っていない**（作者欄などが配信ファイルに持ち越されるため、
   タグは付け直す）
5. 検査に落ちた出力は名前を変えて残し（配信用と取り違えない）、試した利得・上限・測定値を JSON に残す

検査が飾りでないことも確かめる: 無理な目標（例: -6 LUFS）では落ちること。

## <a id="edge-fades"></a>本編の頭と尾: 短くフェードし、切れた断片は聞いて削る

- ジングルの余韻が**完全な無音**まで落ちた直後に、本編が 10 ミリ秒で -18 dB まで立ち上がると、
  **プツッという雑音に聞こえる**（実測）。録音開始の本編は話の途中から始まることが多い
- 対処 1: **本編の頭 0.03 秒・尾 0.05 秒を必ずフェードする**（尾は、話の途中で切れた本編からジングルへつなぐため）
- 対処 2: 頭に**切れた語の断片**や「うん」「ろ」のような意味の無い音があれば、最初の文の立ち上がりの少し手前
  （部屋の静かな音だけの所、例: 0.08 秒前）から始める
- **削るかどうか・どこまで削るかは聞いて決める**: 断片に見える音が語の頭そのものの場合がある。短い区間だけを
  機械で文字起こしすると、長い区間とは別の語が出る（実測: 同じ冒頭が短い窓では「うん、ろ」、長い窓では語の一部として吸収された）
- 聞き比べの候補ファイルは、**名前の先頭で区別が付くようにする**。共通の接頭辞に A/B/C を付けただけの名前は、
  プレーヤーの窓の題名が途中で切れて区別できない（実測）。中身を名前にする（例: `よしから始める版.mp3`）
- 削った秒数は、書き出しの記録（JSON）と素材の目録に書く（作り直すときに同じ値を使う）

## <a id="intro-jingle-silence"></a>冒頭ジングルの後ろの長い無音は切る

ジングルのファイルは、音が消えた後に数秒の無音を持っていることがある。冒頭にそのまま置くと、話し始めまでが空きすぎる
（実測: 3 秒強の空白は長すぎる）。

- ジングルの音が **-60 dB を最後に越える時刻**を測り、その少し後（0.5 秒前後）で切る。切り口は 0.2 秒ほどでフェードする
- 締めのジングルは切らない（回の終わりは余韻のまま終わってよい）
- 切る位置はジングルごとの値なので、番組側の入口に持つ

## <a id="call-over-jingle-riser"></a>冒頭のかけ声は、ジングルの盛り上がりの上に乗せてアタックを語尾の直後に置く

冒頭だけ「番組名のかけ声 + ジングル」にするときの作り方。冒頭用の音を 1 本作って `--intro` で渡す（締めは `--jingle` のまま別の音にできる）。

- ジングルが**頭の無音 → だんだん大きくなる盛り上がり → アタック**の形なら、かけ声とジングルの間の空白を詰めるだけでは足りない。
  盛り上がりの前半はほとんど聞こえないので、間を 0 にしてもまだ空いて聞こえる（実測: 0 にしても 0.3 秒ほど聞こえない区間が残った）。
  **盛り上がりをかけ声の下に敷き、アタックが語尾の直後に来るように置く**
- アタックの位置は耳でなく測る: 2.5 ms 窓の包絡で、盛り上がりが途切れる時刻と、低域（20–150 Hz）が一気に跳ぶ時刻を取る。
  盛り上がりの直後に短い無音を挟んでアタックが来る作りが多い。**語尾の響きが床近くまで落ちた時刻を、盛り上がりの切れ目に合わせる**
- 値を固定して持つなら、使う前に「切れ目が無音で、その前後が鳴っている」ことを確かめる。ジングルを差し替えると値が黙って合わなくなる
- **声の下の盛り上がりの大きさを測る**。語尾の近くでは盛り上がりが声とほぼ同じ大きさになり、声が埋もれうる（実測: 差 2〜3 dB）。
  聞いて埋もれるなら、声の鳴っている間だけ下の音を下げる
- 冒頭用の音は**可逆形式（FLAC など）**で持つ。MP3 で持つと、仕上げの符号化と合わせて 2 回符号化することになる
- 冒頭用の音でジングル頭の無音を落としていれば、[冒頭を切る位置](#intro-jingle-silence)はその分ずれる。**冒頭用のファイルの時刻で数える**
- かけ声のテイクを回ごとに替えるなら、**選び方を決定的にする**。作り直すたびに冒頭が変わると、聞いて OK を出したものと
  違うものが出ていく。どれを使ったかは書き出しの記録（JSON）に残す
  - **回の並び順で選び、N 回ずつの組ごとに順番をランダムに並べ直す**（組の切れ目で同じものが続いたら入れ替える）。
    N 回で全テイクが 1 回ずつ出て偏らず、周期も見えない。乱数は「固定の種 + 組の番号」のハッシュから作る
    （言語の乱数生成器は版で出力が変わりうる）。新しい回は並びの末尾に足されるので、既存の回の割り当ては動かない
  - 採らない: **回の名前のハッシュで 1 本ずつ選ぶ**（少ない回数では偏る。実測: 7 回で 5 本中 2 本が一度も出ず、同じものが続いた）/
    **乱数で 1 回決めた順番を繰り返す**（N 回ごとに同じ並びになり、聞き手に周期が分かる）

## <a id="outro-riser-under-last-words"></a>締めのジングルも、盛り上がりを最後の言葉の下に敷いてアタックを語尾の直後に置く

- 盛り上がりのあるジングルを締めに全長で続けると、最後の言葉からアタックまでが **ジングル頭の無音 + 盛り上がり + 本編の尾の無言** だけ空き、
  聞き手には空白に聞こえる（実測: 2.7〜4 秒の空白は長すぎる）。[冒頭のかけ声](#call-over-jingle-riser)と同じく、盛り上がりを最後の言葉の下に敷く
- script では `--outro-overlap <アタックの時刻>` = 締めのジングルを本編の終わりのその秒前から重ね、本編の終わりにアタックが来る。
  本編はその下で最後まで鳴る（連結でなく足し算。ffmpeg の `amix` は既定で入力数で割って音量を下げるので `normalize=0`）
- **本編の尾の無言は本編ごとに違う**（実測 0.15〜1.6 秒）。`--trim-tail` で、最後の言葉の少し後（例: 0.15 秒）に本編が終わるよう揃える。
  最後の言葉は短い窓の音量で測る（例: 10 ms 窓で -45 dB を最後に越えた所）。削った秒数は頭と同じく記録に書く
- 聞き比べの候補は「今のまま / 盛り上がりを敷く / 盛り上がりを落としてアタックから始める」。落とす版は最後の一語が確実に聞こえるが、音がいきなり鳴る
- 盛り上がりの終わりは声と同じくらいの大きさになりうる（実測: 差 0 dB）。最後の一語が埋もれないかを聞く（[聞く所](#listen-checklist) の 3）
- 検査: 重ねた所は本編区間の音量の測定から外す。長さは「冒頭 + 本編 + 締め − 重ね」で勘定する

## <a id="measure-from-file-head"></a>区間の長さはファイルの頭から測る

MP3 を途中の時刻から切り出して（`-ss` で頭出しして）測ると、**先頭の数十ミリ秒が無音に見える**ことがある。
その区間を「無音の始まり」と拾い、空白の長さを実際より長く出してしまう（実測: 0.7 秒の空白が 1.5 秒と出た）。
区間の境目や空白の長さは、ファイルの頭から読み込んで時刻で数える。

## <a id="listen-checklist"></a>機械では確かめられない所（人が聞く）

1. 頭: ジングル → 本編の最初の一言
2. ジングルの大きさ: 声と比べて大きすぎ／小さすぎないか
3. 尾: 本編の最後 → ジングル（締めを重ねたなら、最後の一語が盛り上がりに埋もれていないか）
4. リミッターの削り量が大きかった本編の、大きな笑い声などの箇所。 どこかは仕上げの記録からは分からないので、 本編 (仕上げる前の part) の山が 0 dBFS 近くまで行く区間を
   [`../scripts/audio-window-check.py`](../scripts/audio-window-check.py) `peaks` で大きい順に出し、 上の数か所を数秒ずつ切り出して聞いてもらう
   (山は話し手の声の頭であることが多い = 実測。 元の音が平らに潰れているか = flat factor は ffmpeg の `astats` で見られる)

## <a id="when-a-check-fails"></a>検査に落ちたとき

| 落ちた検査 | よくある原因 | 対処 |
|---|---|---|
| true peak | 削る量が大きく、MP3 化で山が伸び続けた | 作り直しの回数を増やす前に、本編に大きな雑音や機材トラブルが無いか疑う |
| 本編区間の音量 | 本編が極端に小さく、リミッターが効きっぱなし | 削り量が 10 dB を超えるなら収録の問題。目標を下げて出すか相談する |
| ジングル区間の音量 | ジングルが極端に短い・無音が長い | ジングル単体を測る。無音が長いと区間の測定が不安定になる |
| 長さ | 入力の音声が途中で切れている・先頭に空白がある | 本編の長さと開始時刻を確かめる。頭尾を削ったなら、削った後の長さで勘定しているか |
| タグ | ffmpeg の版で付くタグが変わった | 余分なタグ名を見て、無害なもの（エンコーダ名の類）なら除外に足す |

## <a id="bgm-under-speech"></a>本編の下に BGM を敷く（試作 → 採用の順）

- **まず試作で聞かせる**: 仕上がった配信音声（ジングル + 本編 + ジングル）の上に BGM を足し算で重ねた 1 本を作り、本人・共演者に聞いてもらう。
  入口 = `scripts/audio-bgm-underlay.py`（BGM の integrated loudness を測って目標に合わせ、区間を切ってフェードし、`amix normalize=0` で重ね、出力を測り直す）。
  これは仕上がった MP3 をもう 1 回符号化する 2 世代目なので、**採用が決まったら仕上げ script の `--bgm` で生の本編から 1 回の符号化で作り直す**
  （`audio-finish-episode.py <part> … --bgm <loop.flac> --bgm-lufs -40`。区間とフェードは下の決まりどおりに script が出し、BGM の素材の sha256 と利得・区間を `.json` に残す）。
  上げ済み・予約済みの回は、作り直した音声だけを差し替える（題・紹介文・公開時刻はそのまま。LISTEN は音声だけ渡すと紹介文が空になる = [podcast-distribution.md#listen-style-api](podcast-distribution.md#listen-style-api)。
  YouTube は一度取り込んだ回の音声を取り直さない = 差し替えは公開前に）
- **区間**: 冒頭ジングルが終わる所から数秒かけてフェードイン、締めのジングルが重なり始める所で消え終わるようフェードアウト。ジングルの上には乗せない
  （仕上げの記録 `.json` の `intro_jingle_s` / `trim_head_s` / `trim_tail_s` / `outro_overlap_s` から時刻が出る）
- **音量は声との差で決め、曲ごとに候補を 3 段作って聞き比べる**: 声 -16 LUFS に対して、BGM の integrated loudness を声の 16 / 20 / 24 dB 下（-32 / -36 / -40 LUFS）から始める。
  実測では 16 dB 下は「うるさい」、会話の下に敷くなら 24 dB 下前後。決めた値は曲ごとに番組の値の表に書く
  - <a id="bgm-level-per-track"></a>**値は曲ごと。曲を替えたら前の曲の値を使い回さない**: integrated loudness で揃うのは平均だけ。盛り上がりの大きい曲（LRA が大きい・3 秒窓の最大が平均より 6 dB 以上上）や、
    声に近い音色の旋律を持つ曲は、同じ値でも静かな話の声に近づく（実測: 声の 24 dB 下のはずの値で、間の多い箇所では約 13 dB 下まで来て「でかすぎ」と言われた。
    波の小さい曲は同じ値・同じ箇所で問題にならなかった）。波の大きい曲は、目安の値より 4 / 8 dB 下の段も候補に入れる
  - **聞き比べは間の多い箇所で**: 平均的な箇所では段の差が聞き分けにくい。BGM が一番聞こえるのは声が止まっている所
  - **切り出しは生の本編から仕上げと同じ利得・リミッターで作り、今の値の段が仕上がりと一致することを測ってから渡す**（同じ箇所の 0.4 秒窓の下側の分位を比べる）。
    道具 = `scripts/audio-bgm-audition.py`（`quiet` = 間の多い箇所を探す → `clips --reference` = 段ごとの切り出しと仕上がりとの照合 / `profile` = 曲同士の波の大きさ・帯域 / `gaps` = 仕上がりの話の間の BGM の大きさ）。
    値を決めたら切り出しでなく仕上げ script で生の本編から作り直す
  - ⚠️ ffmpeg でループする入力（`-stream_loop -1`）に `-ss` を付けると、折り返しのたびに `-ss` の位置へ戻る（実測）。ループの途中から切るなら filter の `atrim=start=` で切る
- **出力の検査は仕上げと同じ**（全体の loudness・true peak）。BGM が 20 dB 以上下なら全体の loudness はほとんど動かない（+0.1 LU 程度）が、
  true peak は上がりうるので測る
- **ループ素材の形式**: 長い本編に短い BGM を繰り返して敷くなら、素材は **WAV / FLAC**。AAC（m4a）は頭に符号化遅延の無音が入り、
  繰り返しのつなぎ目で切れる。sample rate はジングル・本編と揃える
- **つなぎ目の無いループ素材を合成で作るとき**: 曲の終わりの残響・余韻が頭に入っていないと、繰り返したときに切れて聞こえる。
  [最後の周][1〜N 周][最初の周] の順に描いて真ん中だけを切り出せば、頭に最後の周の尾が入る。
  その前後の周が本物の周とサンプル一致するよう、乱数（位相・揺れ）は曲の中の位置で決め、残響は線形・時不変（畳み込み）にする。
  切り出しの頭と、切り出しの直後の数秒を比べて一致を確かめる（実測で差は信号の 10⁻⁶）
- <a id="synth-bgm-sound-pitfalls"></a>**BGM を合成で作るときの音の罠**（聞き手は原因でなく「ビブラートがきつい」「もっちゃり」「ボケる」と言う）:
  - **ずらして重ねた 2 本のうなりは、ビブラートに聞こえる**: ±c セントずらした 2 本は f × (2^(2c/1200) − 1) Hz でうなる（A4 で ±5 セントなら約 2.5 Hz = ちょうどビブラートの速さ）。
    倍音ごとに音量をゆっくり揺らす処理も、深さ 0.1 を越えると同じに聞こえる。伸ばす旋律は 1 本にし、パッドは ±1 セント以内・揺れの深さは 0.06 程度にする。
    伸ばしている区間の 1.5〜12 Hz の音量の揺らぎで確かめる（実測で約 1/12 に下がった）
  - **低い中音域で 2 度に重なった和音は濁る**: 和音の音を最小移動で 150〜330 Hz 付近に詰めると、2 度（add9 なら 9 度と 3 度。短調では半音）がそこで鳴る。
    下から 3 度 → 5 度 → 9 度のように 3 度と 5 度だけで積み、パッドの立ち上がりと消えの重なりを短くし（約 2 秒 → 0.7 秒）、
    共有の残響に送る音を 250 Hz 付近で high-pass する（低音は残響なしにする）。実測で 100 Hz 未満の割合が半分、400 Hz〜2 kHz が倍になった
  - **パッドを上へ開いたら、旋律の音域と重なっていないかを見る**: 重なると旋律が埋もれ、聞き手には「旋律が無い」と聞こえる。旋律をパッドの最高音より上へ移すか、パッドを下げる
  - **版を聞き比べてもらうときは、integrated loudness をそろえてから渡す**: peak でそろえた書き出しは版ごとに数 dB 違い（実測 3.5 dB）、大きい方が良く聞こえる
  - **ある声部が鳴っているかは、混ぜる前のその声部で確かめる**: 混ぜた音で音の高さを測ると、ベースの倍音（根音の 1 オクターブ上）や
    伴奏の同じ高さの音でも通ってしまう（実測）。声部ごとの bus を書き出しの手前で取り出して測る
  - **低い旋律の音が「聞こえない」と言われたら、残響の周波数特性と左右の和を見る**: 残響の応答を移動平均で滑らかにしてからエネルギー 1 に正規化すると、
    エネルギーが低い所に集まり、200〜500 Hz では残響が元の音より大きくなる（実測 6〜9 dB）。高い旋律では害が無くても、その音域では
    直前の音の残響が次の音を塗りつぶす。左右で別の応答（片側を時間反転など）を使うと、ある高さで左右が逆位相に寄り、左右を足すと約 10 dB 消える
    （1 つのスピーカーで聞く人には鳴っていない）。確かめ方 = 送る量 × 応答の周波数特性を元の音と比べる / その音の高さで L・R・(L+R)/2 を測る。
    直し = 残響に送る音を high-pass する（旋律の全部の音に同じに）
  - **旋律と和音の倍音の並びが似ていると、音色が区別できず単調に聞こえる**: サインに少し倍音を足した音どうし（1 / .3 / .12 と 1/k^1.6）はほぼ同じ並び。
    片方か両方の倍音を母音のフォルマントで形づけると（5 kHz まで、RMS はそろえる）、音量を変えずに区別がつく（別の母音どうしにする）。
    母音ごとに下の揺れとざらつきを測ってから選ぶ（母音によって揺れが増えるものがあった = 実測）。
    倍音の高さに絞った雑音を混ぜる「空気」の層は、雑音の音量のゆらぎが 1.5〜12 Hz に入ってビブラートに聞こえる（帯域を広げても狭めても残った = 実測）
  - **「濁る」は窓ごとのざらつきで数にできる**: 0.5 秒ごとのスペクトルの山の対から Plomp-Levelt / Sethares の協和モデルで計算し、版どうし・小節ごとに比べる。
    短い音が全音で続く動き（特に 1 kHz 付近）は、余韻と残響の中で重なってざらつく。旋律を機械で組むなら、各音と伴奏の倍音とのざらつき、
    前の音とのざらつきを点数に入れ、旋律を和音の一番上の音より上で組むと下がる（実測）。濁る小節が見つかっても、その小節を特別扱いせず、
    全体の設定（残響の量・旋律の動き方の決まり）で効くものを探す
  - **採用した曲の和音の種類だけを替えた版を頼まれたら**（「同じ作りで和音だけ別の種類に」）: 和音に依らない所（周ごとの表・音色・音量・残響・ループの仕掛け）はそのまま写し、
    和音に依る規則は原理から当て直す（例: 「共通音 2 つを残し、残りが全音上がる」 は最小移動の声部進行なので、新しい和音にも最小移動で当て、同じ音域に折り返す）。
    旋律の音は和音の中の役割で写す（伸ばす色の音 → 新しい和音の色の音、次の和音へ着地する音はそのまま）。新しい和音の音だけかを assert し、
    元の版と波の大きさ・帯域を比べる（上の `profile`）。解釈が分かれる所（旋律を音の高さのまま残すか役割で写すか）は渡すときに別案として 1 行添える
  - **アンビエントに寄せる**: 拍を刻む層（分散和音）を外す、パッドを数秒かけて立ち上げて前後の和音と重ねる、旋律は長い音を少なく、
    伴奏の残響を長く深くする（残響に送る音の high-pass は残す = 低域の濁りが戻らない）。旋律は立ち上がりと余韻を延ばし旋律だけの残響を足すとぼける
    （足しすぎると「ボケすぎ」と言われる）
- **作り直した版は、前の版との差で確かめる**: 同じ Part・同じ削りで BGM だけを足して作り直したなら、新旧を同じ位置から読み、片方を反転して足すと BGM だけが残る
  （MP3 の符号化の差はそれより十分小さい）。差の integrated loudness が狙いの値の前後か、ジングルの区間で差が消えているかを測る
  （`ffmpeg -ss 600 -t 60 -i 新.mp3 -ss 600 -t 60 -i 旧.mp3 -filter_complex "[1:a]volume=-1[i];[0:a][i]amix=inputs=2:normalize=0,ebur128" -f null -`。
  実測 = 狙い -40 LUFS に対して本編の差 -39.4 LUFS、締めのジングルの上は -61 dB = BGM なし）
- **BGM の素材を共同作業者も書ける共有フォルダに置くなら、仕上げの入口に sha256 を固定し、照合してから使う**（差し替えられた素材が気づかれずに配信に載るのを止める）
- **共演者が収録で楽器を生で弾くなら、その回には後から敷かない**（BGM が二重になる）。生演奏は話と同じトラックに入るので、後から音量を変えられず、切った所で音楽も途切れる
  - 収録の途中で曲を流した区間（その場で生成した曲を聞いた、など）だけなら、回ごと外さずにその区間だけ BGM を消す = `scripts/audio-finish-episode.py --bgm-mute A-B`（Part の元の時刻、前後 2 秒でなだらかに消して戻す）。区間は話者つきの文字起こしの「流す」「止める」の発言と、音の波形の両方で決める
- **人に渡す file の大きさ**: 30 分級の MP3 は 128 kbps で 30 MB を越え、チャットの添付の上限（30 MiB）に掛かることがある。聞かせるだけなら 96 kbps の写しを別に作る
