# 板書写真の保管と公開 — 選ぶ・振り分ける・番号を付ける・見せる

授業中にスマホで撮った板書の写真を、 授業ごとに 1 つの PDF にして決まった場所に置き、 受講者が見られるようにする仕組みの一般則。 1 枚の写真に書き込みを重ねる作業は [`chalkboard-close-up-merge.md`](chalkboard-close-up-merge.md)、 手書き文書の写真を読む前処理は [`photographed-document-transcription.md`](photographed-document-transcription.md)。 すべて実測 (導入先 1 件)。

## <a id="pick"></a>写真を手元に持ってくる = Picker で本人が選ぶ

- Google Photos の Library API は、 外部の app から本人の写真を列挙できない (app が作った写真だけ) = 取り込みの API 経路は **Picker だけ**: session を作る → 本人が URL を開いて写真を選び「完了」 → 選ばれた写真だけが読める。 部品 = [`scripts/lib/photos_picker.py`](../scripts/lib/photos_picker.py) (session・待機・列挙・原寸の取得、 token の読み込み)
- URL は**スマホの写真のバックアップ先と同じ Google アカウント**でログインしたブラウザで開く (スマホでも PC でもよい)。 session には期限がある (API が返す `timeoutIn`) = URL を渡したらすぐ選んでもらう
- **その日の全部の授業の写真を 1 回の Picker でまとめて選んでもらう** (時限ごとに分けてもらわない)。 **何日分か溜まっていれば、 その全部の日を 1 回で** (日ごとに Picker を分けない = 本人の操作が日数分に増える)。 日と時限に分けるのは次の段で機械がやる
- 取り込みを background で走らせ、 出た URL を本人に渡す。 標準出力は行ごとに flush する (URL が buffer に溜まって出てこない事故 = [`debugging-discipline.md`](debugging-discipline.md))

## <a id="split"></a>撮影時刻で時限に振り分ける

- 写真の撮影時刻 (`createTime` は UTC) を現地時刻に直し、 その日の授業の時間割で振り分ける。 境目は **前の授業の終わりと次の授業の始まりの中点** (休み時間の中ほど)。 最後の授業より後に撮った写真は最後の授業に入れる (授業の後に黒板を撮ることがある)。 部品 = [`scripts/lib/class_meetings.py`](../scripts/lib/class_meetings.py) の `period_midpoints` / `assign`
- **指定した日以外に撮った写真は入れない** (選び間違いで前の週の写真が混ざる)。 入れなかったことは表示する
  - **日の指定の方が間違っていたときに、 本人に選び直させない**: 選んだ写真は Picker の session の期限までもう一度列挙できる (API の仕様。 回し直しそのものはまだ実測していない)。 session の id を表示し、 入れなかった写真の日を指定し直して同じ session で回し直す command を最後に出す (Picker を開かずに続きを処理する option を持たせる)。 id を出していないと、 指定を直すだけのために本人が同じ写真をもう一度選ぶことになる (実測)
- **板書を取らない授業** (演習・ゼミなど) は、 時間割の側に印を付けて取り込みから外す (置き場所・番号を決めない、 録画の取り込みも同じ印で外す)。 **振り分けの境目には残す** — 時間割から消すと、 その時間帯に撮った写真が隣の授業の PDF へ流れ込む。 その時間帯の写真は入れずに枚数だけ表示する
- 時限ごとに 1 つの PDF (撮影順、 EXIF の向きを直してから)。 原寸のまま入れる (板書の細かい字は縮めると読めなくなる)

## <a id="numbering"></a>「第N回」 を付ける = 2 つの数え方を照合する

- 置き場所の続き番号 (その科目で最大の回 + 1) だけで決めると、 **写真を撮らなかった回があった時点で以後の番号が 1 つずつずれる**
- 続き番号は**板書の PDF の名前の形 (`{回}_{日付}.pdf`) に完全に合う file だけ**から数える。 同じフォルダに置いたスライドなど (`{回}_{日付}_<語>.pdf`) を数えると、 その日の回が済んだ扱いになって番号が 1 つ進む (実測 = カレンダーとの照合で止まって分かった)
- 授業のある日だけが入ったカレンダー (Classroom のクラスのカレンダーに毎週の予定を入れて休講を除いたもの = [`google-classroom-api.md#class-calendar-lecture-number`](google-classroom-api.md#class-calendar-lecture-number)) があれば、 学期はじめからの件数が正しい回数になる
- **両方を出して、 食い違ったら止めて人に確かめる** (どちらが正しいかは、 写真の無い回があったのか、 休講がカレンダーに入っていないのかで決まる。 機械はどちらとも決められない)。 その日にカレンダーの授業が無い (補講を入れ忘れた・日付の誤り) ときも止める。 人が確かめたら回数を明示して進める
- 同じ日の PDF が既にあれば、 その回数を使う (作り直し)
- 何日分かをまとめて取り込むとき、 同じ科目が 2 日以上にあれば、 先の日の PDF がまだ無くても日付順に続けて番号を振る (置き場所の続き番号だけを見ると、 先の日の分を数えずに 2 日とも同じ番号になる)

## <a id="guards"></a>止まる条件は、 写真を選んでもらう前に判定する

- 置き場所が無い (学期はじめの用意の漏れ) / 回数が食い違う / 同じ回の PDF が既にある — どれも **Picker を開く前**に判定して止める。 写真を選んでもらった後で止まると、 本人の手間が無駄になる
- **同じ回の PDF は上書きしない** (手で直した PDF = 書き込みの統合や差し替えをしたもの、 を黙って消さない)。 作り直すときだけ明示の指定 (`--force` 等) で上書きする
- 写真を選ばずに「置き場所と第N回」 だけを出す mode を持たせる (授業の前に番号を確かめられる、 作り直しの前にも使える)

## <a id="publish"></a>受講者に見せる = 学期はじめに 1 回だけフォルダを案内する

- 置き場所のフォルダ (科目ごと・学期ごと) の共有リンクを学期はじめに 1 回作り、 LMS のお知らせで 1 回案内する。 以後は PDF を足すだけで受講者から見える (毎回リンクを貼らない)
- 授業の動画を同じように置いているなら、 動画のフォルダも同じお知らせで案内する。 ⚠️ 動画は本人が直接上げることが多い = **手順書の一覧でなく、 フォルダそのものを見て有無を確かめる** (実測: 一覧だけを見て「無い」 と誤報告したことがある)。 別の端末から上げた動画は、 手元では 0 byte の「オンラインのみ」 に見えることがある ([`dropbox-placeholder-diagnosis.md`](dropbox-placeholder-diagnosis.md))
- お知らせの文面は人に見せて OK をもらってから投稿し、 投稿後に読み戻して照合する ([`paste-destined-plain-text.md`](paste-destined-plain-text.md))

## <a id="after"></a>置いた後

1. **確認**: 頁数 = 選んだ枚数、 全頁を縮小して並べて目で見る (別の授業の写真・振り分けの境目・横倒し)。 黒板に番号を振っていれば、 番号順に並んでいるかも見る
2. <a id="fill-missing-from-recording"></a>**撮りそびれた板書**: 授業の録画から静止画 (画面の切り出し) を作り、 PDF の該当の位置 (黒板の番号の順) に差し込む。 **頁の幅を写真の頁にそろえる** — 写真から組んだ PDF は 1 px = 1 pt で頁が大きく、 切り出しをそのまま入れると小さな頁になって表示の倍率が頁ごとに跳ぶ。 1 枚の黒板を数枚に分けて切り出したなら撮影 (切り出し) 順に並べる。 差し込むだけなら元の頁はそのまま残る (足した頁を抜けば元に戻る)。 頁を置き換える・消すときは、 前の PDF を控えに取ってから (実測)
3. **振り返り**: 授業の記録 (どこまで進んだか・計画との差) を板書から書き起こし、 次の回の計画に反映する。 板書から書き起こした数式は記号計算で検算する (写真からの書き起こしは係数や記号を補って「生成」 しやすい = [`photographed-document-transcription.md`](photographed-document-transcription.md))
4. 感想や質問を集める課題を出すなら、 その文面にも「黒板の写真を上げました」 と書くと、 受講者が見に行く
