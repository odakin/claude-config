# Rebuttal Letter (= Author Response to referees)

paper revision で referee report に point-by-point 回答する rebuttal letter (= response-to-referees / author response) 作成の規律。 [`paper-audit.md`](paper-audit.md) (= 誤り検出 / forward ref / 重複) と相補 (= こちらは「referee への返信作成」 側)。

**Sibling docs** (= 全 5 で paper / proposal lifecycle を cover): 自分 paper の internal audit = [`paper-audit.md`](paper-audit.md) / 自分が referee として外部 paper / 申請書を評価 = [`peer-review-workflow.md`](peer-review-workflow.md) / grant 申請書の submit = [`erad-submission.md`](erad-submission.md) / 論文の journal / arXiv 投稿ポータル経由の submit = [`paper-submission.md`](paper-submission.md)。 本書 (= author response) はこれら 4 の方向違いで、 referee からの指摘に著者として返す側。

**書く前**: 返答書 (と、 それへの共同研究者のコメントに答える案) を著者の代わりに起草するときは、 英文の下書きの前に方針 (答える論点と骨子・referee や共同研究者の主張の採否と拠り所・原稿の変更の要否・著者に決めてもらうこと) を出して著者の確認を取る。 下請けに起草を渡すなら依頼を方針の段と起草の段に分ける = [`concise-output.md#policy-before-draft`](concise-output.md#policy-before-draft)。

**書き終えたら**: 出す前に、 別の agent に段落ごとに答えになっているかを判定させる。 共著者の文を残して間に文を足したときは、 報告に「変えていない」 と書かない = [#answer-fit-check](#answer-fit-check)。

**送る前に** (返答書のほか、 共著者・編集者・referee への便で、 直しの案か他人の文についての言明を含むもの): 照合票を作り、 送る文面と一緒に本人に見せる。 下請けの他人の文の読みは原文と照らすまで仮説、 鉤括弧で括るのは原文の部分文字列だけ = [#pre-send-verification-sheet](#pre-send-verification-sheet)。

**共著者が書いた返答書に直しを出すとき**: 全部の答えの直しを一度に出さず、 答えの段ごとに 1 段ずつ出して、 収束してから次の段へ = [#stepwise-edit-proposals](#stepwise-edit-proposals)。

## 構造

- LaTeX standalone document (例: `response-to-referees.tex`)。 referee comment を色付き italic quote (= `\newenvironment{referee}{\begin{quote}\color{blue!65!black}\itshape}{\end{quote}}`) で表示、 各 comment に `\textbf{Response.}` で回答。
- referee ごとに `\section*{Referee N}`、 major / minor revisions を `\subsection*`。
- 冒頭で thank-you + 全体方針 (= 例: 「2 manuscript を merge した」) を 1 段落。

## 規律 (= 6 reflex)

### 1. 回答は変更記録でなく本文を直接照合して書く (= 最重要)

変更記録 (= task tracker / completed-tasks 等の作業ログ) の「removed / added / moved」 表現は曖昧で、 回答が本文の実際の対応とズレる。 **回答 draft 後、 各「removed / added / changed / moved」 claim を本文 grep で検証する**。

**failure mode** (= 記録ベースで書くと起きる):
- 記録に「削除 *または* 引用追加」 と両論あると、 回答が「削除」 と決め打ち → 本文は「根拠追加」 だった (= 逆の対応)。
- 記録に「(旧版時点で) 対応済み」 とあるのに回答が「has been added」 (= 新規追加) と書く → 本文は元から参照済み (= added は不正確)。

**reflex**: rebuttal 完成後、 全 Response の検証可能 claim を本文 grep で一括照合する:
- 用語置換 (= 「X を Y に置換」) → 旧 X が `grep -c` で 0、 新 Y が `>0`。
- 削除 (= 「removed」) → 該当語句が本文に残っていない。
- 追加 (= 「added」「cite」) → 該当が本文に存在。
- 「removed と書いたが本文に残存」 「added と書いたが grep で見つからない」 を潰す。
- 旧式番号 (= Eq.(N)) は改訂版で変わるので grep 不能 → 旧版 tex の該当箇所を内容 (= keyword) で特定 + 現本文の対応を Read で個別確認。

### 2. 起源でない文献は「see, e.g.」 で引く

referee が「for example: X」 と挙げた文献は **一例であって唯一の出典ではない**。 X が standard result (= 教科書級) の起源でない場合、 唯一の出典のように引かない:
- 本文: `$...$~\cite{X}` (= X が出典に見える) でなく `$...$ (see, e.g., \cite{X})`。
- 回答: 「we cite X *as a reference*」 / 「as the referee suggests」 で、 「the original source」 と誤認させない。
- 文献の年・巻を WebSearch で確認し、 起源か standard treatment かを判定する。

### 3. referee の誤記は静かに正す

referee が著者名 / 式番号 / 用語を誤記した場合、 正しいものを使う (= 露骨に「あなたの誤りです」 と指摘しない)。 例: referee が citation 著者名を誤記 → 回答では正しい著者名・年・巻を書く (= 訂正を明示せず自然に正しい情報を出す)。

### 4. referee 指摘に同意しない時、 自己否定語を避け中立に

著者が「我々は誤っていない」 立場の場合、 「erroneous」 「our mistake」 等の自己否定語を使わない。 中立表現に置換:
- 「Corrected」 → 「We have revised the text」
- 「the erroneous mention of B has been removed」 → 「the mention of B has been removed」

referee を怒らせず、 かつ誤りを認めない。 例: referee が「principle A が principle B と混同されている」 と指摘 → 「the text now consistently refers to principle A, and the mention of principle B has been removed」 (= 混同を認めず、 wording を整えた、 と返す)。

### 5. 全 referee comment を省略せずフル引用

`[...]` / `[\dots]` で省略しない。 referee が「自分の comment が正確に受け止められた」 と確認できるよう、 **原文を逐語フル引用**。 原文の箇条書き構造 (= bullet) も保つ (= referee が 2 点を 1 bullet にまとめていたら、 回答も 1 block で両方に答える)。

### 6. 旧式番号は submission 版基準、 回答は「done / moved」 形式

referee の Eq / section / page 番号は **submission 版基準**で、 改訂版 (= merge / restructure 後) では変わる。 回答で改訂版の新番号に深入りせず、 「done」 「moved to an appendix」 「rephrased」 形式で答える。 冒頭で次を断る:
> Equation, section, and page numbers in the quoted comments refer to the originally submitted version; the numbering has changed in the revised manuscript.

## referee の section/Eq 番号 ≠ 改訂版・旧版 tex の番号

referee は submission PDF の番号で書く。 merge/restructure した改訂版とも、 古い source tree の section 構造とも一致しないことがある。 照合時は **番号でなく内容 (= keyword)** で旧版該当箇所を特定する。 submission PDF が repo に無い場合は旧版 tex を内容 grep で辿る (= §1 reflex の旧式番号確認と同じ手法)。

<a id="exact-numbers-per-version"></a>**番号そのものが要るとき** (返答書で「旧 (N) は今の (M)」 と書く・約束の照合 = 下の [#promised-edits-check](#promised-edits-check)) は、 各版の source を一時 dir で組んで読む。
label のある式・図・節 = `.aux` の `\newlabel`。 文献 = `.aux` の `\bibcite` (引用順の bst では、 前の方に引用を 1 本足すと後ろの番号が全部ずれる)。 label の無い式 = 一時の写しのその式に `\label` を差して組む (原稿は変えない)。
組んだ番号は、 相手が読んだ PDF の文字層とも突き合わせる (同じ頁にその式番号がある・文献番号の項の著者が key と合う)。 突き合わせには、 番号を全部ずらした写しで食い違いが出ることを foil に置く。
構成を変えていなくても番号はずれる: 前の式の 1 行を番号なしにしただけで、 後ろの式番号が全部 1 つずれた (実測)。
まだ当てていない改訂 (足す予定の引用) で番号がどう動くかも同じ手で測る: 写しに案の `\cite` を差して組み、 `.bbl` の `\bibitem` の順 (または `.aux` の `\bibcite`) を読む。 次の便で referee が挙げた番号を「旧 N は今の M」 と書くのに要る。
置き場所の候補ごとに組む: 同じ引用でも、 脚注に置くか本文に置くかで間にある別の引用との前後が入れ替わり、 番号が 1 つ動いた (実測)。 写しを組む script は提案の記録の隣に置く (番号の根拠を再現できるように)。

## 実例 (= 該当 private paper repo、 2026-06-02)

2 本の原稿を統合した major revision で、 数十の referee comment に point-by-point 回答。 §1 reflex (= 本文 grep 照合) で **2 件のズレを発見・修正**:
- 「the unsupported sentence has been removed」 ← 実際は根拠を追加して justify した (= 削除でなく根拠追加)。
- 「a reference … has been added」 ← 実際は旧版から `\eqref` で既に参照済みだった (= added でなく対応済み)。

両方とも task tracker の記録ベースで回答を書いたために発生。 残りの Response は検証可能 claim (= 用語置換 / 削除 / 引用 + 質的な項目) が全て本文と一致。 → **教訓: rebuttal は最初から本文 grep で書く (= 記録ベースは removed/added が本文とズレる)、 §1 reflex を最初に回せば 2 件を未然に防げた**。

## <a id="defensive-revision"></a>reject 後の誌替え再投稿: 防御改訂の 3 検査 (2026-08)

rebuttal を書かない誌替え再投稿 (= reject 済み原稿を修正して別誌へ) で、本文に claim・引用・修正を足すときの検査 3 点。いずれも 2026-08 の実例 (reject 後の共著論文の再投稿) で発火した。

1. **断言 framing 検査**: 足す文が「予言 + 精密実験の制限」型の量的主張なら、referee がその場で back-of-envelope できるかを自分で先に計算する。安全に通過すると示せない (= 見積もりが現行 bound と同 order 以下にならない) 制限は断言せず、**test/example framing** (「can be tested by ...」の例示) に落とす。新規主張ゼロで引用は復活でき、攻撃面を作らない。
2. **修正の 2 次露出 sweep**: 表記・整合性の修正 (例: 未定義記号をただしい結合定数に relabel) が、それまで曖昧さの陰に隠れていた本文内矛盾 (= 図の使用パラメータ vs 本文の許容域、など) を**露出させないか**を突き合わせる。露出するなら、力学の駆動変数を特定して scaling で読み替えられないかをまず調べ、成立するなら caption/本文の 1 文で先回りして塞ぐ (= 数値の再計算より先に構造を疑う)。
3. **査読実績の照合**: 「referee に突かれうる」と主張・対策する前に、過去の report 群を機械照合 (grep) して**実績あり (= 対応必須) と純予防 (= 入れ得だが optional)** を区別し、その label 付きで判断者に提示する。予防コストの妥当性は実績の有無で変わる。

関連: 依頼側の縮小原則 = [`research-email.md #shrink-the-ask`](research-email.md#shrink-the-ask)。

> **姉妹**: 系譜 (= どの版か) と防御改訂 (= どう書くか) の手前に、 **中心主張がそもそも成立するか**の検算がある — [`paper-audit.md#headline-claim-budget-check`](paper-audit.md#headline-claim-budget-check) (= 模型の形式に依らない収支で 2〜3 行。 再投稿の直前に中心主張が収支で不成立と判明した実例)。

## <a id="manuscript-lineage-verification"></a>改訂に入る前の系譜検証: 「手元の最新」 を疑う 3 検査 (2026-08-21)

reject 後の改訂や誌替え再投稿の準備で、 **土台にした版が共著者合意済の最新でなかった**事故の再発防止。 共著論文では「最後に自分が受け取った添付」 ≠ 最新 (自分が cc 外だった期間の改訂、 別の共著者が投稿システム向けに変換した版、 など) が普通に起きる。

1. **系譜表を作る** — 投稿ごとに (日付、 投稿者、 source の所在、 語数、 識別 keyword の有無) を 1 行ずつ並べる。 **語数・keyword は単調でなければならない** (改訂を重ねた版が大幅に短くなる、 referee が褒めた framing の語が消えている = 土台の取り違えの signal)。 referee report が言及する語句が原稿に無ければ、 その report が読んだ版を持っていない。
2. **cc 外期間を列挙する** — 共著者間 thread で自分が外れていた期間の版は「手元に無い」 と仮定し、 投稿者に source を直接要求する (投稿システムの proof PDF だけでは source は復元できない)。
3. **referee が名指しした文を grep する** — 過去 report が名指しした句が改訂版に原文のまま残っていないか機械照合。 残っていれば「直した」 認識が誤り (= 別の版を直した) か、 修正が取り込まれていない。

**図の再現性** — 数値図は「本文の式 + caption のパラメータ」 から再計算して照合する (= [`scientific-computing.md #figure-vector-extraction`](scientific-computing.md#figure-vector-extraction))。 caption のパラメータで再現できない図は、 作図 code が別の式・別のパラメータを使っていた signal で、 referee に突かれる前に著者間で決着させる。

## <a id="deferred-check-reserve"></a>「検証済みだが companion 送り」 の cross-check は、 構造的境界で閉じる部分を本稿に印字し、 残りを response letter の予備として持つ (2026-09-08、 2026-09-09 改訂)

**Pattern**: 本稿の主張を支える cross-check (例: 別 sector の恒等式を多成分で機械検証) を、 その閉形式ごと companion に送って本文は「検証した、 詳細は Ref. [x]」 だけにすると、 referee は「検査可能な式が本稿に無い」 と突く。 このとき 4 手がある: (i) companion を先に (同時に) 公開して引用を checkable にする / (ii) 本稿は現状の正直な scope のままにし、 恒等式と検証 artifact を response letter の予備として手持ちにする (求められた時だけ付録化) / (iii) 主張を検証済み sector に絞る (真の主張を弱める) / (iv) 恒等式のうち印字済みの量だけで閉じる部分 (例: 最低次の接触項) を印字する。

**Rule (2026-09-09 改訂)**: 既定は (ii) と (iv) の併用、 companion が近ければ (i) を重ねる。 **(iv) の可否は「印字済み量だけで閉じる部分」 の切れ目が構造的境界かで決まる**。 切れ目が「どの振幅が入るか」 で決まり (例: 最低次の恒等式には異なる sector を混ぜる振幅が入らない = 背景の対称性がその次数の混合項を作る定数 tensor を許さないので、 混合項は次の次数から)、 本稿と companion の sector 分担線に一致するなら、 (iv) は fig leaf にならない。 その場合の書き方 = ① 恒等式**全体**を Γ レベルで display する (混合項は記号だけ、 値と規約辞書は companion) ② 印字部分は loop 計算の check として 3 拍 (何が決まるか / 調整余地なし / 一致した値) で書き、 機械 anchor (印字式からの audit script) を残す ③ 残りは「混合振幅が入る次数」 と名指しして companion へ送り、 検証範囲 (成分数・generic q・pole) を明記する。 切れ目が展開の途中の恣意的な打ち切りなら「自明部だけ印字して非自明部は次の論文」 に見えて「残りも出せ」 を誘うので、 (iv) は避けて (ii) だけにする。 (ii) の条件 = 本文の文が「係数決定には使わない cross-check」 のように主張の重さを既に限定していること、 材料 (note + 機械検証 script) が即座に出せる状態にあること。 ⚠️ 「既に本文で示した別の結果の言い換えだから印字する価値が無い」 は却下理由にならない — Ward–Takahashi 恒等式は誘導作用への制約でなく loop 計算の check で、 印字済みの別の対称性の恒等式も同じ立場 (誘導作用が共変なら自動) にある。 検査可能な式がゼロの現状が floor で、 恒等式と閉じる部分の印字は checkable 量を単調に増やすだけで、 referee の要求はそれ以上強くならない。

起源 = 第 2 ラウンドの AI 査読 (ある恒等式を本稿でどこまで示すか)、 著者裁定「(ii) でいこう」 → **後日、 著者が (iv) を再提起して採用** (趣旨: 全く書かないのは有り得ない、 閉じる次数だけ書いて残りを次の論文に回すのが、 何もしないより悪いことは無い)。 印字式からの実測で、 閉じる次数が構造的な境界と判明し、 付録 (導出) + 本文 (最低次の形) に印字、 audit script が anchor。 ⚠️ meta: 前日版の rule「(iv) は罠」 は単一 instance の referee 心理推測をその日のうちに層1 へ hoist したもので、 後日の first-principles 検算で反転した。 一般則の hoist は instance が settle してから (= 著者が採否を実際に運用した後)。 sibling = [`paper-audit.md#claim-strength-three-tests`](paper-audit.md#claim-strength-three-tests) (言明の強さ)、 [`#defensive-revision`](#defensive-revision) (断言 → test framing)。

## <a id="ask-editor-second-referee"></a>不採択の直後に編集者へ出す 1 通: 第 2 referee を頼む

report が 1 本で、 その中の具体的な主張が原稿で確かめられる誤読のとき、 誌替えの前に担当編集者へ返信で第 2 referee を頼む。 正式 appeal ではない。

- **段を分ける**: 例 = APS (Physical Review) は公開の規程で 3 段 (journals.aps.org/authors/editorial-appeal-procedures)。 (1) 担当編集者への再考依頼 (慣行) (2) 正式 appeal = Editorial Board の 1 名が記録を見て助言、 著者は適任・不適任の member を挙げられる (3) 手続きの公正さだけを見る最終段。 最初の 1 通は (1) だけにし、 (2) の候補名は返事を見てから使う。
- **読み手は専任の編集者**: 多くの誌の associate editor は研究歴のある専任職で、 その分野の現役研究者ではない。 物理の優劣は判定できないので、 技術語・節の列挙・関連文献の比較を並べても説得にならない。 書くのは 3 つだけ:
  1. 編集者が原稿を開いて 1 分で確かめられる事実 (例 = 「report が挙げた文献を、 本稿は付録の照合でだけ引いている」)
  2. 誤読を平易に言い切る 1 文 (例 = 「report はその照合を本稿の結果と読んだ」)
  3. 本稿の結果が何かを 1 文
- **report の文は限定まで verbatim で引き、 限定ごと答える**: "see Refs. X, for example" なら、 例を崩すだけでは「many papers」 の本体が残る。 「挙がったのは X だけ / X は照合で引いた / 近い先行研究の一覧と違いは §N に書いた / report は他を挙げていない」 の形で本体に答える。
- **頼み方**: 第 2 referee の分野を 1 句で指定する。 report が挙げた文献の著者本人を候補に挙げると、 自分たちの読みへの自信として効く (その人が当の referee でも、 自分の論文との違いは当人が判断する)。
- **文体**: 簡潔・平易・論理的。 1 段落 1 主張。 読みにくい英文 (主語が抽象名詞の受け身、 "questions no equation" のような詰めすぎた言い方) は短い普通の文に言い直す。 冗長の差し戻しが続いた (実測) = 初稿から絞る。
- **共著者に「appeal は効かない、 誌替えが安い」 と言われたら**: これは正式 appeal でなく 1 通であること、 費用は書き終えた 1 通だけであること、 期限 (例 = 3 週) を切って動きがなければ誌替えに移ることで答える。 決めた人たちの連名で「こう決めた、 今日中に異論が無ければ出す」 の形にする。 誌替え先の cover letter にも同じ線引きを入れる (同じ referee に回ることがある)。
- **予防 (原稿の側)**: 古典的な文献との一致を付録で確かめると、 その付録が主結果と読まれることがある。 照合のための引用は「照合のため」 と本文に明示し、 序論で既知との線引きを 1 文で言う ([`paper-audit.md`](paper-audit.md) の主張の配置の検査)。
- 他人の mail client から送られる文面の非 ASCII = [`paste-destined-plain-text.md#non-ascii-via-other-client`](paste-destined-plain-text.md#non-ascii-via-other-client)。

## <a id="reconsideration-reply"></a>編集者が再審を許したあとの返答書: 一問一答・原稿は最小・同じ referee が読む前提

不採択の後に編集者が「referee の反論への詳しく collegial な返答があれば再審する」 と返したとき、 referee に転送される返答書の書き方。
report が修正を求めず新規性だけを否定している場合を想定する (修正の要求がある report は上の 6 reflex)。

- **同じ referee が先に読む前提で書く**: 「referee に転送できる形で」 という編集者の依頼は定型で、 referee の交代を約束していない。
  中身は固く、 口調は友好的にする。 友好的で論理の固い文は新しい referee にもそのまま効き、 敵対的な文は同じ referee には逆効果 = 失うものが小さい側を取る。
  分野を指定した referee の依頼は編集者だけへの欄に書き、 頼みは 1 つにする (「その分野の referee に評価してほしい」 まで。 「今の referee に加えて、 または替えて」 のように選択肢を文末に並べると、 どちらを望むか決めかねているように読める = 残すか替えるかは編集者が決める)。 新しい referee には今の report とこちらの返答も見せるよう頼む (判断の材料になる)。
  その欄で、 認めること (例: 個々の係数は既知) と主張すること (例: 計算した対象は新しい) を並べるときは、 両方が同時に成り立つ理由を 1 段ずつつなぐ: 相手の計算は何を変数にして何をしたか → 認めることはその計算から分かる (原稿のどこが照合しているか) → こちらの結果 (対象と確かめた恒等式) は相手の論文に無い (本文で確かめた範囲で。 「その計算には現れない」 は変数の取り方の論拠になり成り立たないことがある = 下の "for example" の行)。 専門外の編集者は、 並べただけの 2 文の関係を補えない (実測)。
- **原稿の変更は最小にする**: 求められていない変更を入れると、 その分だけ指摘が正当だったように読める。 返答は原稿の既存の文 (節・付録・表) を指して答え、 「新しい版ではこう書いた」 を約束しない。
  投稿画面が新しい原稿を必須にするなら、 小さな誤りの訂正と記号の統一だけを入れ、 その一覧は referee 向けの返答書に置かず、 編集者だけへの欄に事実だけで書く (何を外した・何を直した。 訂正の理由の物理を限定句つきで語らない = 1 文で論理が閉じない)。 式番号がずれるなら返答書の冒頭に 1 文で、 何番以降がいくつずれたかだけを書く (ずれていない番号の種類と、 ずれた原因の表示は書かない = 原因は編集者だけへの欄の変更の一覧が持つ)。 ずれの範囲は、 両方の版を組んで全 label で確かめる = [`../scripts/tex-label-shift.py`](../scripts/tex-label-shift.py) (投稿版の PDF が手元に無くても、 git の commit から組む)。
- **一問一答で短く**: report の文を全部 verbatim で引き、 各点に 1〜数文で答える。 書けば書くほど、 指摘が正当だったように見える。
  点は report の文の組ごとでなく、 反論ごとに切る (論文を要約する文は、 その後に続く「新しくない」 の前置きなので同じ点に入れる)。
  点を併せたら、 2 つの答えの文を並べ直すのでなく、 論理の線を 1 本に組み直して文の数を前後で数える (並べ直しただけの答えは、 併せる前より長かった = 実測)。
  推薦・判定の文 (「掲載を勧めない」) は反論でないので点にしない: 引用して、 見出しの無い短い結び (その推薦が立つ見方 → どの点がそれに答えたか → その上で再考を) にする。
  語数は引用を除いた自分の文で前後を記録する = [`../scripts/letter-word-count.py`](../scripts/letter-word-count.py) (`--quote-env` に引用の環境、 `--git-rev` に直す前の版。 referee の文を環境で囲まず `\R` のような macro の後に置く雛形は `--quote-macro R --part-macro A` = referee の文を引用に数え、 答えごとの語数も出る)。
- **書き出しで同意しない**: 「Correct.」「Agreed.」「The summary is accurate.」 で始めると、 その点を譲ったように読める。 自分の主張で始め、 report の記述は「…, as the report describes」 のような従属句で受ける (次の文で、 その対象が新しいと短く言い切る)。
  report が原稿の主張していないことを否定しているときも、 「原稿はそれを新しいと言っていない」 を主語にして書く (相手の誤読を主語にしない)。
- **結びで譲歩しない**: 「指摘してくれれば喜んで削る」 は弱い。 かといって「失わずに削れる部分は見つけていない」 のような削らない宣言も、 優先順位を付ける気が無いと読まれる (実測)。 長さの点は下の行のとおり、 主結果の読みと読み方の案内で閉じる。 文献の招き (「他に計算した仕事を知っていれば引く」) は新規性の点に 1 回だけ置く。
- **長さの指摘 (「N 頁で書ける」) には、 長さでなく主結果の読みで答える**: その指摘は、 論文の主結果を何と読んだかに立つ (帰結だけが新しいと読めば N 頁に収まる)。 主結果は何か → 帰結はそこから出る → N 頁に入るのは帰結だけ → 主結果は新しい (新規性の点を指す) ので検証できるよう全部示す → 復習の部分は原稿がそうと明記していて、 既知の読者は飛ばせる、 の一直線で書く。 「report は〜と言う」 を主語にした文を途中に挟むと、 報告の見方とこちらの主張を行き来して読みにくい (実測)。 「どこを削れるか report は示していない」 は、 長さの懸念を述べるのに個々の削除を挙げる義務は無い、 と返される (実測)。
- **原稿の自己記述は切らずに引く**: 序論の「新しい結果は §X と、 それを支える付録にある」 を「新しい結果は §X にある」 と途中で切って引き、 付録を「結果ではない」 と言うと、 序論 1 行で反証される (実測)。 付録の役割は中身で言う (「標準の方法で既知の係数を独立に再現した照合」)。
- **"for example" の反論は種類全体で、 事実だけで**: 挙がった例を崩すだけでは「many papers」 が残る (上の [#ask-editor-second-referee](#ask-editor-second-referee))。
  種類全体に効く答えは事実で組む: こちらが何をどの理論で計算したか (対象・成分・確かめた恒等式) / 挙がった文献が何を変数にし、 何を計算したか (本文で 1 本ずつ読んだ範囲。 束ねる動詞は全部に当てはまるものを選ぶ) / この対象を計算した論文を知らない (名指しがあれば引く)。
  ⚠️ 「相手の変数には X が現れない」「相手は X を量子化しない、 こちらは量子化する」「どの計算でも同じ」 は論拠にしない: その一ループに X の内線が無ければ、 こちらの量は相手の汎関数の X についての変分で、 連鎖律から出る ([`paper-audit.md#novelty-from-variables-or-identities`](paper-audit.md#novelty-from-variables-or-identities)、 実測)。 「恒等式を確かめた」 も同じく論拠にならない (同じ節)。
  ⚠️ referee が問うていない「2 つの量の関係」 を認める文は足さない (答えが弱くなる = 実測)。 問われたら、 原稿の導出の節 (こちらの量から結果を組んだ節) を指して答える。
  「report も挙げていない」 は付けない (印字の有無の争いに移り、 重要性の反論に答えない = 実測)。 返答書の地の文に「X は例である」 のような議論の手続きの語りを持ち込まない (推敲の会話の流れの語が文に残った形 = 読み手には不自然)。
- **非母語の読み手に通じる平易さ**: 共著者と referee の多くは英語の非母語話者。 名詞の動詞用法 (「the summary names X」)、 口語の句 (「as much」)、 指示先の曖昧な語 (「the rest」)、 切り詰めた言い方 (「and we see none」) を避ける。 動詞は say より state / specify。 1 文に主張 1 つ、 式番号の尾を長く引かない。
  文が短くても通じない形 (抽象的な述語・名詞句が運ぶ判断・同格の挟み込み・圧縮した否定の並列・文末の選択肢) と直し方 = [`writing-discipline.md#short-but-unreadable`](writing-discipline.md#short-but-unreadable)。 返答書は全文の長さが 30 語以下でも、 この形で何度も止まった (実測)。
- **完成稿は更の目で読み直す**: 何十回の直しの後は、 会話で使った語・論点の名前が文に残る。 最後に原稿を見ていない読み手のつもりで頭から読み、 論理の流れだけを追って整える。
- 編集者だけへの欄の文は ASCII で ([`paste-destined-plain-text.md#non-ascii-via-other-client`](paste-destined-plain-text.md#non-ascii-via-other-client))。 返答書は PDF (上の「構造」)。

## <a id="promised-edits-check"></a>査読の外で約束した修正の照合 (preprint を読んだ人への返信)

preprint を読んだ人への返信で「本文に明示する・引用する・図に足す・別途確かめる」 と書いたら、 改訂・投稿の前に、 その約束が原稿に入っているかを確かめる。 §1 と同じく、 記録でなく本文で照合する。

1. **約束は送った mail の文面から 1 件ずつ拾う** — 下書きや内部の要約から拾わない。 内部の要約は約束を数え落とす (実測)。 下書きと送信版の違いも 1 文ずつ見る。
2. **外への約束と、 共著者の間の方針を分ける** — 送った文に無い書き換え (主張の範囲を絞る、 など) は外への約束ではない。 照合の表には両方を並べるが、 「約束を守っていない」 と書くのは前者だけ。
3. **版ごとに 1 対 1 で照合し、 約束より前の版を foil にする** — 相手が読んだ版では「無い」、 約束を入れた版では「有る」 と出なければ、 照合が区別していない。 照合は script にして、 相手が読んだ版・投稿版・いまの原稿・改訂案の全部に回す。 番号は上の [#exact-numbers-per-version](#exact-numbers-per-version)。 改訂案が著者への注の中で置き換えた旧文を引用しているなら、 注の中身を除いてから照合する (旧文を本文と取り違える = 実測)。
4. **改訂案が約束を当てた文を書き換えるとき** — 文字どおり保たれるか、 中身で保たれるかを分けて書き、 判断を著者に渡す (例: 明示すると約束した仮定が、 書き直しで要らなくなって消える)。 返答書や相手への連絡で触れるかも著者が決める。
5. **送った後の相手の再返信を拾う** — thread の記録が最初のやりとりで止まり、 こちらの返信への反論が記録に入らないことがある (実測)。 照合のときに、 返信を送った thread を差出人で 1 回引く。
6. **新しい査読の指摘と重なる文に印を付ける** — 約束した引用の整理 (誰を先行として引くか) と、 査読の新規性の指摘 (既存の文献との違い) は、 同じ文 (「先行文献では明らかでなかった」 型の主張) に効く。 主張の範囲を絞る案は、 査読が既知と言う所に主張を寄せることがある = 印を付けて著者の判断に渡す。

## <a id="condensing-a-reply"></a>返答書の答えを縮める書き直し: 主張の対応表・引用を含む語数・参照は要の 1 つ

返答書の答え (記入例を含む) を、 中身・裁定・数値を変えずに簡潔・平易に、 論理の流れを追いやすく書き直すとき。 縮めるほど、 限定が落ちる・主張が強まる・裁定で入れると決めた文が消える。 どれも新しい文だけを読み返しても見えない。

1. **元の文の主張を 1 つずつ並べ、 書き直した後の置き場所を表にする** — 列 = 元の主張 / 新しい文のどこ / 落とした・変えた理由。 落とせるのは、 別の答えか引用した原稿の文が同じことを言うもの、 番号を語に置き換えたもの、 主張を狭める向きのもの。 限定 (up to factors of order unity や to leading order のような句) と、 裁定や共著者の規則で入れると決まった文は落とさない (後の指示が簡潔さを求めたときは 6)。 理由の欄を書けない行が残ったら縮め過ぎ。
2. **語数は引用を含む数と含まない数を両方書く** — 道具 = [`../scripts/letter-word-count.py`](../scripts/letter-word-count.py) (組んだ返答書の `.tex` に当てる。 referee の文を macro の後に置く雛形は上の行の `--quote-macro`)。 依頼者が示した「今の長さ」 が引用を含む数と合うなら、 求められた長さも引用を含む数と読む。 原稿の変更 (概要の文・足した段落) を引用する答えでは、 引用と地の文が同じ中身を 2 回言う。 求められた長さに収まらないときは、 どの段落がどの裁定・限定を運ぶので削れないかと、 引用を外して所在だけを書く案を依頼者に出す (引用を外すと referee は新しい版を開かないと文を読めない = 採るかは依頼者)。 裁定で入れると決めた文と引用だけで、 求められた長さに収まらないことがある (実測)。
3. **参照は 1 文に要の 1 つ** — 1 文に式・節・文献の番号が 3〜4 個挟まると、 論点の筋が細部に埋もれる。 理由は語で言い、 番号は読み手が開かないと主張を確かめられない所だけに残す。 外した番号は対応表の理由の欄に書く (根拠を後から辿れる)。
4. **1 段落 1 論点で、 1 文目にその段落の結論** — 論点の順を先に決めて段落を 1 つずつ置く (独創性を問う指摘なら、 例えば 既知を認める → 新しい点 → 挙がった文献の前提 → 自分たちの先行研究 → 原稿の変更)。 別の答えで言った結果は言い直さず、 その答えを指す 1 句にする。 括弧の言い換えと「i.e.」 の重ねを外す。
5. **縮めた文を組んで確かめる** — 番号と記号の検査を通し直す。 列挙を 1 項目 1 行に収めるといった組版の指定は、 組んだ PDF の行で判定する ([`latex.md#rendered-line-count`](latex.md#rendered-line-count))。 答えの中で引用した原稿の変更の文と、 原稿の変更の案の文が一字一句同じかを機械で照らす (片方だけを直すと食い違う)。
6. <a id="condense-second-pass"></a>**言い回しを縮めた後も「くどい」 と言われたら、 文ごとに答えに要るかを問う** — 中身を変えない書き直しは、 言い回しと番号の分しか短くならない (実測)。 次の段の基準: 各答えの 1 文目で問いに答え (同意する・どう直したか)、 その後に置くのは答えを支えるのに欠かせない根拠だけ。 落とすのは、 読み手が既に知っていること (原稿の説明の言い直し、 読み手自身が挙げた文献の中身の説明)、 原稿の 1 か所を指せば済む説明、 答えが成り立つのに使わない数値・番号・他の論文の節の名前、 別の答えが言うこと。 前に「入れる」 と決めた任意の文も、 後の指示が簡潔さを求めていれば落とす候補になる。 書かないと決めたこと (禁止の側) と主張の限定は残す。 落とした文は元の文のまま、 種類と理由を添えて一覧にし、 決めた人が 1 文ずつ戻せるようにする。 残した文には、 消すと答えのどこが崩れるかを 1 行ずつ書く (書けない文は落とす候補)。 自分たちの先行研究の文は、 消すと新しさの主張が強まるので残す。 原稿の変更の引用を所在の 1 文に替える (2 の案) なら、 5 の一致の検査は消さず、 「引用が無いときは所在の 1 文があるか」 を確かめる形に直す。 引用を外して変更の中身を地の文で言い直すときは、 原稿の文の強さを変えない (原稿の文に無い「だけ」「必ず」 を足さない)。 複数の文献を 1 つの引用にまとめて縮めるときは、 1 本だけの発見を全部に帰さない (「そのうち 1 本が」 と書く)。 表裏の 2 文 (「X なら A、 X でなければ B」) を 1 文にまとめるときは、 原稿の式が排他 (どちらか一方) か加算 (B は常にあり、 X で A が足される) かを先に確かめ、 動詞をそれに合わせる (加算の式を「X でなければ B」 と書くと、 X のときに B が消えると読める = 実測)。 読み手の読みの逆転は、 読み手の文を引き直さずに「X が与えるのは A で、 B ではない」 の 1 文で言える。

## <a id="per-sentence-reply"></a>referee の文ごとに答える形に組み直す: 切り方と、 置き直した文の一致の照らし

referee の段落を 1 文ずつ引いて直後に答える形 (一問一答をさらに文で切る形) に組み直すとき。 既にある答え (共著者が書いた文を含む) を新しい形に置き直すので、 途中で文が欠ける・言い換わる・順が入れ替わる。 新しい版だけを読み返しても見えない。

1. **切り方と番号を先に決める** — 主張を含まず次の文を導くだけの前置きの文は、 次の文とまとめる。 同意だけで済む文を分けるか次の文とまとめるか、 番号を返答書の通し番号にするか段落の番号の下の枝番にするかは、 書く人たちが答えを書く前に決める = 後で変えると引用と答えの両方を動かす。
2. **置き直した文を機械で照らす** — 言い換えないと決めた文 (共著者の答え) は、 空白をそろえた元の答えを置き直す単位 (文の塊) に切り、 (a) 各塊が新しい版に一字一句同じで 1 回ずつ、 元と同じ順にあるか (b) 塊を並べると元の全文になるか (欠け・余り) を数える。 引いた referee の文も、 (c) どれも元の段落の部分文字列で、 並べると元の全文になるか (落とした文・足した文) を数える。 改行の位置の違い・1 語の脱落・引用符の付け替えは目では見えない。 照らす script は、 空白をそろえて部分文字列を数える短いもので書ける。
3. **置き直す文の中に referee の文の引用があると、 新しい形では直上の引用と重なる** — その文を書いた人の文なら置き直す側は変えず、 重なりと (あれば) 引用の字面と原文の違いを書いた人に知らせる。 縮めるかは書いた人が決める。
4. **元の答えが触れていなかった文に答えを足すときは、 土台を答えごとに書く** — 文で切ると、 元の答えが答えていなかった文 (前提の確認・譲歩) が空いて見え、 書き手が自分の説明で埋めがちになる (実測)。 足すなら共著者のメモや裁定を土台にし、 土台の無い説明は足さずに書く人たちに問う。 土台 (どのメモの何項・どの裁定) は答えごとに方針の表か記録に残す = 検収で、 新しい文と元の文・土台を 1 対 1 で突き合わせられる。
   <a id="coauthor-will-rebuild"></a>**共著者が自分で組み直す・書くと言った答えは、 こちらで組み直す前に、 その人に 1 行で聞く** — 共著者が自分で組み直すと言った部分を、 こちらの案で作り直すと、 共著者の文を切って間に文を入れた版が先に届き、 共著者はそれを退けて自分で書き直す (実測)。 聞く間はその部分の案を止め、 ほかの部分を進める。 会議の最中で直接聞けないなら、 その場にいる著者に伝言を頼む。 依頼した著者が「それでも作って」 と決めたときは、 共著者の文の塊は切らず、 足す文は塊の外に置き、 送り状にそう書く (塊の間に文を入れると文意が変わりうる = [#do-not-say-unchanged](#do-not-say-unchanged))。 ここと 6 の「塊」 = 共著者が 1 つの答えとして続けて書いた文のまとまり (2 の照らしで切る単位とは別。 1 文ずつに切っても、 その間は塊の外にならない)。 共著者がそう言ったことは方針の「決めてもらうこと」 に問いとして入れ、 方針を何人かに並べて書かせたなら集約で落とさない ([`multi-session-coordination.md#parallel-collation-table`](multi-session-coordination.md#parallel-collation-table))。 既存部分を直す了解の一般則 = [`shared-repo.md#primary-author-consent`](shared-repo.md#primary-author-consent)。
5. **答えのラベルは、 比べる形のどれでも同じ文字が同じものを指すように選ぶ** — 段落の形で R = referee の段落、 一文の形で R = 答え (Response) にすると、 書く人たちのやり取りで同じ文字が二通りの意味になる (実測)。 一文の形は referee の文を C (Comment)、 答えを A (Answer) にすると、 段落の形 (R / A) と A の意味がそろう。 番号は macro の引数で振り、 本文に手で書かない。
6. **置き直した後に、 前を受ける語が直前の文を受けているかを読む** — 文を別の文の下に移すと、 「also」「this」「In addition」 のような前を受ける語が、 移した先の直前の文を受けなくなる。 上の 2 の照らしは字面の一致しか見ないので、 ここは人が読む。 逆向きの読み違いもある (実測: 共著者の文の前を受ける語が受け先を失ったと読み、 足した段落を共著者の 2 文の間へ移したが、 元の並びではその語は直前の共著者の文を受けていた = 移した段落が共著者の文の続きを切った。 共著者は、 その段落が問いへの答えになっていないこと、 文の間に文を入れたのに変えていないと書いたことを指摘した)。 受け先を失ったと読んだら、 動かす前に、 足した文を外した元の並びで読み直す。 直すときは共著者の文を変えず、 新しく足した文を共著者の文の塊 (4 の [#coauthor-will-rebuild](#coauthor-will-rebuild) の定義) の外へ動かす。 塊の間に入れたいなら、 その文を書いた人に先に聞く (間に入れると文意が変わりうる = [#do-not-say-unchanged](#do-not-say-unchanged)、 主筆の既存部分を直す了解 = [`shared-repo.md#primary-author-consent`](shared-repo.md#primary-author-consent))。

## <a id="inline-quotes-under-block"></a>referee の段落を残し、 答えの中で 1 文ずつ色付きで引いて答える形

一問一答の referee の段落は原文のまま残し (上の 5 のフル引用は段落が持つ)、 その下の答えの中で referee の文を 1 つずつ色付きの段落の引用 (`quote` 環境に色) で引いて、 直後に答える形。 段落を文に切って交互に置く形 ([#per-sentence-reply](#per-sentence-reply)) と共通の決め事 (前置きの文はまとめる・置き直す文と引いた文を機械で照らす・共著者の文の中の引用との重なりは書いた人に知らせる・空いた文に足す答えの土台) はそちらに従う。 この形で加わるのは次の 3 点。

1. **答えの中の引用の字面を、 書く前に著者に決めてもらう** — referee の文献番号 (「their Ref. [N]」) と URL を引用に残すと、 返答書が自分の文献表 (`\cite`) を持つとき、 すぐ下の答えの番号と 2 通りの番号が並ぶ。 残すか `\ldots` に置き換えるかは著者が決める (段落の側は原文のまま)。 引用の中のほかの字面は原文どおり (誤植も原文のまま、 中の二重引用符は一重に)。
2. **引いた文には必ず答える** — 答えの無い引用は、 引かなかった文より目立つ。 同意だけの文も引くなら、 短い答え (1 文) を付ける。
3. **`\ldots` を含む引用は、 切れた片ごとに照らす** — 各片が同じ論点の referee の段落に順に現れるかを数える (一重引用符を二重に戻してから)。 1 語を変えた写し (foil) が落ちることも 1 回確かめる。

2 つの形を両方作って比べるときは、 中身を同じにして並べ方だけを変える = 形ごとに答えを足したり減らしたりすると、 形の比べと中身の比べが混ざる。

## <a id="answer-fit-check"></a>書き終えた返答書を出す前の照らし: 段落ごとに答えになっているか、 と「変えていない」 と書かないこと

返答書をどの形 (段落の形・[#per-sentence-reply](#per-sentence-reply) の文ごとの形・[#inline-quotes-under-block](#inline-quotes-under-block) の色付きの引用の形) で書いても、 共著者や編集者に出す前に当てる。 文で切る・置き直す・答えを足すうちに、 段落が直前の referee の問いに答えず、 前の段落の説明の続きや隣の論点の話になる (実測)。 書き手は各段落を置いた意図を知っているので、 読み返しても噛み合っていない段落を意図どおりに読む。 [#per-sentence-reply](#per-sentence-reply) の 2 の照らしは字面が同じかを見るだけで、 答えが噛み合うかは見ない。 同じ問いを、 英文を書く前の方針にも当てる (書き手と別の vendor が書かずに方針を疑う段 = [`multi-session-coordination.md#write-one-doubt-one`](multi-session-coordination.md#write-one-doubt-one))。 その役は方針を読んでいるので、 下の 1 の批判役 (方針を知らない目) の代わりにならない。

1. **書き手とは別の agent に批判役を頼み、 段落ごとに判定させる** — 渡すのは返答書と referee の報告だけにし、 方針の記録や書き手の説明は渡さない (読むと書き手の意図で読む)。 段落ごとに要旨を 1 文に縮め、 直前の referee の文 (質問・指摘) への答えになっているかを「答えている / 一部だけ / 答えていない」 で判定させ、 答えていない段落には、 その段落が実際に何に答えているかを書かせる。 見るのは段落の結論の文が問いの形に合うか (例 (架空): 「この近似はいつ成り立つのか」 の下の段落が「この近似は広く使われている」 で終わると、 成り立つ条件を答えていない)。
2. **噛み合わない段落を直し、 直した段落をもう一度判定させてから出す** — 段落が共著者の書いた文なら、 書き手は変えず、 判定と理由をその文を書いた人に知らせる ([#per-sentence-reply](#per-sentence-reply) の 3 と同じ)。 段落・要旨・判定の一覧は検収に添える (直した前後を突き合わせられる)。 判定とその理由も仮説 = 出す前に、 他人の文の読みを含む判定の理由は原文と照らし、 照合票と一緒に見せる ([#pre-send-verification-sheet](#pre-send-verification-sheet))。 <a id="critic-verdict-cause-check"></a>**判定の理由にこちらの直しが挙がっても、 直しが原因とは限らない** = 直しの有る形と無い形の両方を同じ批判役に判定させ、 判定が直しに依るかを確かめてから扱いを決める (依るなら直しを直し、 依らないなら共著者の文として書いた人に知らせる = 上のとおり)。 実測: 理由に足した括弧が挙がったが、 括弧を除いた形でも判定は同じで、 理由は直しの外 (もとの段落の組み立て) にあった。
   <a id="critic-sandbox-copy"></a>**批判役に渡す写しは、 作業の場所の外に 2 file だけ置く** — 返答書の tex から comment を剥がした写し (ai-collaboration の `scripts/strip-tex-comments.py`、 剥がした後に `scripts/check-review-target.py` で comment 0) と referee の報告を、 作業ルートの外の空の dir に置く (作業ルートの中に置くと、 祖先の CLAUDE.md や隣の方針の file が批判役に届く = [`cold-eyes-isolation.md`](../../ai-collaboration/conventions/cold-eyes-isolation.md))。 剥がした写しを組んで、 本文の字が元と同じかを 1 回比べる (`pdftotext` の差 0)。 こちらの直しで 1 行に繋がった長い行が写しに残ると、 行の長さで直した所が見分けられる = 長い行は空白で折り返し (`\` の直後では切らない)、 同じ比べで本文の字が変わらないことを確かめる。 依頼の指示には、 読む file としてその 2 つを名指しし、 ほかの file・repo・履歴を開かないと書く。 掲示板で頼むなら `--review-target <写し>` を付ける (要約が査読に読める依頼は、 写しが無いと投稿されない)。 批判役を subagent で立てても、 依頼の全文と判定は記録に残す ([multi-session-coordination.md#subagent-work-on-record](multi-session-coordination.md#subagent-work-on-record))。 背景の subagent で立てるなら、 照らしは読むだけの形で頼む (許可の確認で止まる = [multi-session-coordination.md#bg-subagent-blocked-on-permission](multi-session-coordination.md#bg-subagent-blocked-on-permission))。 判定の表は検収の記録にそのまま載せ、 書き手の見立てが違う所は別の表に書く (混ぜると、 方針を知らない目の判定がどれだったか分からなくなる)。 批判役は原稿を持たないので、 物理・数値・番号の正しさは見ない = 書き手の確かめは別に残す。 直して判定し直させるときは、 写しを差し替え、 同じ批判役に直した答えだけを判定させ、 1 回目の表は変えずに 2 回目を足させる (書き手は 1 回目の部分が変わっていないことを確かめる)。 実測: 方針を知らない批判役が、 書き手の見落とした段落どうしの食い違い (最後の一覧で「関係ない」 と呼んだ節を答えの根拠に使う、 下の [#unrelated-changes](#unrelated-changes) の 1) と、 書き手が足した文と冒頭の 1 文の食い違いを見つけた。
3. <a id="do-not-say-unchanged"></a>**他人の文を変えずに間へ文を入れると文意が変わりうる。 報告で「変えていない」 は使わない** — 共著者の文を一字一句残して置き直したとき・文と文の間に文を足したときは、 送り状や報告に「文は変えず、 〜と〜の間に〜を足した」 と、 足した文と場所を書く。 [#per-sentence-reply](#per-sentence-reply) の 2 の照らしが示すのは字面が同じことだけで、 文意が同じことではない。 間に入った文で前を受ける語 (同 6) や結論の文の受け先が変わると、 書いた人は自分の文が変えられたと読む (実測)。

## <a id="pre-send-verification-sheet"></a>共著者・編集者・referee に出す文の、 送る前の照合票: 受け手の目で原文と並べて読む段を、 検収の持ち主が持つ

**範囲**: 共著者・編集者・referee に出す文 (返答書のほか、 共著者への便・チャットの投稿・原稿や返答書への直しの案・送り状も入る) のうち、 (a) 直しの案 (他人の文・原稿・返答書をどう変えるか) か、 (b) 他人の文 (referee・共著者・文献) についての言明 (「X は … と言っている」「X の文は変えていない」「この段落は X の問いに答えている」) を含むもの。 日程・事務の連絡と、 頼まれた書類の送付のように他人の文に触れない便は範囲の外。 下の 1〜4 は組で当てる。

**なぜ** (この節を足した原因。 どれも実測):

- **検収の段はあったが、 検収の持ち主が自分で見たのは機械で数えられるものだけだった** (組版のエラー、 共著者の文が部分文字列として残っているか、 差分の印、 PDF の見え方)。 中身の読み (語の意味、 原文との一致、 「変えていない」 の主張の真偽、 直しの文) は批判役や worker に任せ、 その出力を確かめずに外に出す文に入れた。 共著者に出す文の検収で何を見るかが書かれていないと、 検収は数えられるものに縮む。
- **下請けの読みは、 言い換えを重ねると限定が落ちる。** 批判役の判定の理由・worker の要約・便の文・文面を簡潔にする書き直し、 と段を経るうちに「この一句は」 の限定が落ち、 鉤括弧つきの「X は … と言っているだけ」 になる (原文の主節が落ちた、 実測)。 どの段でも原文を開かなければ、 誰も気づかない。
- **送る OK は中身の検証にならない。** 本人に見せたのは送る文面と要約で、 原文と並べた表は無かった。 見せる側が「確かめました」「判定を受けた文と同じです」 と添えたので、 OK が検証済みの印に見えた。
- **受け手の指摘のたびにその次元だけの規則を足すと、 次の誤りは、 まだ規則の無い次元で出る** (実測)。 指摘を検査の項目に変換し続けても、 原文と並べて読む段の持ち主がいないことは変わらない。
- **差し戻された束の判定を引き継いだ。** 受け手が束を差し戻した後、 新しい窓が前の判定を「判定を受けた文と同じ」 として引き継ぎ、 同じ束から項目をそのまま出し直した。 差し戻しは前の検査が拾えなかった印なのに、 その検査を検証済みとして使った。
- **問われれば見つかる。** 本人に問い直された直後に、 書き手は自分の方針の穴をいくつも出した (実測)。 能力はあるが、 見せる前に自分から問う段が無い。
- **規則が有っても届かない・発火しない** (実測): 送る前の事実の確認の規則が名前でメールだけを指していると、 チャットの便や返答書の案を書く者はそれを読まない / 委譲の検品の規則が hash・build の再走の形で書かれていると、 文の読みの照合を含むとは読まれない / 新しい窓は project の規則の文書は読むが、 仕事を割り振る者の規則とこの規約は読まない / 第三者を名指しする文を一次記録と突き合わせる規則は、 発火の語 (誤り・訂正・批判) に当たらない要約では発火しない / 「並べ替えだけだから中身は変わらない」 の前提で検査を外す。 範囲を便の種類で書き (上の範囲)、 参照を各入口 (研究メール・委譲の検品・帰属・方針の原則・project の規則の文書) から張るのはこのため。
- **根**: 「受け手の目で、 原文と並べて読む」 段の持ち主がいない。 機械の検査は検収の持ち主が持ち、 意味の検査は批判役が狭い頼みで持ち、 批判役の出力を確かめる者がいない。 指摘はそのたびに批判役の検査項目か機械の検査に変換され、 持ち主のいない段は残る。 この節は、 その段の持ち主と形を決める (検査の項目を足し続けるのでなく)。

1. **照合票を作り、 送る文面と一緒に本人 (送る OK を出す人) に見せる** — 項目 1 行の表。 列 = (1) **原文** (referee の報告・共著者の版から script で写す。 手で写さない) (2) **こちらの文** (直しなら前と後) (3) **出した者** (批判役・worker・書き手・本人) (4) **照らしたこと** と結果 (意味が変わるか・比べる 2 語が同じ種類か・言い換えと原文の一致・「変えていない」 と書くならその単位 = 字面か文意か) (5) **照らしていないこと**。 表を埋めた後に、 書き手が「受け手はどこに突っ込むか」 を 1 回自分に問い、 出た穴を表の外に書く (上の「問われれば見つかった」 を、 問われる前に回す)。 本人の OK は表を見た上の OK になり、 OK が何を保証しないか (5 の列) が見える。 見せる文面に「確かめました」 を添えるなら、 何を確かめたか (4 の列) を指す。 照合票は file にして便の記録の隣 (project の repo の、 返答書・便の記録の場所) に置き、 名前を `send-sheet-<YYYY-MM-DD>-<便>.md` に揃える (揃えると使った便を数えられる = 下の「まだ機械にしないこと」)。
   - **作り手 = 検収の持ち主** (書き手に仕事を割り振り、 提出を受け取る者 = 指揮役)。 検収は持ち主の仕事なので、 照合票も持ち主が作る。 項目が多い便 (目安 = 10 を超える) は、 明示の基準に照らして読む下請けに下書きを頼む。 そのときも、 他人の文に触れる行 (1 の列と、 他人の文についての言明の行) は持ち主が全部原文と照らす。 下請けの「照らした」 は、 持ち主が原文と照らし直すまで 4 の列に入れない (下の 2)。
   - **5 の列 (照らしていないこと) と「記録が無い」 は、 その便の系譜の記録を引いてから書く** (同じ便や前の便の照合の file、 掲示板の thread、 会話記録、 repo の検査の記録)。 引かずに書いた不在は表に偽の空白を作り、 本人は既に照らした項目を照らしていないと読み、 回っていた下請けの照合を無いと読む (実測: 記録を引かずに書いた「無い」 と「照らしていない」 が、 どちらも既にある記録と食い違った)。 表の 5 の列は、 OK が保証しない範囲を本人に見せる列なので、 そこが誤ると本人は照らし直しを頼む先を誤る。
   - 費用 = 1 便あたり数分〜十数分。 送るのが遅くなる分は、 差し戻しの往復 1 回より小さい。
2. **下請けの「他人の文の読み」 は、 原文と照らすまで仮説** — 批判役・worker が出した referee・共著者・文献の文についての読み・要約・判定の理由は、 外に出す文に入れる前に原文と並べて照らす (一般形 = [`multi-session-coordination.md#delegate-output-inspection`](multi-session-coordination.md#delegate-output-inspection) の 3)。 入れるときは原文の語で引く。 **鉤括弧・引用符で括るのは原文の部分文字列だけ** = 言い換え・訳・要約は括らない (括ると、 読み手は原文の写しとして読む)。 文面を簡潔・平易に書き直す段でも同じ (書き直しは限定を落とす = 上の「なぜ」 の 2 つ目)。 1 本の批判役の判定は揺れる (同じ段落に、 別の回で別の判定が出た) = 判定も仮説で、 判定の理由が他人の文の読みを含むなら、 その読みも照らす。
   - **機械**: `python3 scripts/check-attributed-quotes.py --draft <送る文> --source <原文>` = 送る文の中で他人に帰した引用 (「…」 / “…” / "…" / ``…'' / "> " の塊。 帰属は同じ文の語 = referee・共著者・さん・と言う 等で見る、 人名は `--attrib` で渡す) が原文の部分文字列かを、 空白・改行・引用符を寄せて数え、 違うものを行で出す。 送信の道具は同じ検査を送る前に回す: [`scripts/discord-post.py`](../scripts/discord-post.py) と個人層の送信の CLI の `--quote-source <原文の file>` = 原文に無い引用があれば dry-run に ✗ が出て `--send` は止まる (承知で送るときは `--allow-unmatched-quote '<理由>'` で理由を残す)。 `--quote-source` が無いときは、 他人に帰した引用の件数を 1 行で知らせる (送る道具には、 どの file が原文かが分からないので止めない)。 送信の道具が見る帰属の語は既定の一覧だけ (人名を足すなら CLI の `--attrib`)。 寄せ方と限界の正本 = engine [`scripts/lib/attributed_quotes.py`](../scripts/lib/attributed_quotes.py) の冒頭。 LaTeX の返答書では `\begin{quote}` と `quotation` の塊も引用として数える (帰属は塊の前後の文の語)。 文書が referee の文を引くのに定義した macro・環境 (例 = `\Q{…}`・`referee` 環境) は `--quote-macro Q` / `--quote-env referee` で名前を渡す = 渡さないと、 macro で引いた referee の文は 1 件も照らされず、 中の ``…'' だけが数えられる (実測: 名前を渡す口が無かった間、 塊の引用の照らしを project ごとに手で書き直していた)。 段ごとに直しを出すとき ([#stepwise-edit-proposals](#stepwise-edit-proposals)) も、 引用の照らしは返答書の全体に当てる = 他の段の引用の違いも先に分かる (直すのはその段で)。
   - **機械の結果の置き場**: 照合票の 4 の列の 1 行 (「他人に帰した引用 N 件 = どれも原文の部分文字列」)。 機械が見ないもの = 括らずに書いた言い換え、 帰属の語の無い引用、 部分文字列ではあるが文脈から切り離した引用 (主節を落として従属節だけを引く)、 片をつないだ引用の片と片の間 (同じ段落に順にあることだけを見る)、 数えない形 (ASCII の一重引用符・名前を渡していない LaTeX の環境と macro・添付の file の中身)、 原文の file の中の話し手 (編集者の手紙と referee の報告が 1 つの file なら、 編集者の文を referee に帰しても一致に出る = 話し手を分けるなら、 その人の部分だけを source に渡す)。 どれも 5 の列に書く。 「引用 0 件」 は照らした引用が無いことで、 他人の文を引いていないことではない。
3. **照合票を作った後に変えた所は、 照らし直してから見せる** — 照合票の後に送る文・添付を変えたら (並べ替え・文の切り方・平易化の書き直しを含む)、 変えた行の照合をやり直す。 並べ替えと切り方だけの直しも文意を変える (前を受ける語・結論の文の受け先が変わる = [#per-sentence-reply](#per-sentence-reply) の 6、 [#do-not-say-unchanged](#do-not-say-unchanged))。 「並べ替えだけだから中身は変わらない」 という前提で検査を外すと、 受け手はまさにそこで文意が変わったと言う。 自分で当てた直しは、 書いた者でない目 (worker か批判役) に 1 回通してから見せる (書き手と検収が同じ者になると、 書き手の意図で読む)。 本人の OK の後に変えたら、 変えた所を示してもう一度 OK をもらう。
4. **差し戻された束の判定は引き継がない** — 受け手が束を差し戻したら、 その束の検査 (批判役の判定を含む) は前の検査が拾えなかった印 = その判定は使わない。 残す項目は照合票に新しく通す (前の判定の表を引いて済ませない)。 新しい窓 (session) が前の窓の記録を引き継ぐときも、 送り直すものは「判定済み」 を引き継がない。

**まだ機械にしないこと**: 照合票の有無を送信の道具で確かめる網は、 照合票を何便か使って形 (列・置き場所・file の形) が決まってから作る。 形が固まる前に網を作ると、 表の形を変えるたびに網も直すことになり、 網が形を縛る。 それまでは、 照合票を作るのは上の 1 の持ち主の段で、 機械は 2 の引用の検査だけ。

**捨てた案と理由**: 批判役の検査項目を受け手の指摘のたびに足し続ける = 症状ごとの継ぎで、 次の誤りはまだ無い次元で出るうえ、 誤りが批判役の出力そのものから来ることがある / 本人が全部読んでから OK する = 本人の時間を食い、 OK の性質 (送るかどうかの判断) も変わらない。 照らしていないことを表で見せるほうが、 OK が何を保証するかがはっきりする / 批判役をやめる = 本物の食い違いも見つける。 やめずに、 出力を仮説として扱う (2) / 送信を一定時間待たせる = 時間は原因でなく、 検収の中身が原因 / 受け手の立場で読む検品の下請けを毎便に置く = AI の層がもう 1 つ増え、 その出力もまた照らす要がある (大きい便だけに置く形は候補に残る)。

## <a id="stepwise-edit-proposals"></a>共著者が書いた返答書に修正案を出す: 答えの段ごとに 1 段ずつ、 収束してから次へ

主筆の共著者が書いた返答書に、 照合で見つけた直しをまとめて出さない。 複数の答えにまたがる直し・組み方の変更・最後の一覧の整理を 1 つの差分にすると、 受け取った側は 1 回で全部を確かめきれず、 全体を差し戻す (実測)。

1. **段を決めて 1 段ずつ出す** — 段は答え (A1〜An) の単位で、 順番は主筆が決める。 1 つの段で出すのは、 その段の答えの直しだけを当てた版からの差分と、 その段についての問いだけ。 次の段の直しは、 前の段の案が収束した (主筆が採った・直した) 版の上に作る。 先の段の問いを前倒しで出さない。
2. **組み方の変更と、 段をまたぐ直しは、 それを扱う段まで出さない** — 段をまたぐ直し = 冒頭の番号の 1 文、 最後の一覧 ([#unrelated-changes](#unrelated-changes))、 複数の答えの語を揃える直し。 組み方を変える案 ([#per-sentence-reply](#per-sentence-reply)) も、 中身の段が収束してから出す。
3. **出した直しの一部だけを残すときは、 残す直しが取り下げる直しに依っていないかを 1 件ずつ見る** — 答えの中の場所にある直しでも、 別の直しに合わせて入れたものがある。 例 (架空): 答えの中で末尾の一覧を指す句を消す直しは、 一覧を削る直しに合わせたもの。 一覧を元に戻すなら、 その句を消す直しも外す (残すと、 一覧は残るのに答えから一覧を指す句だけが消える)。 段ごとの版は、 直しの一覧を 1 か所 (直しを当てる script の表) に持ち、 そこから選んで作る = 直しの文を段ごとに写さない (写すと段ごとの版で同じ直しの文が食い違う)。
4. **主筆の依頼で進め方を変えたら、 その project の規則の文書に主筆の言葉のまま書く** — 次の session が同じ形で一度に出さないため。 1 段を出すたびに [#answer-fit-check](#answer-fit-check) の判定を当てる (前の判定を受けた文と同じ段落は判定の表を引く。 受け手が差し戻した束の判定は引かず、 照合票に新しく通す = [#pre-send-verification-sheet](#pre-send-verification-sheet) の 4)。
5. <a id="minimal-edit-keeps-word-order"></a>**直しは、 主筆の文の語順と語を保つ最小の形から考える** — 曖昧さや誤りを直すときも、 主筆の語を別の語に置き換える前に、 語の位置を動かす・1 語を足す・外すで直らないかを先に試す。 例 (架空): 否定のかかる所が 2 通りに読める「the effect is not seen because of the filter」 は、 not を because of の前へ動かすだけで、 意図の読みの 1 通りになる (「the effect is seen not because of the filter」)。 語を替えると、 主筆は差分を読むたびに文意が動いていないかを確かめ直すことになる (実測: 語を替えた直しが、 検収で語順を保つ形に戻った)。
6. <a id="unrestricting-a-claim"></a>**主筆の限定を外して一般の形にする直しは、 限定の外で一般の形が何の意味で成り立つかを確かめてから出す** — 2 つの量の減り方を比べた結果 (片方が速く減る) から言えるのは、 多くの場合、 比の上の主張だけである。 両方がすでに十分小さい領域では、 「片方が先に消え、 もう片方だけが残る」 は絶対値の意味では言えない。 主筆が「現実的な条件の X では」 と限っているのは、 その領域を外すためのことがある = 限定を外す前に、 限定の外の典型の値で両方の大きさを 1 回見積もる。 限る理由が書かれていないのが問題なら、 限定は残して、 理由 (条件) を括弧で添える (実測: 限定を外した直しが、 検収で、 限定を残して条件を添える形に戻った)。
7. <a id="edit-cites-what-is-shown"></a>**直しの文に図・式を引くときは、 引く先を開いて、 文が言う量・因子が陽に出ているかを確かめる** — 図は絵にして見る (文が言う時刻や量が、 図の印・軸に描かれているか)。 式は字面を見る (展開すると出る因子は、 読み手が式を開いても見えない)。 改訂でまだ番号が動く原稿の式・図の番号は、 返答書の直しに足さない (実測: 図に描かれていない量を図で示すと書いた直しと、 因子が陽に無い式の番号を足した直しが、 それぞれ書き手の見直しと検収で外れた)。

## <a id="unrelated-changes"></a>referee の指摘と関係ない変更: 返答書での扱いと、 入れる時期

再投稿の原稿に、 referee が求めていない変更が入るとき (投稿の後に preprint で出した版を基準にした、 著者が別に誤りを見つけた、 など)。 referee は自分の指摘への答えを読むので、 混ぜると答えの筋が見えにくくなり、 指摘の外の変更が指摘への答えのように読まれる。

1. **referee の指摘と関係ない変更だけを、 答え (A1〜An) と別の一覧に置く** — 返答書に独立の段落を 1 つ置き、 変更ごとに 1 行 (どこを・何に)。 投稿の後に入れた変更でも、 答えが使う変更 (答えが引く節・式を足した・直した) は指摘と関係ある変更 = 一覧に入れず、 それを使う答えの中で変更として言及する (節や式を引くだけでなく「新しい節」「その節の最初の段落でそう述べた」 のように)。 一覧で「関係ない」 と呼んだ節を答えの根拠に使うと、 referee には関係ないと言った節で答えていると読める (実測)。 投稿の後に節を付け替えたなら、 付け替えは冒頭の番号の 1 文で言う (答えが付け替えた後の番号で引くため)。
2. **既に公開した版で入れた、 指摘と関係ない変更は「指摘と関係なく、 投稿の後に公開した版 (arXiv vN) に入っている」 と書き、 返答書のいちばん最後 (結びの前) に置く** — 付加情報なので、 答えより先に読ませない。 冒頭には「節・式・図の番号は再投稿の原稿のもの」 の 1 文だけを置く (その原稿は返答書と一緒に referee に渡る)。
3. **まだ公開しておらず指摘とも関係ない直しは、 referee とのやり取りが終わった後の最後の版で入れる** — 今回の再投稿に入れると、 referee が読む差分と返答書が増え、 指摘への答えと区別しにくくなる。 案と検算は捨てず、 最後の版用の file に残して、 その project の台帳 (TODO) から指す (実測: 入れる方向で作った案を、 著者が最後の版に回した)。
4. **共著者に原稿の変更の承認を頼むときは、 変更の diff と、 選んでもらう文そのものを添える** — 「この段落と食い違うので半文足すか」 のような問いだけでは、 相手は判断できない。 足す文を 1 文で書き、 場所 (直前の文) を引く。 変更の一覧は diff の頁で指す。
